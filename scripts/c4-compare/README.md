# Измеритель сверки C4 (`scripts/c4-compare`)

Инструмент QA эпика «Допиливание BYOA» (фаза Ф2, `docs/plan-byoa-quality.md`).
Сверяет **экспорт-кандидат** (схема, построенная агентом по BYOA-промпту и
залитая в ArchMap) с **экспортом-эталоном** (принятая схема того же репозитория)
и раскладывает расхождения по классам.

Зачем: без замера правка промпта неотличима от дисперсии модели. 100 % совпадения
не бывает никогда — измеряем вектор чисел по классам, а не «похоже/не похоже».

## Запуск

Только стандартная библиотека + PyYAML — берём venv бэкенда:

```bash
# один прогон
backend/venv/bin/python scripts/c4-compare/compare.py run \
    ЭТАЛОН.yaml КАНДИДАТ.yaml \
    --md отчёт.md --json итог.json --title "Zabbix Haiku base 2026-09-04"

# сводная таблица по нескольким JSON-итогам
backend/venv/bin/python scripts/c4-compare/compare.py table \
    итог1.json итог2.json --md сводка.md
```

Без `--md` отчёт печатается в stdout; краткая строка метрик всегда идёт в stderr.
Вход — YAML `GET /export` ArchMap (`nodes:` дерево, `edges:` список).

Гейт:

```bash
cd backend && ./venv/bin/python -m pytest ../scripts/c4-compare -q
cd backend && ./venv/bin/ruff check --config pyproject.toml ../scripts/c4-compare
```

## Как устроен матч узлов

Ступени с убывающей уверенностью; каждый узел матчится не более одного раза,
ступень фиксируется в отчёте (доля матчей ступени 3–4 — сама по себе сигнал,
что имена разошлись):

1. **якорь** — совпали `source.repo` + `source.path` (нормализованные). Берётся,
   только если ключ однозначен с обеих сторон.
2. **имя + форма** — точное совпадение нормализованного имени (нижний регистр,
   ё→е, пунктуация схлопнута) и `shape`. Тёзок разводим по похожести путей.
3. **синонимичное имя** — токены после лёгкого стеммера кириллицы, двуязычного
   словаря (`SYNONYMS`, `SYNONYM_PHRASES` в шапке `compare.py`; **словарь
   дополняется по находкам**) и стоп-слов. Порог: Жаккар ≥ 0.6 **или**
   `difflib` ≥ 0.85. При нескольких кандидатах — лучший по мере, предпочтение
   той же форме. Две поблажки форме имени:
   - **слабые типовые токены** (`WEAK_TOKENS`: broker, bus, cache, db, server,
     service, backend, frontend, queue, worker, app, engine, hub). Модели любят
     дописывать к имени тип объекта — «RabbitMQ» → «rabbitmq-broker», «Redis» →
     «redis-cache», «Django» → «django-backend». Такой токен **не штрафует**:
     мера считается и по одним сильным токенам, и по всем, берётся лучшая.
     Именно лучшая, а не «только по сильным»: замена рубила бы класс
     «уточняющее слово с одной стороны» («Почтовый сервер (SMTP)» ↔
     «SMTP-сервер»). Если сильных токенов у одной стороны не осталось
     («Веб-приложение» — сплошь типовые слова), работает обычный Жаккар.
     Расхождение `shape` матч не отменяет (у слабой модели `redis-cache` —
     broker, у эталона `Redis` — database), но даёт флаг `форма`.
   - **стеммер кириллицы** (`stem_ru`): у слова длиннее 4 букв срезается одно
     самое длинное типовое окончание, словарь применяется и к слову, и к
     основе. Без него «Воркеры очередей» не сходились с «worker-queue» из-за
     падежа и числа. Стеммер намеренно грубый и на матч ступеней 1–2 не влияет.
4. **форма + технология** — только `database`/`broker`, технология совпала и
   кандидат единственный («БД заказов» ↔ «PostgreSQL»).

**Путь в дереве в матч не входит.** Контейнеры у двух моделей расходятся законно,
поэтому расхождение родителя — флаг `уровень`, а не промах. Прочие флаги пар:
`форма`, `external`, `нет якоря` (у эталона `source.repo` есть, у кандидата нет).

Классы узлов: **совпал** (+флаги), **ПРОПУСК** (узел эталона без пары; отдельно
считаются пропущенные контейнеры), **ВЫДУМКА** (узел кандидата без пары),
**ДУБЛЬ** (лишний узел кандидата, претендующий на уже занятый узел эталона — в
отчёте указано, на кого именно).

## Как устроен матч рёбер

По парам **сматченных** концов, направление значимо; одна пара с несколькими
каналами — несколько рёбер, ключ матча `(пара, канал)`. Классы взаимно
исключающие, приоритет сверху вниз:

- **НАПРАВЛЕНИЕ** — у кандидата есть только обратное ребро той же пары;
- **КАНАЛ** — ребро найдено, но канал брокера другой (или потерян);
- **СИНХРОННОСТЬ** — ребро найдено, `sync` разошёлся (`null` = синхронный);
- **совпало** — всё сошлось;
- **ПРОПУСК** — оба конца сматчены, ребра у кандидата нет;
- **ПРОПУСК-ПО-УЗЛУ** — конец эталона не сматчен: вина узла, не ребра;
- **ВЫДУМКА** / **ВЫДУМКА-ПО-УЗЛУ** — симметрично, по рёбрам кандидата;
- **ДУБЛЬ** — у кандидата ≥ 2 ребра на одной паре с одним каналом.

**Подписи не судим автоматически** (актив/пассив — семантика, а не ошибка):
для совпавших рёбер считается похожесть подписей, и пары ниже 0.25 попадают в
секцию «Подписи: проверить глазами». В метрики этот список не входит.

## Как читать метрики

Сводного скаляра нет намеренно. Ключевое:

- **узлы: полнота** = сматчено / узлов эталона — «сколько состава агент нашёл»;
  **точность** = сматчено / узлов кандидата — «сколько из построенного по делу».
- **пропуски-контейнеры** — отдельная строка: потерянный контейнер утаскивает за
  собой поддерево и рёбра, это не рядовой пропуск.
- **дубли** — обратная сторона полноты: один смысл двумя узлами.
- **покрытие якорями кандидата** — доля узлов с `source.repo`; без якоря синк из
  репозитория и федерация работают вслепую, поэтому это самостоятельная цель.
- **рёбра: полнота структурная** = совпало / рёбер эталона, у которых **оба конца
  сматчены** — качество связей в отрыве от полноты состава; **полнота общая** —
  того же делённого на все рёбра эталона (падает и от промахов по узлам).
- **найдено в нужном направлении** = совпало + канал + синхронность: сколько
  связей вообще есть и не развёрнуто (полезно, чтобы отделить «связи нет» от
  «связь есть, семантика разошлась»).
- **направление / канал / синхронность** — семантические классы: их рост при
  неизменной полноте означает, что промпт учит структуре, но не смыслу.

Сравнивать прогоны между собой имеет смысл только при неизменных порогах
(`JACCARD_MIN`, `RATIO_MIN`) и словаре синонимов: правка словаря сдвигает все
цифры, поэтому базлайн после такой правки перегоняется целиком.

## Сентинелы

`test_compare.py`: настоящие экспорты эталонов против себя (100/100 и нули во
всех классах, включая Zabbix с тёзками и путями в ссылках рёбер) плюс
синтетические возмущения маленькой схемы — синонимичное переименование, удаление
узла, близнец, разворот ребра, смена и потеря канала, `sync`, перенос в другой
контейнер, потеря якоря, неоднозначная ссылка. Тесты с настоящими экспортами
пропускаются (skip), если каталога материалов рядом нет.
