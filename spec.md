# ArchMap — spec.md

Описание продукта
Веб-сервис для описания многослойных программных систем
с произвольной глубиной иерархии. Альтернатива Structurizr
без ограничения в 4 слоя.

Проблема
C4-модель ограничивает описание системы четырьмя слоями.
В реальных системах компоненты содержат субкомпоненты
произвольной глубины. Structurizr это не решает.

Решение
Дерево узлов произвольной глубины. Каждый узел — либо
атомарный компонент, либо контейнер для дочерних узлов.
Архитектор сам решает, на каком уровне останавливаться.

Роли
Архитектор: создаёт и редактирует узлы, связи,
  прикрепляет flowchart и OpenAPI-спеки к узлам.

Пользователь: просматривает дерево, навигирует по уровням,
  открывает flowchart и OpenAPI-спеку через UI.

Сущности
Node
- id          UUID
- name        строка, обязательное
- description строка, опционально
- role        строка, свободное: "сервис", "БД", "брокер"...
- technology  строка, свободное: "Python", "Kafka"...
- parent_id   UUID | null
- shape       форма отображения (C4): service | database | broker | person
- is_external флаг «внешний узел» (на чужих уровнях рисуется «гостём»)
- flowchart   текст (Mermaid), опционально
- openapi_spec текст (YAML), опционально
- pos_x, pos_y координаты на схеме — РАСКЛАДКА, не версионируется
- created_at, updated_at
- has_children вычисляемое поле в API (есть ли дочерние узлы) — для дерева слева

Edge
- id          UUID
- label       строка, опционально (в UI поле называется «Описание»)
- technology  строка, опционально: "REST", "gRPC", "Kafka"
- source_id   UUID → Node
- target_id   UUID → Node
- source_handle, target_handle  точки стыковки стрелки — РАСКЛАДКА, не версионируется
- waypoints    кастомные точки-сгибы пути ЛОКАЛЬНОЙ стрелки (оба конца на одном уровне):
               список {x, y} в координатах графа уровня, БЕЗ концов. null/пусто —
               авто-маршрут (smoothstep). РАСКЛАДКА, не версионируется
- created_at

Кастомный путь стрелки (изломы)
На основной схеме архитектор может задать стрелке трассу вручную, чтобы обойти
«хитросплетённые» узлы. Грипы на горизонтальных/вертикальных сегментах стрелки тянутся
перпендикулярно — сегмент едет за курсором, остальной путь достраивается ортогонально.
Плечо примагничивается к ровному положению относительно хэндла: если перпендикулярная
координата сегмента подходит близко (порог в экранных px / зум) к координате конца
стрелки (S или T), она прилипает к ней — концевой стаб схлопывается, плечо становится
прямым продолжением хэндла (легко выровнять).
Доступно: режим основной схемы (не контекст-схема), архитектор. Работает и для
мастер-стрелки (несколько слитых связей одного направления): путь у её членов общий,
поэтому он «размазывается» по всем — читаем у первого члена с геометрией, при коммите
пишем во все memberIds (тот же двухслойный сплит local/ghost). При перемещении узла-конца
излом сохраняется (концевой сегмент дотягивается ортогональным коленом). Смена хэндла конца стрелки СБРАСЫВАЕТ изломы в дефолтный
авто-маршрут: старый путь считался относительно прежних концов и после смены хэндла
кривой, поэтому дешевле начать заново (сброс — только при реальной смене хэндла).

Хранение пути зависит от того, локальна стрелка на уровне или гостевая (как у хэндлов):
- Локальная стрелка (оба конца — узлы этого уровня) видна ровно на одном «домашнем»
  уровне → путь в колонке самого ребра (Edge.waypoints).
- Гостевая/сквозная стрелка проецируется на разные уровни с РАЗНОЙ геометрией (своя
  раскладка узлов и свой спроецированный гостевой конец), поэтому путь хранится
  per-уровень: edge_waypoints (container_id + edge_id → точки). Это зеркало
  ghost_positions/ghost_edge_handles — РАСКЛАДКА, не версионируется. Нет строки = авто.

Сквозные связи
Edge может соединять узлы с разных уровней иерархии
(например, А с уровня 1 и Б1 с уровня 2, где Б1 — дочерний узел Б).

Правила отображения:
- На уровне, где оба конца — локальные узлы: связь отображается как обычно.
- На родительском уровне: сквозная связь А → Б1 проецируется как А → Б,
  где Б — ближайший предок Б1, принадлежащий этому уровню.
- На уровне, где один конец — внешний: внешний узел отображается как
  «гость» (визуально отличается), стрелка идёт от/к нему.
- У промежуточного гостя есть кнопка «Войти» (→) — переход на его слой-схему
  компонентов. Узел из другой ветки дерева, поэтому путь строится заново
  (предки + сам узел), а не аппендом к текущему breadcrumb. Кнопка есть:
  • у листа-гостя, если у него есть дети (GhostNode.has_children, считается в
    _build_graph); у атомарного листа кнопки нет — проваливаться некуда;
  • у свёрнутого контейнера (предок гостя, показанный коробкой): он всегда
    промежуточный, поэтому «Войти» есть всегда — рядом с лупой «раскрыть инлайн».
    Лупа разворачивает содержимое на текущем уровне, «Войти» уводит на слой узла.
- Раскладка гостя привязана к уровню (один узел — гость на разных уровнях
  в разных местах): его координаты хранит ghost_positions (container_id +
  node_id), а точку стыковки стрелки на гостевом конце — ghost_edge_handles
  (container_id + edge_id + node_id → handle). node_id — id ОТОБРАЖАЕМОЙ
  сущности (свёрнутый предок-контейнер ИЛИ развёрнутый лист-гость): один конец
  ребра проецируется на разные сущности по expand/collapse, у каждой проекции
  своя строка. Хэндл локального конца остаётся в колонке самого ребра. Всё это
  РАСКЛАДКА — не версионируется.
- Запрет проникновения в чужую родную рамку (C4-инвариант): гость (и гостевая
  рамка раскрытого промежуточного контейнера) НИКОГДА не лежит внутри родной
  рамки уровня, в которую не входит по членству. Родные рамки = предки из
  breadcrumb, концентрически вложены; гость — член рамок до своего общего предка
  включительно, поэтому единственная «запретная» для него рамка — следующая глубже
  общего предка. При дефолтном спавне, росте родной рамки (добавили узел) и ручном
  драге гость минимально сдвигается к ближайшему краю запретной рамки + интервал;
  задвинуть его внутрь руками нельзя. Гостевую рамку двигаем целиком (жёсткой
  группой), чтобы не разорвать через край. Это РАСКЛАДКА — авто-сдвиг не
  персистится (драг персистит уже скорректированную позицию).
- Дефолтная раскладка гостя (без ручной позиции) — boundary labeling на «кольце»
  запретной рамки: гость ставится на ПЕРИМЕТР рамки F_{memberDepth+1} (та же рамка,
  что у keep-out, + интервал) — оптимальное место кратчайшей стрелки лежит на её
  границе. Базовая ось — горизонталь (поток C4 слева-направо, ближний к связанным
  узлам край), верх/низ берётся, когда горизонталь увела бы стрелку сквозь тела
  других узлов. Гости одной стороны раздвигаются изотонически (PAV) вокруг центра
  масс. Кольца разной глубины решаются изнутри наружу (рамка растёт за уже
  размещёнными глубокими гостями), поэтому keep-out выполняется по построению, а
  его проход остаётся лишь страховкой (ручные позиции, рост рамки за ручным гостем).
- Мастер-стрелка (несколько слитых связей одного направления) — синтетическое ребро
  без своей строки в БД. Её хэндлы (как и изломы) общие для всех членов, поэтому при
  реконнекте «размазываются» по всем memberIds (тот же сплит: локальный конец → колонка
  каждого члена, гостевой → ghost_edge_handles по каждому edge_id с общим node_id).
  Смена узла-конца у мастера по-прежнему запрещена — правится только точка стыковки.

MVP — в объёме
✓ Дерево узлов произвольной глубины
✓ Боковая панель из сворачиваемых секций (аккордеон, каждая секция
    разворачивается/сворачивается независимо):
    - «Дерево узлов» (как в Confluence): иерархия по parent_id, ленивое
      раскрытие веток. Узлы-пользователи (shape: person) в дереве не
      показываются — дерево про детализацию системы, а внутрь пользователя
      проваливаться нечего (на графе они есть);
    - «Добавить узел» (только архитектор): палитра из четырёх шаблонов-форм
      (сервис, БД, брокер, пользователь). Узел создаётся перетаскиванием
      шаблона на схему — см. ниже;
    - «Бизнес-процессы» — заглушка под будущий раздел.
    Вся панель целиком сворачивается в узкую полосу.
✓ Создание узла перетаскиванием: архитектор тянет шаблон нужной формы из
    секции «Добавить узел» на схему уровня. Во время перетаскивания за курсором
    следует не плитка шаблона, а пустая рамка-превью будущего узла (форма с
    прозрачным телом): она масштабируется под текущий зум схемы (совпадает с
    реальным размером узлов) и примагничивается к центральным осям соседей —
    архитектор сразу видит точное место и координаты создаваемого узла.
    В точке отпускания открывается модалка создания узла с уже выбранной формой
    (поэтому поля «Отображение» в модалке нет) и заполняемыми полями. Узел
    появляется там, где показывала рамка (координаты, с учётом примагничивания,
    сохраняются в pos_x/pos_y). Пустой уровень показывает сам холст (канву с
    точками) — drop-зоной служит вся его область, узел встаёт под курсором.
    Подсказка «нет узлов / перетащите форму» висит тостом в правом верхнем углу и
    уезжает за край после добавления первого узла. Холст открывается слегка
    отдалённым (зум ≈0.85), вход на разреженный уровень тоже не подлетает вплотную.
✓ Клик по имени узла в дереве: промежуточный узел (есть дети) → переход на его
    слой основной схемы (детализация — видны все дети узла, как drill-down по
    breadcrumb); лист (детей нет) → контекстная схема узла (см. ниже).
✓ Контекстная схема узла (для листьев): модалка с
    диаграммой вокруг этого узла — сам узел (фокус) + его прямые соседи
    (другой конец любой связи, выходящей за пределы поддерева фокуса: от
    самого узла или любого его потомка), обёрнутый в рамки своих предков.
    Соседи — пунктиром (как гости), связи проецируются на фокус. Схема
    только для просмотра (без правки, раскладка не сохраняется).
    API: GET /api/v1/nodes/{id}/context
✓ Связи между узлами (label + technology)
✓ Формы узлов (C4): сервис, БД, брокер, пользователь. Контейнером (можно
    «провалиться» внутрь / завести детей) может быть ТОЛЬКО сервис; БД, брокер и
    пользователь — атомарные: на графе у них нет кнопки «Войти», в дереве они —
    листья (клик → контекст), и сквозную связь к ним ведём напрямую, а не «внутрь».
✓ Внешние узлы (флаг is_external; на чужих уровнях — «гость»)
✓ Визуализация текущего уровня как интерактивная диаграмма:
    - узлы отображаются как блоки на диаграмме, не как плитки
    - связи отображаются как стрелки между узлами, не как таблица
    - клик по плашке с описанием стрелки открывает окно «Выберите связь» (список
      связей этого направления) — даже если связь одна. По самой линии на основной
      схеме клик не ловится — её сегменты заняты грипами изломов. У стрелки без
      описания вместо плашки — компактный плейсхолдер «•••» (он же точка входа). Выбор
      пункта открывает детализацию связи (поповер с информацией и кнопкой правки).
      Архитектору в окне выбора доступна кнопка «Добавить связь» — дозаписать новую
      связь того же направления, не протягивая отдельную стрелку
    - плашку с описанием архитектор может двигать вдоль стрелки дрэгом (по умолчанию —
      по центру). Позиция хранится как доля пути (0..1) и адаптируется при смене
      хэндлов/изломов: остаётся на той же доле к тому же концу. Со стрелки плашку не
      увести — доля зажата в [0,1], дальше концов движение залочено. Короткий клик
      (без сдвига) по-прежнему открывает «Выберите связь»
    - связь создаётся протягиванием новой стрелки от узла (архитектор): хэндлы
      узла раскрываются по ховеру, конец отпускается на цели. Попадание в ХЭНДЛ
      любого узла (с прощающим радиусом) создаёт прямую связь к нему. Отпускание
      на ТЕЛО узла мимо хэндлов: лист — прямая связь; узел-сервис С ДЕТЬМИ —
      «зона входа»: открывается выбор его потомка (поиск скоупится поддеревом),
      связь ведётся к нему и становится сквозной. Во время протягивания зона входа
      показывается явно — её контент гаснет, по центру возникает знак «стрелка вниз
      в лунку». На пустом холсте — отменяется.
    - связь к узлу ВНЕ текущего уровня (которого нет на холсте — ни локально, ни
      гостем): во время протягивания на любом не-корневом уровне у верхнего края
      холста появляется плитка-полоса «Связать с узлом вне уровня» (элемент
      интерфейса, не объект графа; подсвечивается при наведении конца стрелки).
      Отпускание конца на неё открывает окно выбора дальнего конца из ВСЕЙ схемы
      (дерево + поиск по имени; узлы текущего уровня и сам источник недоступны).
      Выбранный узел становится дальним концом, связь — сквозной. Закрывает кейс,
      когда оба нужных узла нельзя свести на один холст.
    - магнитное выравнивание узлов по центру при перетаскивании. Плюс снап по
      РАВНЫМ ИНТЕРВАЛАМ (distribution, как в Figma): если два соседа стоят на одной
      линии (горизонтальной/вертикальной) с зазором X между краями, то на расстоянии
      X от края ряда возникает магнитная зона — перетаскиваемый узел прилипает,
      продолжая равномерный ряд. Подсвечивается двумя розовыми засечками равной длины
      (эталонный зазор пары + новый зазор у узла). Центр-выравнивание приоритетнее по
      каждой оси; снап по зазорам работает на свободной оси (ось ряда). Действует и
      при драге узла, и при перетаскивании шаблона-превью из палитры.
✓ Алерты незавершённости схемы (только архитектор): индикатор «подвисших»
    элементов. При наличии активных алертов в правом верхнем углу схемы
    всплывает оранжевая плитка со скруглёнными углами и восклицательным знаком
    в треугольнике; клик раскрывает меню с детализацией. Срабатывают два типа:
    (1) атомарные (листовые) узлы без единой связи;
    (2) связи, у которых хотя бы один конец упирается в промежуточный
        (контейнерный) узел, а не в атомарный.
    Контейнеры в проверке (1) не участвуют (прямых связей у них быть не должно —
    это ловит проверка 2, а группировку детей за «подвисание» не считаем).
    Алерты глобальные (по всей схеме) и считаются на бэке.
    API: GET /api/v1/nodes/alerts
✓ Навигация: войти в узел / вернуться выше
✓ Выделение и безопасное удаление узла с канваса. Выбранный (активный) узел
    подсвечивается синим свечением по контуру формы — архитектор видит, какой
    узел исчезнет по Backspace/Delete. Удаление по Backspace/Delete не сносит
    узел напрямую (встроенное удаление React Flow отключено), а открывает то же
    предупреждение со списком связей, что и кнопка «Удалить» в модалке узла
    (общий компонент NodeDeleteConfirm). Действует только у архитектора и только
    при ровно одном выбранном узле. Удаление узла удаляет всё его поддерево
    (дочерние узлы любой глубины) и все связи поддерева. Предупреждение
    показывается, только если есть что терять: у поддерева есть внешние связи
    (ровно один конец вне поддерева) ИЛИ у узла есть дети; в списке — именно эти
    внешние связи (включая связи потомков наружу). Лист без связей удаляется
    сразу, без модалки.
✓ Создание и редактирование связи, включая смену концов (в т.ч. на сквозную)
✓ Просмотр и редактирование flowchart (Mermaid)
✓ Просмотр и редактирование OpenAPI-спеки
✓ Две роли: architect, viewer
✓ Одна организация (не multi-tenant)

Версионирование документации (планируется, см. tasks.md → бэклог)
Документация (узлы и связи) поддерживается в версионируемом состоянии.
- Версионируется только СЕМАНТИКА. Версионируемые поля:
    узел — name, description, role, technology, parent_id, flowchart,
           openapi_spec, shape, is_external;
    связь — label, technology, source_id, target_id.
  Поля раскладки (pos_x/pos_y, source_handle/target_handle) НЕ версионируются —
  перемещение узлов в версию не попадает.
- Публикация ПАЧКОЙ. «Пачка» = семантический diff между живым состоянием и
  последней опубликованной версией; кнопка «Опубликовать» проводит черту (как
  git commit). Отдельный «принцип формирования пачки» не задаётся.
- Автор и время фиксируются на уровне версии целиком (без аудита отдельных
  действий внутри пачки).
- Возможности: история версий, состояние на версии N, diff(A, B) с подсветкой
  added/removed/modified (узлы и связи + изменённые поля), откат к версии
  (forward-revert — история не стирается).
- Конкурентность (несколько редакторов): оптимистичная блокировка по версии
  сущности — устаревшая правка отклоняется с конфликтом.
- Хранилище — PostgreSQL (НЕ Git). Git рассматривался и отклонён: при
  многопользовательской записи даёт конфликты слияния. Возможный задел на потом —
  экспорт опубликованных версий в Git как витрина/ревью, не как БД.
