        владельца 2026-11-04: пререквизиты описать в руководствах архитектора и администратора,
        для компаний с интерактивным агентом ручной режим (агент берёт входящий скелет через
        MCP); ArchMap хранит в проекте «репозиторий → последний применённый коммит и метка
        версии», проектировать как будто старых проектов нет; сборщик с `--since КОММИТ` даёт
        затронутые объекты по карте владения, коммит не найден → полный прогон; первая версия
        применяет только через «входящее», без автоприменения; цикл исправлений, скептик и гейт
        рекомендаций не блокер, а цена простоты; пределов бюджета на стороне ArchMap нет (лимиты
        забота компании), нехватку токенов переживает форма входящего: результат сборщика уходит
        до старта агента, агент шлёт работу частями («готово 7 из 12»), повтор продолжает с
        недостающего, живую схему агент из пайплайна не трогает; интеграция = шаг в CI компании
        с push по HTTPS на эндпоинт вида POST /api/v1/projects/{id}/incoming со служебным
        токеном Bearer archmap_… с единственным правом «положить входящее в проект X» (секреты
        ARCHMAP_URL и ARCHMAP_TOKEN в CI, mTLS дело прокси), шаблоны для GitHub Actions, GitLab
        CI, Jenkins и Bitbucket, имя версии из переменных CI; вебхуков и наблюдателей в ArchMap
        нет, сервер код не получает. Этапы: А входящие, служебный токен и шаг CI со сборщиком
        (бывшая фаза 4 ТЗ сборщика); Б агент в пайплайне без терминала с промптом обновления и
        MCP, результат во входящее частями; В хранимый коммит и область агента по затронутым
        объектам; Г автоприменение с откатом и окно «Сервис обновлён». Владелец: «сейчас не к
        спеху», «пусть эпик ждёт своего часа».
