        ⚠️ ОТЛОЖЕНО на переанализ (2026-08-02): с момента исходного анализа сервис

        Цель: держать узлы и связи в версионируемом состоянии — история версий,
        diff между версиями, откат.
        ПРИМЕЧАНИЕ (2026-07-16): «Применить» BYOA-дозаливки доков
        (plan-agent-docs.md, этап 2) сознательно НЕ кладётся в undo-историю —
        откат перезаписанных дозаливкой доков должен покрыться именно
        версионированием: снимок версии обязан включать node_docs и
        openapi_spec, revert — возвращать их вместе с остальной семантикой.
        До тех пор страховка — dry-run превью + тумблер перезаписи (дефолт
        «не перезаписывать»).
        Принципы:
        - Версионируется только семантика. Версионируемые поля: узел — name,
          description, role, technology, parent_id, openapi_spec, shape,
          is_external + доки узла (node_docs — коллекция с этапа 1
          plan-agent-docs.md); связь — label, technology, source_id, target_id. Поля
          раскладки (pos_x/pos_y, source_handle/target_handle) НЕ версионируются —
          перемещения узлов в версию не попадают.
        - «Пачка» = семантический diff(живое состояние, последняя версия); кнопка
          «Опубликовать» проводит черту (как git commit). Отдельный принцип
          формирования пачки не задаётся.
        - Автор и время — на уровне версии целиком (без аудита отдельных действий
          внутри пачки).
        Реализация (вариант A — снимок + diff):
        - Таблицы: version (id, seq, published_at, author, message) + полный
          семантический снимок всех узлов/связей на версию. Миграция Alembic.
        - API: список версий; состояние на версии N; diff(A, B) → added/removed/
          modified (узлы, связи + поля); публикация (snapshot + message); revert =
          публикация версии, восстанавливающей выбранный снимок (forward-revert).
        - Конкурентность: оптимистичная блокировка по version/updated_at сущности →
          конфликт при устаревшей правке (несколько редакторов).
        - UI: индикатор «есть неопубликованные изменения» (бьётся только на семантику);
          превью «что войдёт в версию» + сообщение; экран истории; экран сравнения
          двух версий с подсветкой diff; откат к версии.
        - (Опц., позже) экспорт опубликованных версий в Git как витрина/ревью.
