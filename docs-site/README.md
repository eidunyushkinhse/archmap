# Документация ArchMap (docs.archmap.tech)

Пользовательская документация: три руководства — пользователя, архитектора и администратора.
Исходники — Markdown в `content/`; сайт собирает свой генератор (`src/`, TypeScript, Node
исполняет его напрямую); тема повторяет стиль приложения (`theme/`), дерево страниц слева —
дерево объектов продукта. Читателям сайт открыт; автор входит по скрытому адресу и правит
страницы в браузере.

```bash
cd docs-site
npm ci
npm run password   # задать пароль автора (хэш — в docs-site/.env)
npm run dev        # http://localhost:8800 — сервер, пересборка по правкам, перезагрузка вкладок
npm start          # то же без перезагрузки вкладок (для стенда)
npm run build      # dist/ как статика; битые ссылки и якоря останавливают сборку (CI)
npm run report     # карта фрагментов: какой текст на каких страницах
npm run check      # типы + тесты генератора, авторизации и API
```

## Роли

- **Читатель** — любой посетитель: дерево страниц, поиск, чтение. Кнопок входа и правки
  на сайте нет.
- **Автор** — один пароль; вход по адресу `/login` (ссылок на него нигде нет, адрес набирается
  вручную). Сессия живёт 90 дней в cookie, поэтому с каждого устройства входят один раз.
  После входа в шапке появляются «Редактировать» и меню «Автор» (редактор, выход).
  Неверные попытки входа ограничены: 5 за 15 минут с адреса.

Пароль задаёт `npm run password` (пишет scrypt-хэш в `.env`); для локальной разработки можно
`DOCS_AUTHOR_PASSWORD=…` в `.env`. Ключ подписи сессий создаётся сам в `.data/session-secret`
(или `DOCS_SESSION_SECRET`). За nginx с TLS — `DOCS_TRUST_PROXY=true` (cookie Secure, адрес
клиента из X-Forwarded-For). Шаблон — `.env.example`.

## Редактор (`/edit/`)

Слева дерево страниц и фрагментов, справа поля (название, описание, порядок) и текст с
живым предпросмотром тем же движком, что собирает сайт. Вставки: фрагмент (строка
включения с правильным относительным путём), ссылка на страницу, блок, картинка (загрузка в
`content/images/`). Сохранение — <kbd>Ctrl</kbd>+<kbd>S</kbd>: файл пишется в `content/`,
сайт пересобирается, битые ссылки и якоря показываются под текстом. «+ Страница» создаёт
файл с фронтматтером (адрес — транслитерация названия, правится), «+ Фрагмент» — файл в
`_shared/`. Правки — обычные файлы в репозитории: их видно в `git status`, коммит как
обычно.

## Устройство content/

```
content/
├── index.md              главная («Домашняя страница» в дереве): заголовок и вводный текст
├── user/                 руководство = папка с index.md
│   ├── index.md          титульная: title, short (короткое имя), order, description
│   ├── navigation.md     страница: title, order, description
│   └── import/           подпапка = раздел навигации (заголовок — из её index.md)
├── architect/ …
├── admin/ …
├── _shared/              фрагменты для включений (страницами не становятся)
└── images/               картинки (копируются только те, на которые есть ссылки)
```

Адрес страницы — путь файла без `.md`: `user/navigation.md` → `/user/navigation/`.
Порядок в дереве — `order` во фронтматтере (меньше — выше), затем по названию.

## Фронтматтер

```md
---
title: Навигация по проекту
order: 1
description: Одной фразой — подзаголовок страницы, список разделов и поиск.
---
```

Если `title` нет, названием становится первый `# Заголовок` (он уходит из тела). Внутри тела
начинайте с `##`: `h1` — это название страницы.

## Единый источник истины: включения

Текст, нужный в нескольких руководствах, пишется один раз в `content/_shared/` и включается
строкой на отдельной строке:

```md
<!--@include: ../_shared/tree-navigation.md-->
```

Путь — относительно текущего файла (или от корня `content`, если начинается с `/`). Фрагмент
может включать другие фрагменты; цикл и отсутствующий файл — ошибка сборки. Ссылки и картинки
внутри фрагмента пишутся относительно **самого фрагмента**, а не страницы, куда он попадёт.
Якоря фрагмента (`{#tree}`) становятся якорями каждой страницы, куда он включён. В редакторе у
фрагмента видно, куда он включён; `npm run report` печатает ту же карту.

## Ссылки

- На страницу — относительным путём к её `.md`: `[Импорт](../architect/import.md)`.
- На раздел страницы — с якорем: `[Факты](../user/node-page.md#facts)`; внутри страницы — `[см. выше](#tree)`.
- Внешние (`https://…`) открываются в новой вкладке.

Сборка проверяет каждую ссылку: несуществующая страница или якорь — ошибка с подсказкой, какие
якоря есть. На фрагменты ссылаться нельзя — только на страницы, куда они включены.

## Якоря заголовков

Из текста: `## Дерево объектов` → `#дерево-объектов`. Устойчивый якорь, который переживёт
переименование заголовка, задаётся явно: `## Дерево объектов {#tree}`. Повтор якоря на одной
странице — ошибка.

## Картинки

```md
![Что на картинке](/images/depth-canvas.png "Подпись под картинкой")
```

Путь относительный или от корня `content` (с `/`); подпись (в кавычках) становится
`<figcaption>`. Файл должен существовать — иначе ошибка сборки.

## Блоки

```md
::: tip Заголовок по желанию
Совет.
:::
```

Виды: `note` (Примечание), `tip` (Совет), `warning` (Внимание), `danger` (Осторожно),
`details` — свёрнутый блок с заголовком-кнопкой. Клавиши — `<kbd>Ctrl</kbd>`. Код — обычными
блоками с языком (` ```bash `, ` ```yaml `): подсветка и кнопка «Копировать».

## Выкладка

Сервер (`npm start`) слушает 127.0.0.1:8800: перед ним nginx с TLS для docs.archmap.tech,
`DOCS_TRUST_PROXY=true`. Адреса абсолютные от корня, поэтому сайт живёт на своём хосте;
страница «не найдено» — `404.html`. `dist/` после `npm run build` можно отдать и просто
статикой — без авторского режима.
