## Гарантия «логика стрелок не пострадает» — разграничение рисков

НИ ОДНА фаза не меняет конвейер укладки (buildAutoRoutes / routeAll / nudge /
плашки / T4-мини-проход): Ф1-Ф2 меняют только КОГДА считать и ЧТО ре-рендерить,
Ф3 исполняет ТОТ ЖЕ модуль в воркере, Ф5 — чистая презентация. Реальный класс
рисков — не «маршруты стали другими», а ОРКЕСТРАЦИЯ/УСТАРЕВАНИЕ: применить
устаревший снимок, пропустить нужный ре-рендер (неполная сигнатура), залипшая
дуга-мостик. Против этого — обязательные гейты каждой фазы:

1. tsc -b --force / eslint / vitest (372) — pre-commit hook уже держит.
2. Дамп маршрутов на реальной сцене (scratchpad/scene.json, тест-дампер как в
   perf-проходе 6ecbe7d): маршруты/хэндлы/плашки/позиции до/после — бит-в-бит.
   Обязателен для Ф3 (воркер), дёшев — гонять на всех фазах.
3. Headless-инвариант «финал == перезагрузка»: после раскрытия/сворачивания
   (дать анимации доиграть) структурная сигнатура DOM (transform узлов + path d
   рёбер) равна сигнатуре после F5 того же состояния. Это ДОКУМЕНТИРОВАННЫЙ
   контракт анимационного слоя (spec.md: «финал байт-в-байт равен рендеру после
   перезагрузки») — он ловит именно оркестрационные баги (устаревший снимок).
   Скрипт собрать по рецептам памяти ui-verification-headless / headless-route-dump.

## Причины (ранжированы, с привязкой к коду)

1. ПОЛНЫЕ ПРОГОНЫ КОНВЕЙЕРА ВНУТРИ ОКНА АНИМАЦИИ.
   Раскрытие: (а) прогон «по замерам детей» — дети смонтировались → RO →
   sizesVersion bump (LevelGraph.tsx, handleNodesChangeMeasured ~стр.429) →
   полный computeViewLayout; (б) прогон «зеркало засева» — seed-интенты
   (own-on-first-render) → commitLayout → viewLayout меняется → ещё прогон,
   результат ИДЕНТИЧЕН ПО ПОСТРОЕНИЮ (контракт own-on-first-render).
   Сворачивание: зеркало expanded:false → прогон с идентичным результатом.
   ВАЖНЫЙ ФАКТ: стадии раскладки УЗЛОВ сознательно живут на NODE_W×NODE_H
   (pipeline.ts, комментарий у PipelineInput.sizes) → замеры меняют ТОЛЬКО
   маршруты/плашки, НЕ позиции узлов. Значит отложенный флаш прогона «по
   замерам» не сдвинет ни один узел — артефактов не будет вовсе.
2. СТОИМОСТЬ apply(): assembleRfGraph строит ВСЕ объекты заново → React.memo
   обесценен → ре-рендер ~всех узлов на каждый apply. В dev ×2 (StrictMode в
   main.tsx — НЕ выключать, это dev-only цена).
3. ДВОЙНОЙ ПРОХОД РЕНДЕРА РЁБЕР на массовой смене геометрии: рёбра рендерятся →
   publish в реестр мостиков (EdgeJumpContext) → версия контекста меняется →
   все рёбра рендерятся второй раз. paused у EdgeJumpProvider покрывает только
   драг (LevelGraph.tsx ~стр.1086), окно анимации — нет.
4. RASTER-цена drawIn: stroke-dashoffset — некомпозитная SVG-анимация, все
   стрелки стартуют одновременно → пиковый repaint 400мс.
5. Мелочи: транзишены рамок по layout-свойствам (left/top/width/height);
   узлы едут по transform без will-change (промоушен слоёв не гарантирован).

### Ф1. «Тихое окно» + скипы (ядро) — СДЕЛАНО 2026-07-14, ждёт глазной проверки
A. Holdoff compute+apply на окно анимации — реализовано с двумя находками:
   - LevelGraph: тело async-эффекта раскладки вынесено в computeNow()
     (useCallback на данных; «последний выигрывает» через runIdRef вместо
     cancelled-флага, инвалидация на unmount отдельным cleanup'ом []); эффект
     раскладки = 3 строки: hold → dirty=true и выход, иначе computeNow().
     Шлюз gate (hold/flush/release/reset) — useMemo-объект, отдан хуку пропом.
   - НАХОДКА 1 (обязательная): эффект-СБОРЩИК объявлен РАНЬШЕ эффекта раскладки
     (было наоборот). setLayout прогона-инициатора и зеркало интентов
     (viewLayout) приходят ОДНИМ батчем; сборщик должен успеть применить план
     (applyLayout → gate.hold()) до того, как эффект раскладки среагирует на
     viewLayout — иначе зеркальный прогон стартует В окно. Эффекты общаются
     только через стейт layout — перестановка легальна.
   - НАХОДКА 2: flush не «до unmask», а unmask ЖДЁТ ПРИМЕНЕНИЯ: setLayout —
     стейт, применение случается в сборщике позже; unmask сразу после счёта
     показал бы стрелки по СТАРЫМ маршрутам на кадр. Механика: flush ставит
     промис (appliedResolveRef), сборщик резолвит его после applyLayout;
     скип-по-сигнатуре и перегнанный прогон не ждут. Отсчёт fade рамок и
     setActive(false) — от фактического unmask (не от конца move), иначе флаш
     сдвигал бы unmask за конец фейда.
   - Точки: раскрытие — конец move (flush → unmask(true)); сворачивание — конец
     фазы 1 (flush → своп: свежая раскладка ложится в pendingRef через apply);
     закрытие окна — endDraw (release: хвост досчитывается в фоне; без drawIn —
     release прямо в unmask/свопе); cancel() — release (кик только при dirty:
     старт драга не получает лишний прогон); reset() — сброс без досчёта.
     Продолжения флаша гейтятся эпохой окна (epochRef: cancel/reset/новый план).
B. Скип идентичных применений — layoutSig (graph/layout/layoutSig.ts):
   механическая сериализация всех полей (Object.keys + Map/Set сортировкой),
   4 юнита (в т.ч. чувствительность к каждому полю и страж полноты образца).
   При скипе обязательны: prevRoutesRef, интенты, liveHandleInputs — сделано.
F. Пауза реестра мостиков: paused={dragging || jumpsPaused}; jumpsPaused —
   стейт хука: true с планом (батч), false на unmask/свопе. НАХОДКА 3 (баг,
   пойман гейтом «финал == перезагрузка»): пауза глотала и УДАЛЕНИЯ — рёбра,
   умирающие на свопе, рендерились последний раз с paused=true, их прощальный
   publish(id, null) съедался, и реестр вечно держал полигоны мёртвых рёбер
   (живые рисовали дуги «над призраком»). Фикс: publish(null) проходит СКВОЗЬ
   паузу (смерть рёбер — редкое структурное событие, один батч).
   Принятый артефакт (зеркало драг-паузы): дуга статичного ребра над скрытым
   на время move может висеть «над пустотой» ≤420мс.
G. CSS: .lg-canvas--anim .react-flow__node { will-change: transform; } — есть.
Гейты Ф1 пройдены: tsc/eslint 0, vitest 376 (+4 layoutSig), дамп маршрутов
бит-в-бит с эталоном 6ecbe7d (scene.json, A/B/B_prev), headless-инвариант
