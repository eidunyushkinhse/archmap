# План: вторая итерация тюнинга (кандидаты матрицы Ф5)

Ветка: feat/tuning-round2. Источник — docs/qa-federation-matrix.md (шесть
кандидатов, приоритет сверху). Баланс прежний: минимум ручных действий /
минимум алертов / максимум семантики; одно-репо не регрессирует (сентинелы
байт-в-байт + повторная матрица в конце).

## Фазы

- **Ф0 (мердж-слой)**: К3 (уточнение матчера) + К4 (новый класс замечания) —
  backend/app/import_merge.py + тесты. Обязательны: сохранность тестов Ф0/Ф1
  прошлого эпика, снапшоты одно-файлового прогона, полевые кейсы обоих склеек.
- **Ф1 (замечания)**: К2 — did-you-mean на «узел не найден» в
  import_yaml/import_merge (где резолвятся концы связей); порог Ф8ж дословно.
- **Ф2 (промпты)**: К1 (перестройка примера при multi_product) + К5 + К6 —
  import_prompt.py, skeptic_prompt.py; сентинелы байт-в-байт при
  multi_product=False.
- **Ф3 (матрица-2, архитектор)**: повторные прогоны — федерация (все три
  репозитория, чекбокс ВКЛ) + один изолированный контроль (Zabbix, чекбокс
  ВЫКЛ). Критерии: раздел федерации исполняют 3/3 агента; ложной склейки
  плагин↔ядро нет; схемная секция ≤ 6 строк; алертов < 27; «узел не найден»
  чинится за один круг; холостых кругов аудита нет.

## Ловушки (⚠ в ТЗ)

1. К1: пример — ДАННЫЕ (`_EXAMPLE_DOC` + `example_yaml(depth)`), трансформация
   программная; не хардкодить второй текст примера (протухнет).
2. К2: подсказка молчит при неуверенности (урок Ф8ж: устёгшая модель копирует
   мусор слепо); кандидаты — только среди узлов ЭТОГО пакета.
3. К3: не сломать матчер v3 (пост-шаг «вклад-свидетель» и порядконезависимость
   — тест перестановок должен остаться зелёным).
4. К4: связь контейнер→ВНУК тоже попадает под правило (потомок, не только
   прямой ребёнок); обратное направление (потомок → контейнер) — тот же класс.
5. Прежние правила: tsc -b (не --noEmit), известный флейк vitest, сентинел-тесты
   на каждый промпт-фикс.
