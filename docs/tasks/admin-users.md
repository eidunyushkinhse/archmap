# Задание: админка пользователей (эпик, ветка feat/admin)

Работаем в ОТДЕЛЬНОЙ ветке `feat/admin` от main. Сливать в main (`--no-ff`) будет
архитектор после приёмки пользователем. Код пишет opus-xhigh, принимает архитектор.

## Мотив и решения пользователя (2026-09-30), не переигрывать

ArchMap разворачивают в закрытом тестовом контуре без интернета. Сейчас учётки
заводятся только через открытую регистрацию (`POST /api/v1/auth/register`), где
роль, включая architect, выбирает сам регистрирующийся. Админка делается в
ОСНОВНОМ коде, а не форком: режимы задаются настройками.

1. **Администратор** — отдельный признак пользователя `is_admin`, а не третья роль.
   Администратор остаётся architect или viewer: право на документацию и право
   управлять людьми не смешиваются.
2. **Первый администратор** создаётся командой на сервере, без интернета:
   `./venv/bin/python -m app.admin create-admin <логин> [--role architect|viewer]`.
   Пароль вводится в консоли дважды (getpass), в аргументах его нет. Если такой
   пользователь уже существует, команда делает его администратором и не трогает
   его пароль, если не передан флаг `--reset-password`.
3. **Настройка `ALLOW_SIGNUP`** (Settings, по умолчанию `true`, чтобы публичная
   версия и dev вели себя как раньше). При `false` эндпоинт `/auth/register`
   отвечает 403 с понятным `detail`. Регистрация НИКОГДА не выставляет `is_admin`.
4. **Экран «Пользователи»** — пункт в меню профиля, виден только администратору:
   - список: логин, роль, «администратор», активен или заблокирован, дата
     создания;
   - «Новый пользователь»: логин, роль, признак администратора, временный пароль,
     который администратор передаёт человеку сам (почты нет);
   - у каждого: сменить роль, выдать или снять администратора, сбросить пароль
     (администратор задаёт новый), заблокировать или разблокировать.
5. **«Сменить пароль»** — пункт меню профиля у всех: старый пароль, новый, повтор.
6. **Блокировка вместо удаления.** Удаления пользователей нет: в проектах живут
   `created_by` и `updated_by`.
7. **Защиты:**
   - заблокированный не входит (`login` → 401 «Учётная запись заблокирована»);
   - его УЖЕ выданный токен перестаёт работать сразу: `get_current_user`
     проверяет `is_active` в БД на каждом запросе;
   - смена роли действует сразу (бэк и так берёт роль из БД, проверь);
   - нельзя заблокировать себя;
   - нельзя снять администратора с последнего активного администратора и нельзя
     заблокировать последнего активного администратора.
8. **Пароль** — минимум 8 символов. Других правил сложности нет.
9. **Вне скоупа:** SSO/LDAP, журнал действий, разграничение проектов, почта,
   удаление пользователей, принудительная смена временного пароля при первом
   входе.

## Шаги

1. **Бэк, модель и миграция.**
   - В `users` добавить `is_admin bool NOT NULL default false` и
     `is_active bool NOT NULL default true`.
   - Миграция через Alembic (`--autogenerate`). Проверь, что она накатывается на
     живую dev-базу (`alembic upgrade head`) и откатывается (`downgrade -1`), затем
     снова вверх.
2. **Бэк, авторизация.**
   - `is_active` в `login` и `get_current_user`.
   - `require_admin`.
   - `ALLOW_SIGNUP` в `config.py` и в `/auth/register`.
   - `GET /api/v1/auth/me` — id, логин, роль, `is_admin`.
   - `POST /api/v1/auth/password` — смена своего пароля, старый пароль
     обязателен.
   - `GET /api/v1/auth/config` без авторизации, отдаёт `{allow_signup}`: фронту и
     будущему демо-режиму.
3. **Бэк, API администратора.** Роутер `/api/v1/admin/users`:
   - `GET` (коллекция без хвостового слэша);
   - `POST` — создать;
   - `PATCH /{id}` — роль, `is_admin`, `is_active`, всё под защитами п.7;
   - `POST /{id}/password` — сброс;
   - ответы без `hashed_password`;
   - ошибки в формате `{"detail": ...}` на русском.

   Pydantic-схемы → `npm run gen:api`, закоммитить `api.gen.ts`.
4. **Бэк, команда `app/admin.py`** (`python -m app.admin create-admin …`).
   Тесты — через функцию, которую команда вызывает: getpass подменить.
5. **Бэк, тесты** `tests/test_admin.py` и дополнения в `test_auth.py`. Покрыть:
   - каждый пункт защит п.7;
   - `ALLOW_SIGNUP` в обоих значениях;
   - регистрация не даёт `is_admin`;
   - заблокированный токен → 401;
   - смена роли действует на следующий запрос;
   - неадмин получает 403 на `/admin/*`;
   - `/auth/me`;
   - смена пароля (неверный старый, короткий новый);
   - команда `create-admin` (новый, существующий, `--reset-password`).
6. **Фронт.**
   - `api/admin.ts`, `api/auth.ts`: `me`, `changePassword`.
   - **Источник роли.** `getUserRole()` сейчас читает роль из JWT, и после смены
     роли администратором интерфейс покажет старую до перелогина. Сделай так,
     чтобы UI брал роль и `is_admin` из `/auth/me` при старте приложения (после
     перезагрузки страницы роль актуальна). Не ломай синхронные вызовы
     `getUserRole()`: например, кэш после загрузки `me`, с JWT как запасным
     значением до ответа. Выбери решение и опиши его в отчёте.
   - Если сервер вернул 401 «заблокирована», выйти на логин с этим текстом.
   - **`ProfileMenu`:** «Сменить пароль» (все), «Пользователи» (администратор).
   - **Экран «Пользователи».** Отдельная страница-роут в стиле `ProjectsPage`
     (шапка с `BrandLink`, таблица), с возвратом на «Все проекты».
   - **Модалки:** «Новый пользователь», «Сбросить пароль», «Сменить пароль» — на
     `ui/Modal`.
   - Блокировка и снятие администратора — с подтверждением `ConfirmDialog`.
   - Тексты короткие, без длинных тире. У себя и у последнего админа кнопки
     «Заблокировать» и «Снять админа» отключены, с подсказкой почему.
   - Тесты vitest на экран, модалки и видимость пунктов меню.
7. **Документация.**
   - `DEV.md`: раздел «Пользователи и администратор» — команда `create-admin`,
     `ALLOW_SIGNUP`.
   - `spec.md`: раздел о пользователях и администраторе.
   - `tasks.md`: пункт «АДМИНКА ПОЛЬЗОВАТЕЛЕЙ» — статус «сделано в ветке, ждёт
     приёмки».
   - `CLAUDE.md` и `QWEN.md` — синхронно, только если меняется описанная в них
     структура (новые роутеры и модули в дереве). Коротко.
8. **MCP.** Код не трогаем, но проверь, что гейт MCP зелёный. Логин
   заблокированного через MCP должен давать понятную ошибку: посмотри, как
   `client.py` показывает 401, и если текст из `detail` доходит до агента, этого
   достаточно.

## Гейты

После каждого шага:
- бэк: `./venv/bin/python -m pytest -q`, `ruff check .`, `mypy app/`;
- фронт: `npx tsc -b`, `npx eslint .`, `npx vitest run`;
- MCP-гейт — в конце.

Коммиты по одному на шаг, на русском, последняя строка —
`Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`.
Коммитить через `git commit --only <пути>`. Ветку пушить в origin после каждого
коммита. Первым коммитом в ветке — этот файл задания и правка `tasks.md`, которая
уже лежит в рабочем дереве main (закоммить её в ветке).

⚠️ `./dev.sh` работает в фоне на main и использует живую dev-базу. Миграцию
накатывай осознанно (она аддитивная). Бэк перезапускать не нужно, он с
`--reload`. После накатывания проверь, что текущий пользователь из `mcp/.env`
по-прежнему логинится.

Headless-браузер не нужен, UI смотрит пользователь.

## Скоуп-гард

Не трогать:
- модель проектов;
- доступ к проектам;
- промпты;
- холст.

Не добавлять:
- удаление пользователей;
- журнал действий;
- SSO.

Демо-режим — отдельная будущая задача, `DEMO_MODE` не вводить.
