## Что сделать

### 1. Бэк: `GET /api/v1/search?q=…&limit=…&kinds=…`

- Скоуп — проект из `X-Project-Id`, как у всех. Читать могут обе роли.
- Коллекция без хвостового слэша (правило проекта).
- Модуль логики — `app/search.py`, роутер — `app/routers/search.py`, схемы —
  `app/schemas/search.py`. После правки схем — `npm run gen:api`, и закоммитить
  `api.gen.ts` вместе с ними (правило CLAUDE.md), даже если фронт поиск пока не
  использует.

**Где ищем (единицы поиска)** — всё знание проекта:
- **объекты:** имя, описание, роль, технология;
- **схемы логики:** имя, эндпоинт (`operation`) и тело ПОСТРОЧНО (единица —
  строка);
- **спека OpenAPI:** построчно;
- **структура БД:** таблица (имя, описание), колонка (имя, тип, описание);
- **каналы брокера:** канал (имя, группа, описание), поле канала;
- **параметры конфигурации:** имя, описание, дефолт;
- **процессы:** имя процесса, подпись шага.

**Как матчим** — это главный пункт. Запрос инженера — сырая строка лога с
переменными частями (`/dev/ttyUSB0`, id, пути), а в схеме написано
`SMSDevices not configured for <устройство>`. Поэтому поиск подстрокой целиком не
годится.
- Токены запроса: нижний регистр; разрезать по всему, кроме букв, цифр и `_`;
  выкинуть токены короче 3 символов, чистые числа и маленький стоп-лист
  (`the, for, not, and, with, from, …` и русские союзы и предлоги).
- ⚠️ `not` НЕ выкидывать как стоп-слово, если без него пропадают фразы ошибок.
  Реши по тесту.
- Лёгкая нормализация русских окончаний: токен длиннее 5 символов сравнивать по
  префиксу без последних двух символов («оповещения» ~ «оповещение»).
- Вес токена — IDF по единицам проекта: `log(1 + N / df)`. Частые слова почти ничего
  не весят, редкие (`smsdevices`) решают.
- Счёт единицы — сумма весов РАЗНЫХ совпавших токенов. Если вся нормализованная
  фраза запроса встретилась подстрокой — бонус.
- Ранжирование по счёту. Из одной схемы или спеки показывать не больше 3 лучших
  строк, остальные учесть числом.
- Порог — не меньше двух совпавших токенов, либо единственный токен запроса
  совпал.
- Считаем в Python по загруженному знанию проекта. Проекты — сотни схем, этого
  хватит. Postgres FTS не нужен (и тесты на SQLite).

**Ответ — список результатов:**
- `kind`;
- адрес: `node_id`, `node_path` (путь объекта через « / »), `title` (имя схемы,
  таблицы, канала, параметра или процесса);
- id для перехода: `doc_id`, `process_id`, `message_id` — какие применимы;
- `line_no` у построчных;
- `snippet` — совпавшая строка, обрезанная до ~200 символов вокруг совпадения;
- `score`, `matched` (совпавшие токены).

Плюс общее число найденного и «ещё N строк в этой схеме».

`limit` по умолчанию 20, максимум 100. `kinds` — фильтр по видам. Пустой запрос или
запрос без значимых токенов — 422 с понятным `detail`.

### 2. Бэк: чтение одной схемы логики

Сейчас одну схему по id получить нельзя: есть только список схем объекта. Если

используй его и ничего не добавляй.

### 3. MCP: `archmap_search` и `archmap_doc`

- **`archmap_search(project, query, limit?, kinds?)`:**
  - вывод текстом, сгруппированный по объектам;
  - у каждой находки — адрес и id для следующего шага;
  - в конце — подсказка, как открыть найденное (`archmap_doc` для схемы,
    `archmap_node` для объекта, `archmap_processes` для процесса).
- **Описание `archmap_search` направляет агента.** Строку лога или текст ошибки
  вставляй целиком, переменные части не мешают. Искать стоит ПЕРЕД тем, как
  открывать карточки подряд.
- **`archmap_doc(project, doc_id)`:** одна схема — путь объекта, имя, вид,
  эндпоинт, «не описана» у заглушки, «в N процессах» и полный текст.
- Версия MCP → 0.5.0, число инструментов в README: 29 → 31.
- В README — таблица инструментов и новый типовой сценарий «Разбор инцидента:
  строка лога → поиск → схема → ветка отказа → процесс».
- ⚠️ Тесты MCP — через фикстуры, провалидированные Pydantic-схемами бэка (урок
  проекта: моки прячут форму тел). Так же, как устроены соседние тесты в
  `mcp/tests`.

### 4. Тесты бэка (`tests/test_search.py`)

- **Главный.** Строка лога `failed to send SMS: SMSDevices not configured for
  /dev/ttyUSB0` находит строку схемы
  `B -->|нет| E[Ошибка: SMSDevices not configured for <устройство>]` ПЕРВЫМ
  результатом, при наличии шумовых схем с `send`, `failed`, `for`.
- IDF: частое слово не перебивает редкое.
- Русские окончания.
- Каждый вид единиц находится (объект, схема, спека, таблица, колонка, канал, поле,
  параметр, процесс, шаг).
- Изоляция проектов.
- Читатель может искать.
- 422 на пустой запрос.
- `limit` и `kinds` работают.
- Кап в 3 строки на схему с «ещё N».
- Отдельно: эндпоинт одной схемы, включая 404 на чужой узел и схему.
