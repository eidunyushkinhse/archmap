## Как работает тур

**Где:**
- только при `demo_mode` и только у гостя;
- запускается сам при первом входе в песочницу;
- «Пропустить» / «Пропустить обучение» — больше не появится сам;
- «Завершить» на финале — тоже.

Состояние тура (пройден или пропущен, текущий шаг) хранится в `localStorage` по id
гостя. Гость живёт, пока жива сессия браузера, поэтому сервер для этого не нужен.

**Кнопка «?»** рядом с меткой «Песочница» в шапках (там же, где метка) запускает тур
с начала.

**Слой тура:**
- затемнение с вырезом и синей рамкой вокруг цели; пульс на шагах с действием;
- карточка с «Шаг N из M», заголовком, текстом, синей строкой действия;
- кнопки «Назад» / «Далее» (на шагах с действием «Далее» нет);
- «Пропустить обучение».

Вид — как в прототипе.
- Цель ищется по DOM: атрибуты `data-tour="…"` на нужных элементах и
  `[data-id]` узлов React Flow.
- Вырез и карточка следуют за целью при скролле, ресайзе, зуме и пане холста.
- Карточка ставится рядом с целью и не вылезает за окно.
- Сквозь вырез цель кликабельна, остальное под затемнением — нет. Исключение:
  холст на шагах с перетаскиванием, где вырез — палитра, а бросать нужно на холст.
  Сделай так, чтобы бросок на холст работал.
- `prefers-reduced-motion` — без пульса.

**Шаги с действием** идут дальше сами, когда пользователь сделал нужное.
- Если он ушёл в сторону, подсказка ждёт.
- Если ушёл на другой экран, тур не ломается: при возврате на нужный экран шаг
  продолжается.
- «Назад» и «Пропустить обучение» работают всегда.

**Как узнавать действия:**
- маршрут (хэш), где хватает его;
- для остального — маленькая шина событий тура, которую зовут из существующих
  обработчиков успеха: узел создан, связь создана, связь перевешена, узел
  раскрыт, драг узла закончен, вход на слой.

Логику тура держать в отдельном модуле, например `components/tour/`. В остальные
компоненты — только `data-tour` и вызовы шины, без логики шагов.

**Шаги про «Ярмарку»** (2–15 прототипа) ищут объекты по именам из демо-пакета:
«Продавец», «Маркетплейс «Ярмарка»», «Сервис заказов», «БД заказов», «Kafka»,
«Order API». Если объект не найден (гость его удалил), шаг пропускается, а не висит.

**Шаги «Ваш проект»** (16 и далее):
- 16 — ждём новый узел формы «Сервис» на корневом слое своего проекта. Он
  становится «системой»: дальше его имя подставляется вместо «Моя система»;
- 17 — ждём второй узел на корневом слое. Его имя подставляется вместо
  «Покупатель»;
- 18 — подсвечиваем ПАРУ хэндлов, по одному у каждого узла: ту, что выберет сам
  рендерер для связи между ними.
  - Найди в движке (`graph/layout`, роутер и выбор портов) функцию выбора сторон
    и портов и посчитай пару заранее, тем же кодом.
  - Если чистого вызова для пары узлов нет и его нельзя дёшево выделить — СТОП,
    опиши в отчёте варианты и что выбрал. Запасной вариант — стороны, смотрящие
    друг на друга по геометрии.
  - Ждём любую связь между этими двумя узлами.
- 19 — подсветка «Войти» на системе, ждём вход на её слой;
- 20 — ждём узел-сервис с родителем «система». Его имя подставляется вместо
  «Веб-витрина»;
- 21 — подсветка рамки и конца стрелки на рамке. Ждём, что связь перевешена на
  дочерний узел (её конец стал ребёнком системы);
- 22 — подсветка «Проект» в шапке редактора, ждём возврат на корневой слой.
  Проверь, что это действительно путь на верхний слой; если нет — опиши и
  подсвети реальный;
- 23 — подсветка связи на слое контекста, кнопка «Далее»;
- 24 — подсветка лупы на системе, ждём раскрытие → финал.

**Подстановка имён:**
- «Моя система», «Покупатель», «Веб-витрина» — из созданных узлов;
- падежи не склонять. Где имя стоит в косвенном падеже («Покупателе», «Моей
  системе»), перефразируй так, чтобы имя стояло в кавычках в именительном падеже,
  например «от точки на объекте «X» к точке на объекте «Y»». Список таких правок —
  в отчёт.

**Повторный запуск «?», когда свой проект уже создан.**
- «+ Новый проект» погашена, поэтому шаги 14–15 не выполнить. Тур проходит
  «Ярмарку» (до шага 13 включительно) и заканчивается короткой финальной
  карточкой: «Свой проект у вас уже есть. Продолжайте в нём.» с кнопкой
  «Завершить».
- Это решение архитектора, текст можно будет поправить на приёмке.

## Шаги

1. Модуль тура: модель шагов (данные), чистая машина состояний (переходы по событиям,
   пропуск ненайденных целей, подстановка имён) и тесты на неё.
2. Слой тура (оверлей, карточка, позиционирование), кнопка «?», автозапуск и
   хранение. Тесты компонента.
3. Привязка к продукту: `data-tour`, события шины, расчёт хэндлов для шага 18.
   Тесты на события.
4. Проверка на демо-экземпляре (http://localhost:5174, `scripts/dev-demo.sh`).
   - Headless-сценарий проходит тур целиком новым гостем, со скриншотами ключевых
     шагов для сверки с прототипом.
   - Перетаскивание из палитры в Playwright может не завестись. Тогда создай узлы
     через API, а шаги с ожиданием проверь событиями: главное, что тур реагирует.
   - Отдельно — повторный запуск «?» при уже созданном проекте.
5. Документация:
   - `spec.md` — подраздел «Обучение» в «Демо-режиме»;
   - `tasks.md` — пункт онбординга: «тур в демо сделан в ветке feat/demo-mode, ждёт
     приёмки; в обычной версии — решить отдельно».

## Скоуп-гард

Не делать:
- тур вне демо-режима;
- серверное хранение прогресса;
- аналитику;
- правку текстов прототипа сверх подстановки имён.

Не трогать:
- поведение холста и роутера (только чтение функций выбора портов и `data-tour`);
- промпты.
