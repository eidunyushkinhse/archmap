# Задание: убрать создание проекта из шаблона

Работа идёт коммитами в main. Код пишет opus-xhigh, принимает архитектор.

## Решение пользователя (2026-09-30)

Способ создания проекта «Шаблон» убираем насовсем. Онбординг на демо-проекте
«Ярмарка» будет позже отдельной задачей (в `tasks.md` это пункт «ОНБОРДИНГ ВМЕСТО
СПОСОБА СТАРТА «ИЗ ШАБЛОНА»»).

Что убираем и что оставляем (решение архитектора по записи в бэклоге):

**УБРАТЬ:**
- вариант «Шаблон» в окне «Новый проект» (`CreateProjectDialog`) вместе с витриной
  (`C4Preview` и всем, что работает только на неё);
- шесть каркасов C4 в `backend/app/templates.py` (`list_templates`,
  `seed_template` и данные каркасов);
- API шаблонов: поле или ветку «шаблон» в создании проекта и эндпоинт списка
  шаблонов, если они есть. Pydantic-схемы → `npm run gen:api`, закоммитить
  `api.gen.ts`;
- функции `api/projects.ts`, типы и тесты, которые проверяют только эту фичу.

**ОСТАВИТЬ** (понадобится онбордингу):
- пакет демо-проекта `backend/app/template_packages/demo-marketplace/`;
- сидер пакета (`seed_package_template` и то, на чём он стоит);
- `scripts/refresh-demo-template.py`.

Сидер больше не вызывается из API: переложи его в модуль с понятным именем или
оставь в `templates.py`, но без каркасов. Шапку модуля перепиши: «посев демо-пакета
для будущего онбординга». Тесты пакета (фикспойнт md5 Ярмарки и посев) должны
остаться и проходить: теперь они вызывают сидер напрямую.

⚠️ Перед удалением проверь grep'ом:
- `NodeTreePanel.tsx` и `NodeModal.tsx`: там слово «template», скорее всего, про
  шаблоны форм в палитре (drag формы), к этой фиче они не относятся. Не трогай их,
  если это не витрина шаблонов проекта.
- `config_prompt.py` и `import_yaml.py`: «template», скорее всего, значит строку
  промпта или что-то своё. Не трогать.
- MCP-сервер (`mcp/`): если там есть ручка или текст про шаблоны проекта — убрать и
  сказать в отчёте. Если нет — не трогать.

## Шаги

1. **Фронт.**
   - Убрать вариант «Шаблон» из окна создания.
   - Раскладка кнопок вариантов не должна поехать. Сейчас там «Пустой / Шаблон /
     Копия / Импорт / ИИ-агент» — останется четыре кнопки, их нужно расставить
     ровно.
   - Удалить витрину и мёртвый код.
   - Тесты окна создания обновить (вариантов стало на один меньше), а не удалить
     молча.
2. **Бэк.**
   - Убрать каркасы и API шаблонов, сидер пакета сохранить.
   - Если из-за удаления параметров меняется контракт `POST /projects`, это
     санкционировано. Проверь, что фронт и MCP не шлют удалённые поля.
3. **Документация.**
   - `spec.md`: убрать способ старта «из шаблона» и витрину, оставить одну
     строку о том, что демо-пакет сохранён для онбординга.
   - `tasks.md`: в пункте об онбординге отметить, что «Шаблон» убран
     (2026-09-30), каркасы удалены, пакет и сидер живы.
   - `CLAUDE.md` и `QWEN.md` синхронно: строка про `templates.py` в дереве
     структуры («каталог шаблонов: 6 каркасов C4 + пакетный демо-шаблон») → по
     новой роли модуля.
   - `README.md`: если там упоминаются шаблоны старта — поправить.

## Гейты

Гейты гоняются после каждого шага:
- бэк: `./venv/bin/python -m pytest -q`, `ruff check .`, `mypy app/`;
- фронт: `npx tsc -b` (не `--noEmit`), `npx eslint .`, `npx vitest run`;
- MCP-гейт, если трогал `mcp/`.

Коммиты:
- по одному на шаг, на русском, последняя строка
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`;
- через `git commit --only <пути>`;
- после каждого коммита пуш. Если DNS в WSL отвалился — повторять через минуту,
  не бросать;
- первым коммитом — этот файл задания.

Сервис `./dev.sh` работает в фоне, не перезапускать.

## Скоуп-гард

- Онбординг не начинать.
- Демо-пакет и сидер не удалять.
- Миграции не нужны: шаблоны не хранятся в БД. Если найдёшь, что хранятся — СТОП
  и отчёт.
- Холст, промпты и шаблоны форм в палитре не трогать.

## Отчёт

- Коммиты: хэш и суть.
- Что удалено: файлы, эндпоинты, поля контракта.
- Что осталось и где теперь сидер.
- Видимые изменения дословно.
- Отклонения.
