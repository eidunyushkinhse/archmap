Сегодня остаток слияния показывается строками («Замечания к слитой схеме», «Споры
содержимого» радиокнопками), и пользователь правит проект после импорта руками.

споры содержимого — как сегодня (`resolutions`), остальное — словарём `decisions`.

## Решения архитектора (не пересматривать; отклонение — только с раскрытием в отчёте)

Р1. **Порядок и тексты — по ТЗ §4.** Порядок: содержимое → поля → связи в
контейнер → пропущенные связи → похожие имена; внутри вида — порядок бэка.
Названия видов на экране не показывать (кроме подписей полосы при ≥15).

Р2. **Состояние ответов — в диалоге, рядом с `resolutions`.** Споры содержимого
остаются в `resolutions` (`id → "cand:<i>" | "all"`, протокол не меняется);
остальные — `answers: Record<string, Answer>` (union по видам). Протухшие ответы
(id пропал из новой сводки) отбрасываются ПРИ РЕНДЕРЕ тем же паттерном, что
`resolutions` сегодня (не эффектом). Черновики второго шага (форма связи, имя
склейки) — тоже в состоянии по id вопроса (ТЗ §4.6).

Р3. **Строки, ставшие вопросами, скрывает фронт** по `remainder.converted_warnings`
(множество текстов): фильтр для `file_remarks[*].warnings`, `schema_warnings` и
плоских `warnings` одно-файлового режима. Одно правило на экран и на текст
«Скопировать замечания для агента»: копируется то, что показано.

Р4. **Строки `conflicts` («…: оставлено «…» (файл 1), отброшено …») в мульти-режиме
с экрана уходят** вместе с секцией «Замечания к слитой схеме» (ТЗ §1.1): это
чтение, не действие; их читает MCP и агент. В одно-файловом режиме список
«Конфликты слияния» остаётся как сегодня (споров полей там не бывает).

Р5. **Споры `shape` / `status` — вопросы вида 4.2**, значения — человеческими
словами: форма — та же карта, что в палитре `NodeTreePanel` (service «Сервис»,
database «База данных», broker «Брокер», person «Человек» — сверить с кодом);
статус — `graph/colors.ts` (existing «Существует», planned «Планируется»,
deprecated «Устарел»). Прочие поля — значение как есть.

Р6. **`unfixable.agent` бывает null** (замечание без единственного файла-владельца —
на практике почти всегда): кнопка тогда «Скопировать замечание для агента» без
имени. Текст копии — вступление как у сегодняшней кнопки панели (`INTRO_MANY_OK`
в мульти-режиме, `INTRO_ONE_OK` в одно-файловом) + «- {text}».

Р7. **Статус (§2):** «Готово к импорту» — `ok` и вопросов нет и `unfixable` пуст;
«Есть вопросы» — `ok` и есть хоть один вопрос или незакрываемое; «Что-то пошло
не так» — `ok === false`. Первая ошибка: первый непустой `file_remarks[i].errors`
(чип — вход i+1, ссылка «Открыть файл …» делает его активным), иначе
`schema_errors[0]` / `errors[0]` без чипа и без ссылки. Форма «Строка N:» — если
текст ошибки начинается с «строка N» (регистр любой), вынести её в шаблон ТЗ; иначе
«Проблема в файле <чип>: <текст>.»

Р8. **Вьюер схемы (§5.5) — НЕ `<dialog>` внутри `<dialog>`** (memory
native-dialog-gotchas: вложенные dialog ломают cancel/Escape). Реализовать
fixed-оверлеем через `createPortal` в `document.body` с собственной обработкой
Escape так, чтобы Escape закрывал вьюер, а не окно под ним (прецедент стека
Escape — `DocOverlay` в inspector / `ErDiagramModal`: посмотреть, как они это
решают, и повторить). Рендер — `MermaidRenderer` (проп `chart`), только для
кандидатов семьи `doc`; кнопка «Выбрать этот вариант» ставит `resolutions[id] =
"cand:<i>"` и закрывает.

Р9. **Клавиатура ← →** — слушатель `keydown` на `document`, пока блок смонтирован;
игнорировать, если `event.target` — input/textarea/select/contenteditable (в том
же окне живёт textarea YAML) или открыт вьюер. Не перехватывать с модификаторами.

Р10. **Массовые кнопки (§7)** ставят ответы ВСЕМ вопросам видов 4.1 и 4.2 (в 4.1 —
только спорам с кандидатом `current`, как сегодня `withMine`): «Оставить, как было
в проекте» — кандидат `current` (для 4.1 это удаление записи из `resolutions`,
как сегодня; для 4.2 — индекс кандидата `current`); «Взять из новых архивов» —
первый не-`current`. Виды 4.3–4.5 и текущий вопрос не трогать.

Р11. **Кап списка объектов (§5.3)** — первые 4, дальше «Показать остальные N» +
фильтр; кап перечня контекста 4.4 — три имени и «и ещё N». Компоненты пикера —
`remainder.components` у вопроса 4.3, `remainder.node_paths` +
`node_has_children` у формы 4.4. Путь показывать серым префиксом + последний
сегмент полужирным (§5.3); в форме 4.4 — путь целиком тем же способом.

Р12. **Один модуль — одна ответственность:** ни один новый файл не длиннее ~300
строк; чистая логика (сборка вопросов, тексты, итог, payload) — без React, в
`questions.ts`; `ImportPane.tsx` после встраивания НЕ должен вырасти (сегодня 634):
что вынести — решает исполнитель Б (кандидаты: статус + сводка одно-файлового
режима, копирование замечаний).
