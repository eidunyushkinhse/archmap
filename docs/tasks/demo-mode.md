# Задание: демо-режим ArchMap (эпик, ветка feat/demo-mode)

Работаем в ОТДЕЛЬНОЙ ветке `feat/demo-mode` от main. Сливать в main (`--no-ff`) будет
архитектор после приёмки пользователем. Код пишет opus-xhigh, принимает архитектор.

## Мотив

Публичный демо-стенд опенсорс-версии. Это не форк, а режим: настройка `DEMO_MODE=true`.
Сначала проверяем на localhost, потом (отдельной задачей) упаковка и сервер.

## Экраны согласованы, тексты дословно отсюда

`docs/tasks/demo-mode-screens.html` — прототип, принятый пользователем. Прочитай его
целиком. Все тексты, состояния и раскладку бери оттуда дословно. Блок с пределами
вверху и заметки над экранами — пояснения для согласования, в продукт не переносятся.

⚠️ «Три Ярмарки» — внутренний ориентир, откуда взялись числа пределов. В
интерфейсе, текстах ошибок, коде и комментариях его НЕ упоминать. В коде пределы —
просто константы с комментарием «пределы демо-стенда».

## Решения пользователя (2026-10-02), не переигрывать

1. **Изоляция: личная песочница.**
   - На странице входа кнопка «Попробовать без регистрации».
   - По ней создаётся временный гость и его копия «Ярмарки» (сидер
     `seed_package_template` из `app/demo_package.py`). Гость — владелец копии.
2. **Гость может:**
   - править свою «Ярмарку» как угодно;
   - создать ОДИН свой проект любым способом окна «Новый проект»: пустой, копия,
     импорт, ИИ-агент.

   Решение архитектора: гостю разрешено владеть не более чем двумя проектами,
   «Ярмарку» отдельно не помечаем. Архивные проекты тоже считаются: подсказка
   говорит «Удалите его».

   Приглашать других и делиться гость не может.
3. **Пределы проекта в демо:**
   - объектов — до 100;
   - связей — до 120;
   - схем логики — до 75;
   - процессов — до 10;
   - текста в проекте — до 250 КБ;
   - загружаемый файл — до 250 КБ.
4. **Выключено всё, что гостю не нужно:**
   - вход по логину;
   - регистрация;
   - меню профиля (смена пароля, выход);
   - экран «Пользователи»;
   - окно и пункт «Доступ»;
   - MCP: у гостя нет пароля, отдельно делать ничего не надо.

   Заглушек сверх прототипа не появляется: скрытое просто скрыто.
5. **Песочница живёт сутки бездействия**, потом удаляется вместе с проектами гостя.
6. **Входа по логину на демо-стенде нет.**
   - Гость возвращается в песочницу, пока его браузер хранит сессию.
   - Если сессия жива, а песочницу уже удалили — «Ваша песочница удалена…»
     (жёлтая плашка, текст из прототипа).
   - Сессии нет — обычный экран демо-входа.
   - Администрирование демо-стенда — только серверными командами.

## Решения архитектора (техника)

- **Настройки** в `config.py`:
  - `demo_mode: bool = False`;
  - `demo_max_sandboxes: int = 300` — сколько живых песочниц разом; дальше
    «На демо сейчас слишком много пользователей…»;
  - `demo_start_per_ip_per_hour: int = 10`.

  Пределы проекта — константы в новом модуле `app/demo.py`, не настройки.
- **`GET /auth/config`** отдаёт `demo_mode` и пределы (фронту для проверки файлов до
  загрузки).

  При `demo_mode`:
  - `allow_signup` фактически `false`;
  - `POST /auth/login` и `/auth/register` → 403 с понятным `detail`;
  - смена пароля и `/admin/*` для гостя → 403.
- **Гость:**
  - в `users` поля `is_guest bool NOT NULL default false` и
    `last_active_at timestamptz NULL` (миграция Alembic, аддитивная);
  - логин вида `guest-<короткий случайный>`, пароль случайный и нигде не
    показывается;
  - общая роль `architect`, чтобы мог создавать проекты; `is_admin` всегда false.
- **`POST /api/v1/demo/start`** (без авторизации, только при `demo_mode`, иначе 404):
  - проверить предел живых песочниц и лимит по IP. Отказ → 429 с `detail`
    «На демо сейчас слишком много пользователей. Попробуйте через час.»;
  - создать гостя, посеять «Ярмарку» владельцем-гостем (`visible_to_all = false`);
  - вернуть токен как у логина.

  Лимит по IP — в памяти процесса, по `request.client.host`. Заголовки прокси
  настроим на шаге упаковки, сейчас не трогать.
- **Активность и срок:**
  - `get_current_user` для гостя обновляет `last_active_at` не чаще раза в минуту;
  - токен гостя живёт дольше суток (например 30 дней), но реально песочницу
    держит `last_active_at`.
- **Песочница удалена.**
  - Если токен валиден, а пользователя нет, и в токене признак гостя (добавь
    claim), то 401 с отдельным `detail`. Фронт по нему показывает жёлтую плашку
    из прототипа.
  - Признак гостя в токене только для этого различения, права по нему не
    решаются.
- **Уборка:**
  - функция в `app/demo.py` удаляет гостей с `last_active_at` старше 24 часов
    (или без активности после создания), сначала их проекты (каскадом схемы),
    потом учётку;
  - при `demo_mode` запускается фоном в приложении раз в 10 минут: lifespan,
    asyncio-задача, сессия БД на прогон;
  - плюс команды в `app/admin.py`: `demo-cleanup` (прогнать сейчас) и `demo-stats`
    (живые песочницы, проекты гостей, самые старые).
- **Гостю запрещено на бэке** (403, даже если фронт кнопку не показал):
  - участники и передача владения;
  - `visible_to_all`;
  - `GET /users`;
  - третий проект: 409 с текстом подсказки из прототипа.
- **Пределы проекта — одна центральная проверка.**
  - Не размазывать по ручкам: их десятки (узлы, связи, доки, процессы, все
    импорты и apply, синк, факты, разведка), одну легко забыть.
  - Предлагаемый способ: при `demo_mode` слушатель сессии SQLAlchemy перед
    коммитом собирает затронутые `project_id`:
    - объекты с `project_id`;
    - доки и факты через `node_id` → `project_id`.

    Он считает объекты, связи, схемы и процессы, а объём текста — суммой длин
    текстовых полей проекта одним-двумя SQL-запросами (описания, схемы логики,
    спеки, конфигурация, таблицы, каналы, процессы).
  - При превышении — исключение, которое глобальный обработчик превращает в 409
    с `detail` по прототипу, транзакция откатывается.
  - Выберешь другой способ — обоснуй в отчёте.
  - Тест-сторож: прогон каждой пишущей ручки сверх предела на маленьких пределах
    (подменить константы в тесте) ловит превышение, хотя бы по одному на семью.
  - Проверка считает итог ПОСЛЕ записи. Удаление и уменьшение всегда проходят,
    даже если проект уже сверх предела.
- **Тексты 409 по прототипу:**
  - объекты, связи, процессы: «Демо-проект поддерживает до N <чего>. Удалите
    ненужные, чтобы добавить новые.»;
  - схемы логики и объём текста: тексты экрана 5;
  - фронт добавляет жирное начало: «Не получилось добавить объект.» /
    «Не сохранилось.».
- **Превью импорта** (новый проект, «Импорт схемы» в проект, синк с кодом).
  - В превью должно быть видно превышение ДО «Создать»: экран 3, плашка + полоска
    «142 из 100».
  - Добавь в ответы этих трёх превью необязательное поле с превышением (что, сколько
    вышло, предел) и кнопку применения блокируй на фронте.
  - Apply всё равно защищён центральной проверкой.
- **Размер файла:** фронт проверяет до отправки (предел из `/auth/config`), бэк —
  тоже: 413 с текстом из прототипа.
- **Pydantic → `npm run gen:api`**, закоммитить `api.gen.ts`.

## Фронт

- **Демо-вход.** При `demo_mode` вместо `LoginPage` — правая половина по экрану 1
  прототипа.
  - Левая половина — та же, что у `LoginPage` (переиспользовать, не копировать).
  - Кнопка «Установить» ведёт на `https://github.com/eidunyushkinhse/archmap` в
    новой вкладке, кнопки одной ширины.
  - Состояния: «Готовим песочницу…», «слишком много пользователей», «песочница
    удалена».
- **Гость в шапках** (лендинг, оболочка проекта, редактор): вместо аватара и меню
  профиля — метка «Песочница».
- **«Все проекты»:**
  - плашка «Это песочница…»;
  - «+ Новый проект» неактивна с подсказкой по наведению, когда у гостя уже два
    проекта (считать по `my_role === "owner"` в списке, включая архив; сервер
    должен отдать, сколько у гостя проектов, или `/auth/me` — `is_guest` и
    `can_create_project`; выбери и опиши);
  - пункта «Доступ» у гостя нет.
- **Тосты пределов на холсте** (экран 4). Используй существующий механизм тостов
  холста, если есть. Окно «Новый объект» показывает тот же текст в своей ошибке.
- **Ошибка в футере окна схемы** (экран 5): правка остаётся в редакторе. Так же —
  спеки, конфигурация, таблицы, каналы, где сохранение может упереться в предел.
- **Импорт** (экран 3): в окне «Новый проект», «Импорт схемы» и синке.
- Тексты без длинных тире (кроме дословных из прототипа), «бездействия» слитно.
- vitest на каждый экран и состояние прототипа.

## Шаги

1. **Бэк: модель, миграция, `app/demo.py`, `/demo/start`, отключения по
   `demo_mode`, уборка и команды.** Тесты:
   - старт;
   - 429 по пределу и по IP;
   - логин и регистрация закрыты;
   - удалённая песочница → особый 401;
   - уборка удаляет только просроченных гостей и их проекты, обычных
     пользователей не трогает;
   - `last_active_at` продлевается;
   - гостевые запреты;
   - вне `demo_mode` всё как раньше.
2. **Бэк: пределы проекта** — центральная проверка, превью с превышением, размер
   файла. Тесты-сторожа по семьям ручек.
3. **Фронт: демо-вход, шапки, «Все проекты».**
4. **Фронт: пределы** — тосты, футер доков, импорт.
5. **Локальная проверка второго экземпляра.**
   - Подними ВТОРОЙ экземпляр в демо-режиме рядом с работающим `./dev.sh`:
     отдельная БД `archmap_demo`, порты 8001 и 5174.
   - Основной сервис и его БД не трогать.

   ⚠️ `dev.sh` создаёт `backend/.env`, только если его нет; переменные окружения
   имеют приоритет над `.env` (pydantic-settings). Проверь, что
   `DB_NAME=archmap_demo DATABASE_URL=… DEMO_MODE=true CORS_ORIGINS=… BACKEND_PORT=8001 FRONTEND_PORT=5174 ./dev.sh`
   (или маленький `scripts/dev-demo.sh`) поднимает изолированный экземпляр, в том
   числе миграции идут в `archmap_demo`.
   - Убедись, что прокси Vite второго фронта смотрит на 8001.
   - Пройди сценарий: старт песочницы → «Ярмарка» на месте → создать проект →
     второй не даёт → импорт сверх предела → добавление сверх предела →
     `demo-cleanup` с подкрученным сроком → «песочница удалена».
   - Headless-браузер — один прогон для сверки с прототипом.
   - Экземпляр оставь работающим для пользователя и напиши в отчёте адрес и
     команду остановки.
6. **Документация:**
   - `spec.md` — раздел «Демо-режим»;
   - `DEV.md` — `DEMO_MODE`, настройки, команды, как поднять демо локально;
   - `tasks.md` — пункт про публичное демо: статус «демо-режим сделан в ветке,
     ждёт приёмки; упаковка и сервер — следующим шагом»;
   - `CLAUDE.md` и `QWEN.md` синхронно, коротко: `demo.py` в дереве, `demo_mode` в
     строке про `config.py`.

## Гейты

После каждого шага:
- бэк: `./venv/bin/python -m pytest -q`, `ruff check .`, `mypy app/`;
- фронт: `npx tsc -b`, `npx eslint .`, `npx vitest run`;
- MCP-гейт — в конце: тесты MCP импортируют бэкендовые схемы, гоняй его и после
  правки схем.

Коммиты:
- по одному на шаг (крупный шаг можно двумя), на русском, последняя строка
  `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`;
- коммитить через `git commit --only <пути>`, для новых файлов — точечный
  `git add <путь>` перед этим; `git add -A` и `commit -a` не использовать;
- пушить ветку после каждого коммита. Если DNS в WSL отвалился — повторять раз в
  минуту;
- первым коммитом — этот файл и `docs/tasks/demo-mode-screens.html`.

⚠️ `./dev.sh` (основной) работает в фоне и смотрит в рабочее дерево с `--reload`.
- После `git checkout -b` он подхватит код ветки, это нормально.
- Миграция аддитивная: накати на основную dev-базу тоже, иначе основной сервис
  упадёт на новых полях. Проверь, что после неё основной сервис отвечает.
- Учётки из `mcp/.env` должны логиниться: основной экземпляр не в `demo_mode`.

## Скоуп-гард

Не делать:
- упаковку для сервера (Docker, nginx, HTTPS) — следующая задача;
- онбординг;
- аналитику;
- капчу.

Не трогать:
- холст и раскладку;
- промпты;
- доступ к проектам для НЕ-гостей.

Вне `demo_mode` поведение продукта не меняется (кроме новых полей `users`) — это
проверяется тестами.
