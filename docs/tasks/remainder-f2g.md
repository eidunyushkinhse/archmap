## 1. Свёртка «Придется подправить вручную (N)» вместо «Что исправит только новый прогон агента (N)»

- Заголовок: `Придется подправить вручную ({N})`.
- Вводная строка (одна): `В файлах есть нестыковки, которые ArchMap не сможет закрыть одним вопросом. Вот их список:`
- Дальше — МАРКИРОВАННЫЙ список (`<ul>`), один пункт на замечание, ТОЛЬКО текст пункта.
  Ни «Можно доработать…», ни «Если оставить…», ни кнопок.
- В свёртку попадают ВСЕ замечания принятых входов, не ставшие вопросами: и схемные
  (как сейчас), и ПОФАЙЛОВЫЕ (раньше жили в карточке «Замечания к файлу N» под
  активным чипом и в одно-файловом списке «Проверьте:»). Бэк: `_unfixable` берёт и
  строки с владельцем (`owner is not None`), кроме converted. Проверь, нет ли
  пофайловых предупреждений, которые живут ТОЛЬКО в `file_remarks[i].warnings` и не
  попадают в `report.warnings` (предупреждения разбора отдельного YAML): если есть —
  они тоже должны оказаться в свёртке (дружелюбный текст или сырой как запасной).
- Карточку `Замечания к файлу N · имя:` и строку `К файлу N замечаний нет.` — УБРАТЬ
  (в обоих режимах), вместе с кнопкой копирования, `copyRemarks`, `askedFor`/
  `StaleFilesConfirm` (они жили только ради копии агенту) и одно-файловым списком
  «Проверьте:». Если `UnchangedInputNote` (заметка о повторном входе) говорит про
  агента — убрать и её из панели ввоза. `importIntros.ts` станет мёртвым — удалить,
  если больше никто не импортирует. Одно-файловый список «Конфликты слияния
  (оставлено первое значение)» — не трогать.
- Контракт `UnfixableOut`: `{id, text, file}` — поля `how`, `agent`, `if_left`
  убрать (их читает только фронт; MCP не читает — проверено). `text` — уже
  дружелюбный пункт. Сырые строки мерджа (`report.warnings`) НЕ МЕНЯТЬ: их читают MCP
  и отчёты применения. После правки схем — `npm run gen:api`, `tsc -b`.

### Тексты пунктов (финальные; подставлять объекты из сырой строки)

Разбор сырой строки — по классу (`_remark_class`, маркеры не менять). Если объект из
строки извлечь не удалось — запасной пункт: сырая строка как есть (без префиксов).

| класс | сырая строка (как есть) | пункт свёртки |
|---|---|---|
| namesakes | `«X» (внутри «P») встречается в файлах как РАЗНЫЕ объекты (различаются источники) — оставлены раздельно` | `«X» (внутри «P») в разных файлах имеет разные метаданные. ArchMap не знает, это один и тот же объект или нет. Если это дубль, его нужно будет удалить вручную.` |
| absorbed | `{имена} слиты в ОДИН объект: у них общий источник (k), а path не задан — …` | `{имена} указывают на один и тот же источник, поэтому ArchMap объединил их в один объект. Если это разные объекты, их нужно будет разделить вручную.` |
| shared_source | `{имена} указывают один источник (k) — …` | `{имена} указывают на один и тот же источник. При следующем обновлении из кода ArchMap узнает только один из них, а второй станет дублем. Чтобы этого не случилось, поправьте якорь в карточке одного из объектов.` |
| edge_labels | `связи {A} → {B}: разные подписи из разных файлов ({подписи}) — …` | `У связи «{A} → {B}» в разных файлах разные подписи ({подписи}). Если это одна и та же связь, лишнюю нужно будет удалить вручную.` |
| roots | `файлы не имеют общих корневых узлов ({имена}) — …` | `У файлов разные корневые объекты ({имена}), поэтому в проекте будет несколько корней. Если это одна система, их содержимое нужно будет перенести в один корень вручную.` |
| actors | `внутри системы оказались люди ({имена}) — …` | `Внутри системы оказались люди ({имена}). Человек пользуется системой, а не входит в неё, поэтому их нужно будет перенести в корень схемы вручную.` |
| lonely | `объектов без единой связи: N ({имена}[ и ещё K]) — …` | `У {N} {объекта\|объектов} ({имена}[ и ещё K]) нет ни одной связи. Проверьте, не потерялись ли связи, и при необходимости проведите их вручную.` (1 → «объекта», иначе «объектов») |
| descendant | `связь «A → B»: «часть» — часть «целое», …` | `Связь «A → B» ведёт от объекта к его собственной части. Её нужно будет удалить или перевесить вручную.` |
| channel_list | `связь «A → B»: в channel перечень «x» — …` | `У связи «A → B» указано сразу несколько каналов («x»). Её нужно будет разделить на отдельные связи вручную.` |
| broker | `связь «A → B»: конец — брокер «Br», а канал …` | `У связи «A → B» с брокером «Br» не указан канал. Его нужно будет вписать в карточке связи вручную.` |
| хвост «…ещё N таких …» | `…ещё N таких …` | приклеивается к предыдущему пункту СВОЕГО класса новым предложением: `И ещё {N} таких же.` |

Если в догрузке (into) сырая строка другая по форме — тот же принцип; тексты выше

## 2. Ошибки разбора: только красный статус, списком при нескольких

- Для битого файла ошибки показываются ТОЛЬКО в статусе «Что-то пошло не так» (как
  сейчас: `Проблема в файле 4 · broken.yaml. Строка 3: …`). Дубль в карточке файла
  уходит вместе с карточкой (п. 1).
- Сломанных входов больше одного (или у одного входа несколько ошибок, или ошибки
  слитой схемы) — под «Что-то пошло не так» МАРКИРОВАННЫЙ список (тот же вид, что в
  свёртке п. 1), пункт на ошибку: `Файл {N} · {имя}. Строка {X}: {текст}` (чип-ссылка
  на вход — как у одиночной строки; строки нет — без «Строка»). Одна ошибка — как
  сейчас, одной строкой без списка. `firstError` → функция всех ошибок (порядок:
  входы по номеру, внутри — порядок бэка; затем схемные). Тест на 2 битых файла.

## 3. Варианты и подсказки вопросов

- Подпись источника без точки: `Из архива plugin-a.zip` вместо `Из архива · plugin-a.zip`
  (бэк `source_label`). По тому же мотиву («не знаем, что это агент») для YAML-входа
  `От агента …` → `Из файла …`. Правило подписи: архив — `Из архива {имя файла
  архива}`; YAML — `Из файла {имя файла}`; у входа без имени файла (вставлен
  текстом) — `Из файла {N}` (номер чипа). Имя корня в подписи больше не используем.
  «Из проекта» (живой узел при догрузке) — как есть. Тесты бэка и фронта обновить.
- Вариант `Добавить все` — без подписи `будут пронумерованы`.
- Все подсказки «Если не отвечать:» → `Если не отвечать, то …` (союз не опускаем):
  - `Если не отвечать, то будут добавлены все {…}, и при добавлении им будут назначены номера.`
  - `Если не отвечать, то в проект попадёт вариант «{источник}», а {второй будет отброшен | остальные будут отброшены}.`
  - `Если не отвечать, то в проект попадёт значение «{v}» ({источник}), а {второе будет отброшено | остальные будут отброшены}.`
  - `Если не отвечать, то связь останется на контейнере и после {создания проекта | догрузки} будет ждать в панели незавершённости. Перевесить её можно будет там.`
  - `Если не отвечать, то группа останется без связей, и панель незавершённости покажет её как изолированную.`
  - `Если не отвечать, то останутся два объекта, и при следующем импорте вопрос повторится.`
  Поищи прочие «Если …:» в remainder/* и приведи к той же форме.
