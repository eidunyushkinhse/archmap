# Эпик «Роли узла: система · контейнер · компонент» — концепция для разведки

Статус: концепция принята владельцем на уровне идеи, реализация НЕ начата. Цель разведки —
найти всё, что устареет, сломается или потребует правки, и собрать подводные камни ДО плана.

## Как устроено сегодня (факты, проверены по коду 2026-10-28)

- Узел (`backend/app/models/node.py`): id, project_id, name, description, role (свободная
  строка), technology, parent_id, shape ∈ {service, database, broker, person}, is_external,
  status ∈ {existing, planned, deprecated}, openapi_spec, source_ref (источник: git:repo#path
  или host:name), version (CAS). «Контейнер» в терминах продукта = любой узел с детьми
  (`has_children` вычисляется). Отдельной роли у узла нет: группировка «Система → подсистемы»
  и «процесс → его модули» выражаются одинаково — parent_id.
- Продукт везде считает узел с детьми АБСТРАКЦИЕЙ (суммой детей):
  - связи: конец связи только в листе; конец в контейнере — алерт «связь упирается в
    промежуточный узел» (`app/alerts.py` _intermediate_edges, AL4-семейство) и замечание
    ввоза «уточните до конкретного компонента» с перечнем компонентов (`merge_warnings.py`,
    тюнинг федерации П5); промпт ввоза, слой 3: «СОЗДАЛ КОМПОНЕНТЫ — ПЕРЕНЕСИ НА НИХ СВЯЗИ
    КОНТЕЙНЕРА» (`import_prompt.py`);
  - схемы логики и спека OpenAPI на контейнере → AL24 `container_own_docs` («Контейнеры со
    своей документацией», модалка «Распределить по детям», `routers/node_docs.py`
    distribute_docs); с 2026-10-28 AL24 видит и параметры конфигурации (`has_config`);
  - конфигурация: промпт предлагает адресами владельца только ЛИСТОВЫЕ сервисы
    (`config_import.owner_service_paths`), превью ввоза предупреждает о владельце-контейнере;
    резолв пометки «зависит от:» — только среди параметров ВЛАДЕЛЬЦА схемы
    (`data_refs._resolve_config`, AL33), обратный индекс — только свои схемы
    (`routers/config_params.py` usage);
  - разведка: заглушки на контейнере → предупреждение превью Р15 (`recon_import.py`);
  - размещение (`models/deployment_instance.py`): экземпляры ТОЛЬКО у листьев (с 2026-10-27;
    раньше — у контейнера с наследованием детьми); размещение контейнера выводится из листьев;
    «цельный контейнер» D22 (`docs/specs/deployment.md`) — все листья поддерева на одном наборе
    площадок → одна карточка; PUT /deployment/placements контейнера расставляет все листья.
  - холст (`frontend/src/components/graph/**`, спеки `docs/specs/container.md`, `guest.md`,
    `edge.md`): свёрнутый локальный контейнер — обычный узел; раскрытый — рамка (compound),
    пунктир 1px #9ca3af, радиус 12, плашка (FramePlaque); гость-контейнер — пунктирный узел
    190×100 с подписью «контейнер»; стрелка в раскрытый контейнер упирается в рамку (эпик
    frame-edges). Узлы 190×100, палитра C4 по глубине (`graph/colors.ts`).
- Полевой репорт 2026-10-28 (пилот): агент смоделировал по C4 — процесс (сервис с детьми) и
  его компоненты (группы маршрутов) — описал конфигурацию и спеку у процесса, схемы у
  компонентов, и всё загорелось (AL33 на каждую пометку, AL24). Починка 2026-10-28 (ветка
  feat/pilot-docs, слита 6869acc3) подтянула конфигурацию к сегодняшнему правилу «факты на
  листьях», но конфликт концептуальный: C4-контейнер (процесс) в ArchMap не существует как
  понятие — любой родитель абстракция.

## Что предлагается (концепция, принятая на уровне идеи)

Две вложенности в одном дереве — две роли узла с детьми:
- **Система** — группировка, сумма детей, своих фактов не имеет. Вкладывается в любую глубину
  (контур → система → подсистема …). Это сегодняшнее поведение контейнера.
- **Контейнер** (в смысле C4, проверено по c4model.com: «something that needs to be running
  in order for the overall software system to work», «it's the container that's the
  deployable unit», «components are not separately deployable units … execute in the same
  process space») — запускается отдельно: процесс, образ, под, база, брокер. Владеет ФАКТАМИ
  ВРЕМЕНИ ВЫПОЛНЕНИЯ: параметры конфигурации, спека OpenAPI, размещение на площадках, законный
  конец входящей связи. Его дети — **компоненты**: части кода, не разворачиваются отдельно,
  владеют ФАКТАМИ КОДА: схемы логики (операции/воркеры), источник (путь в репозитории).
- Лист: если не внутри контейнера — сам контейнер; если внутри — компонент.
- Контейнер внутри контейнера (сайдкар, встроенный процесс): «ближайший побеждает» —
  открытый вопрос, показывать ли это на холсте.
- Формула: **факт контейнера — у ближайшего контейнера, факт кода — у листа/компонента**.

Следствия по семьям:
- конфигурация: параметр описывается у контейнера; пометка «зависит от:» ищет ручку у
  ближайшего контейнера владельца схемы; обратный индекс параметра — схемы всего поддерева
  контейнера; каталог параметров в промпте доков — по контейнеру; промпт конфигурации
  предлагает адресами контейнеры;
- спека: одна на контейнер, у компонента спеки нет (операции компонентов привязываются к
  спеке контейнера — открытый вопрос, как страница компонента показывает операции);
- размещение: экземпляры у контейнера; компоненты внутри контейнера площадок не имеют;
  холст «Развёртывание» показывает только контейнеры;
- связи: конец в контейнере законен (вызывают процесс), уточнение до компонента —
  дополнительная точность, не обязанность; конец в системе — по-прежнему замечание;
- AL24 переворачивается: спека/конфигурация у контейнера — норма, у системы — замечание;
  схемы логики у контейнера с компонентами — открытый вопрос (сейчас алерт, можно оставить);
- превью ввоза всех семей: предупреждать, когда факт контейнера описан у компонента или у
  системы; факт кода (схемы) у системы — замечание как сегодня;
- промпты агентам (ввоз, доки, разведка, конфигурация, факты, скептик): одна фраза о ролях;
  снапшоты промптов обновятся.

Хранение (рабочая гипотеза, разведчики оценивают): поле узла с двумя значениями для узлов с
детьми (например `kind: system | container`, у листа не задаётся и выводится), дефолт для
существующих данных — «система» (сегодняшнее поведение). Поле поедет в YAML-экспорт/импорт,
архив знания, снимки версий, копию проекта, мердж («богатое побеждает»?), синк, MCP
(`archmap_update_node`), api.gen.ts, демо-пакет «Ярмарка», фикстуры лендинга.

UI (прототипы):
- инспектор узла с детьми: выбор из двух — «Контейнер: запускается отдельно, дети — его
  компоненты» / «Система: граница из контейнеров, своих фактов не имеет»; у листа строки нет;
- дерево: чипы роли; холст: раскрытый контейнер — сплошная рамка с шапкой (имя, технология,
  роль), раскрытая система — пунктир как сегодня; свёрнутый контейнер — сегодняшний узел +
  счётчик компонентов; компонент — лёгкая плитка (имя, число схем; без статуса, технологии и
  формы — наследует от контейнера); гость-контейнер — пунктирный узел, подпись «система» для
  группировок;
- прототипы: docs/tasks/c4-elements/prototype-logic.html
  (логика: три режима, переключатели, пересчёт алертов) и
  docs/tasks/c4-elements/prototype-canvas.html (холст: четыре сцены, термины, контрол инспектора).

Терминология: словарь C4 — система / контейнер / компонент. Цена: сегодня продукт зовёт
«контейнером» любой узел с детьми (UI, спеки, доки, промпты, MCP, лендинг, тур демо) —
группировки станут «системой», и слово «контейнер» сузится до C4-смысла. Пользователю из C4
надо объяснить, что «система» в ArchMap вкладывается на любую глубину (в C4 система одна).

## Открытые вопросы владельца (разведка должна их обогатить, не решать)
1. Контейнер внутри контейнера: разрешать, как показывать.
2. Схемы логики у контейнера, у которого есть компоненты: алерт или норма.
3. Дефолт роли для существующих проектов и подсказка по источникам детей (пути в одном
   репозитории → компоненты; разные репозитории → система; монорепозиторий ломает).
4. Операции компонентов и спека контейнера: как страница объекта связывает их.
5. Имя поля и формат в YAML/архиве; поведение при мердже и синке.

## Ограничения разведки
- ТОЛЬКО ЧТЕНИЕ: никаких правок файлов проекта, коммитов, запусков тестов/сборок, записей в БД.
- Репозиторий публичный: в отчёт не переписывать названия рабочих систем владельца из
  dev-базы — если встретятся, называть «проект №N (рабочий)».
- Отчёт — в файл черновика (путь указан в задании) + краткое резюме в ответе.
- Ссылки на код в формате путь:строка. Утверждения — только проверенные чтением.
