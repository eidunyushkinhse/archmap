# История Undo/Redo — спецификация поведения

Нормативный реестр инвариантов истории отмены на уровневой схеме: модель
команд, состав истории, кросс-уровневая семантика, механика отката
перемещений. Формат — [README.md](README.md). Смежное: клавиши и кнопки —
[canvas.md](canvas.md) §7; персист позиций и view_layout — [view.md](view.md);
drawIn после отката — [transitions.md](transitions.md) §9.

Код: `graph/interaction/useHistory.ts` (движок), `graph/interaction/useSnapAlignment.ts`
(persistGroup — команды перемещений), `components/LevelGraph.tsx` (адаптер,
клавиши, кнопки), `pages/TreePage.tsx` (структурные команды, кросс-уровневые
диспетчеры), `graph/interaction/persistGuard.ts`.

## 1. Модель команд и стеков

- **U1.** Движок — чистая фабрика createHistory без React: два стека
  (undo/redo), лимит `MAX_HISTORY = 50` с вытеснением старейших; новый push
  ОБРЫВАЕТ ветку redo. [тест: useHistory.test.ts]
- **U2.** Команда: `{label, level?, undo(), redo()}`; level — containerId
  уровня правки (null = корень). Выполненная команда перекладывается в
  противоположный стек; undo/redo на пустом стеке возвращают false.
  [тест: useHistory.test.ts]
- **U3.** Группировка жеста: beginGroup буферизует push-и, commitGroup
  сворачивает — пусто → ничего; ровно одна → команда как есть (свой
  label/level); больше → составная (undo в обратном порядке, redo в прямом,
  level из первой). Вложенных групп нет — повторный beginGroup продолжает
  буфер. [тест: useHistory.test.ts]
- **U4.** peekUndo/peekRedo отдают верхнюю команду БЕЗ выполнения (нужны
  кросс-уровневому редиректу U12); canUndo/canRedo — предикаты для disabled
  кнопок. [тест: useHistory.test.ts]

## 2. Состав истории

- **U5.** Перемещения (локалы, гости, контейнеры, дети compound-рамок): ОДНА
  команда на жест со списком `{id, old, next}` только реально сдвинутых
  (абсолюты старта снимаются в начале жеста); undo/redo — commitLayout со
  старыми/новыми АБСОЛЮТНЫМИ позициями. Групповой драг = одна команда
  (persistGroup агрегирует жест сам; обёртка beginGroup/commitGroup вокруг
  жеста — страховка). [код]
- **U6.** Создание узла: undo снимает deletion-снимок и удаляет, redo
  восстанавливает С ИСХОДНЫМ id; сопровождается рефетчем уровня и дерева;
  узел, дропнутый в раскрытую рамку, дополнительно рефрешит кэш детей
  контейнера. [код]
- **U7.** Правка полей узла (правая панель): undo/redo — update строго
  СЕМАНТИЧЕСКИХ полей (без позиции и parent_id) с мгновенным зеркалом в стейт
  и обновлением алертов/дерева. [код]
- **U8.** Удаление узла: undo — restore снимка (воссоздаёт всё ПОДДЕРЕВО с
  исходными id, включая строки раскладки), redo — повторное удаление;
  мультиудаление — ОДНА команда «Удаление объектов (N)». [код]
- **U9.** Связи: создание (все три потока — жест, into-пикер, «вне уровня»),
  правка, удаление — снимок/restore/delete + рефетч уровня (правка концов
  меняет проекцию — зеркалить стейтом нельзя). [код]
- **U10.** В историю НЕ попадают: раскрытие/сворачивание контейнеров
  (состояние ВИДА, container.md C7), «Переразложить уровень» (наоборот, чистит
  историю — U14), зум/пан, фильтр «Вид схемы». [код]
- **U11.** Команды кладутся только у архитектора (гейты до push); в
  контекст-схеме мутаций нет вовсе, её локальная история мертва по построению.
  [код]
- **U23.** Клавиатурный сдвиг узлов (стрелки, canvas.md CV31): серия нажатий
  с паузами < 500 мс сворачивается в ОДНУ команду «Перемещение» (несколько
  узлов — «Перемещение группы»); undo/redo переигрывают commitLayout, как у
  драга (U5); мышиный жест, начатый посреди серии, закрывает её флашем;
  размонтирование холста висящую серию не теряет. [код]

## 3. Скоуп и жизненный цикл

- **U12.** История ЕДИНАЯ и СКВОЗНАЯ по уровням: живёт в TreePage, навигация
  её не чистит. Кросс-уровневый undo/redo: диспетчер peek-ает команду и при
  `cmd.level ≠ текущему` СНАЧАЛА навигирует на уровень команды (breadcrumb
  перестраивается по parent_id), ПОТОМ выполняет. [код]
- **U13.** Штамповка level: команды холста — текущим containerId (адаптер
  LevelGraph), структурные — уровнем правки, зафиксированным в замыкании
  команды. [код]
- **U14.** Полная чистка стека ровно в двух случаях: успешное «Переразложить
  уровень» (старые команды указывали бы на стёртые позиции) и ремаунт страницы
  (смена проекта, логаут). Смена уровня и режима «Схема/Процессы» историю НЕ
  чистят. [код; clear как операция — тест: useHistory.test.ts]
- **U15.** Триггеры: Ctrl/Cmd+Z (undo), Ctrl/Cmd+Shift+Z или Ctrl/Cmd+Y (redo)
  — глобальный слушатель window; кнопки-сегмент поверх холста (disabled по
  canUndo/canRedo). Гейты: только архитектор, не контекст, НЕ из полей ввода
  (там нативная отмена текста). Обе дороги зовут кросс-уровневые диспетчеры,
  не движок напрямую. [код]
- **U16.** Хранение — только память вкладки (50 шагов, без localStorage).
  У режима «Процессы» своя независимая история (useProcessHistory). [код]

## 4. Механика отката перемещения

- **U17.** Undo перемещения — КОМПЕНСИРУЮЩАЯ запись, не откат фронт-стейта:
  commitLayout → merge-патч зеркала view_layout + фоновый батч saveLayout +
  синхронное зеркало родителю → пересчёт конвейера, где сохранённые позиции
  перетирают ELK (node.md N19). [тест: levelGraph.test.ts (сохранённые
  координаты перетирают ELK); связка — код]
- **U18.** Команды коммитят через СТАБИЛЬНУЮ обёртку (latest-ref на свежий
  commitLayout): дедуп сравнивает патч со СВЕЖИМ зеркалом, а не со снимком на
  момент создания команды — иначе undo молча гасился (регрессия cb2faad,
  починено 5cc86ff). [код]
- **U19.** Дедуп commitLayout: значение, не отличающееся от зеркала
  (null-нормализация), не пишется и не зеркалится — рубильник петель
  самоподдержки. Следствие: undo без фактической разницы позиций не рождает ни
  записи, ни пересчёта. [код]
- **U20.** Ошибка фонового персиста (сеть/409) → resync: уровень
  перезагружается из БД, зеркало возвращается к истине; одна перезагрузка на
  пачку отказов. [тест: persistGuard.test.ts]
- **U21.** Undo/redo структурной команды = рефетч уровня → ремаунт холста и
  свежий fitView (canvas.md CV8): восстановление требует серверной проекции
  гостей и рёбер. [код]

## 5. Анимации и идентичность

- **U22.** Undo/redo — «ручной жест»: открывает окно `GESTURE_TTL_MS = 4000`
  мс; связи, чья геометрия пересчиталась иначе, перерисовываются drawIn
  (edge.md E64, transitions.md §9); реконсиляция сохраняет выделение
  неизменённых объектов (node.md N28); зеркальный прогон скипается по
  layoutSig. [тест: layoutAnimation.test.ts, reconcileRf.test.ts,
  layoutSig.test.ts]

## Известные ограничения (зафиксированы, не баги)

- Push команды перемещения (persistGroup) юнит-тестом не закрыт: контракт
  стеков закрывает useHistory.test.ts, связка «жест → команда» — только
  код/смоук.
- Label «Перемещение группы» фактически недостижим: persistGroup всегда кладёт
  одну команду на весь жест, до commitGroup доходит максимум одна — она
  сохраняет собственный label. Обёртка groups оставлена страховкой.
- Кнопки Undo/Redo читают canUndo/canRedo на рендере, а стеки живут вне
  React-стейта: disabled обновляется попутными ререндерами обработчиков (на
  практике каждый push/undo сопровождается setState соседей).
