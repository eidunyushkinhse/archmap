# Алерты схемы — спецификация поведения

Нормативный реестр инвариантов подсистемы «незавершённость схемы»: расчёт
алертов на бэкенде, панель SchemaAlerts, фокусировка объекта (locate).
Формат — [README.md](README.md). Смежное: скрытие связи «прямо в контейнер» —
[edge.md](edge.md) E6 / [container.md](container.md) C19; мастер-стрелки —
edge.md E2; рейл тостов и палитра подсветок холста — [canvas.md](canvas.md).

Данные (контракт): `AlertsResponse {disconnected_nodes[], intermediate_edges[],
isolated_groups[]}` — все три поля обязательные массивы.
Код: бэк `app/routers/nodes.py` (GET /nodes/alerts), `app/schemas/node.py`;
фронт `components/SchemaAlerts.tsx` + `schemaAlerts.css`, `pages/useSchemaAlerts.ts`
(хук загрузки + resolveAlertLocate), `pages/MapEditorPage.tsx` (рейл холста +
handleLocate) и `pages/ProjectShell.tsx` (знак в шапке), `components/LevelGraph.tsx`
(LocateRequest), `LevelGraph.css` (lg-locate-flash).

## 1. Расчёт (бэкенд)

- **AL1.** Единственный источник — `GET /api/v1/nodes/alerts`, чистый pull:
  пересчёт на каждый запрос, кэша и пуша при мутациях нет; порядок элементов
  внутри списков не детерминирован (ORDER BY отсутствует). [код]
- **AL2.** Доступ только архитектору (наблюдателю 403); скоуп — ВЕСЬ проект из
  `X-Project-Id` (все узлы и все рёбра), рёбра считаются по СЫРЫМ концам БД —
  проекция уровня и гости на расчёт не влияют. [код]
- **AL3.** Исключений по `is_external` и `status` нет: внешние, planned и
  deprecated узлы и связи участвуют в проверках наравне. [код]
- **AL4.** «Промежуточный узел» = узел, у которого есть хотя бы один ребёнок
  (distinct parent_id по проекту); других критериев контейнерности нет. [код]
- **AL5.** `disconnected_nodes` («объекты без связей»): узел, который НЕ
  промежуточный и не встречается ни одним концом ни в одном ребре. Контейнеры
  исключены осознанно: прямая связь в них — нарушение AL6, а группировка детей
  за связь не считается. [тест: backend/tests/test_alerts.py]
- **AL6.** `intermediate_edges` («связь в промежуточный объект»): ребро, хотя бы
  один сырой конец которого — промежуточный узел. Одна запись на ребро с
  флагами `source_is_intermediate`/`target_is_intermediate` (оба конца
  промежуточные → одна запись, два флага). [тест: backend/tests/test_alerts.py]
- **AL7.** `isolated_groups`: связные компоненты НЕориентированного графа рёбер
  (иерархия parent_id игнорируется — иначе всё связано деревом) из ≥2 узлов;
  алерт зажигается только при ≥2 таких компонент. Одиночки без связей в группы
  не входят — они в AL5. [тест: backend/tests/test_alerts.py]
- **AL24.** `container_own_docs` («контейнеры со своими схемами», правила
  контейнеров 2026-08-03): контейнер (service с детьми, AL4), у которого
  остались СОБСТВЕННЫЕ node_docs или openapi_spec (grandfather). Одна запись на
  контейнер с флагами `has_docs`/`has_spec`. Логика/спеки должны жить на
  атомарных детях — такие доки распределяют по детям (container.md §9,
  C34–C35). Атомарные узлы с доками и контейнеры без своих доков не алертятся;
  не-service с детьми — тоже (контейнер = только service). [тест:
  backend/tests/test_container_rules.py]
- **AL25.** (2026-08-09) `persons_inside` («пользователи внутри системы»): узел
  формы `person` с непустым `parent_id`. По C4 человек живёт на контекстном
  уровне, ЗА границей системы, — актор не может быть частью контейнера. Правило
  требовал промпт импорта и предупреждал отчёт слияния, но объекты, заведённые
  РУКАМИ, не проверял никто. Критерий — форма узла, а не вложенность как
  таковая; человек в корне не алертится. Запись несёт и родителя
  (`parent_id`/`parent_name`) — строка панели читается «<имя> внутри
  <родитель>». В UI слово «актор» не употребляется: форма узла всюду зовётся
  «Пользователь». [тест: backend/tests/test_alerts.py]
- **AL26.** (2026-08-09) `dangling_messages` («сообщения без связи»): сообщение
  процесса с `edge_id IS NULL` — связь, которой оно шло, удалили из схемы
  (ON DELETE SET NULL: удаление связи НЕ сносит сообщение, чтобы расхождение
  было видно, а не происходило тихо). Самосообщения исключены — у внутренней
  операции участника связи C4 и не было (`valid` у них всегда true). Запись
  несёт процесс, подпись и имена концов; порядок — по имени процесса и позиции
  сообщения. Это тот же факт, что подсветка внутри окна процесса, поднятый на
  уровень схемы. ПЕРЕХОД: строка ведёт В ПРОЦЕСС, а не на холст (чинить на
  холсте нечего) — отдельным обработчиком `onOpenProcess`, ИЗ ОБОИХ МЕСТ
  (оболочка страниц и редактор-карта). Из редактора это уход с роута: процесс
  передаётся через `sessionStorage` (`PENDING_PROCESS_KEY`, ключ одноразовый —
  гасится эффектом маунта, не инициализатором: под StrictMode он зовётся
  дважды), а редактор закрывается обычным путём «Готово». БЕЗ подтверждения и
  БЕЗ возврата — решение пользователя 2026-08-11: теряются только стек undo
  редактора и выделение, тогда как уровень записан в роуте, а раскрытия и
  позиции — в БД. До этой даты редактор обработчика не передавал и строка там
  не прикидывалась кнопкой; приёмка показала, что на практике это тупик —
  замечание видно, а починить из редактора нечем.
  [тесты: backend/tests/test_alerts.py, SchemaAlerts.test.tsx,
  MapEditorPage.test.tsx, ProjectShell.test.tsx]
- **AL27.** (2026-08-10) `unbound_participants` («участники без узла схемы»):
  участник процесса с `node_id IS NULL` — линия жизни на диаграмме есть, объекта
  архитектуры за ней нет. Два пути появления: импорт диаграммы, где имя не
  сопоставили ни с одним узлом проекта, и удаление узла (FK гасит ссылку —
  SET NULL; до 2026-08-10 стоял CASCADE, и удаление узла молча сносило участника
  вместе со ВСЕМИ его шагами). Вторая ось «незадокументированности», симметричная
  AL26: сообщение без канала ↔ участник без узла. Запись несёт процесс и имя —
  имя из диаграммы либо имя узла на момент, когда он ещё был (переименование в
  запасное поле не доезжает, у осиротевшего имя может быть устаревшим). Порядок —
  по имени процесса и позиции участника. ПЕРЕХОД: как у AL26, строка ведёт В
  ПРОЦЕСС (`onOpenProcess`) — на холсте такого участника нет вовсе. ПУТЬ
  ИСПРАВЛЕНИЯ ОБЯЗАТЕЛЕН и живёт на шапке участника («привязать»): алерт без него
  был бы тупиком (ср. AL25, где путь исправления отсутствует и это отмечено как
  долг). Привязка подхватывает каналы повисших шагов участника при единственном
  кандидате. [тесты: backend/tests/test_alerts.py, SchemaAlerts.test.tsx,
  bindParticipant.test.tsx]

- **AL28.** (2026-08-11) `orphan_legs` («ответ на асинхронном канале»): шаг с
  `leg='return'`, чей канал `is_synchronous IS FALSE`. Связь НА МЕСТЕ — исчезло
  плечо: у асинхронного канала «ответа» не бывает (`legs_for_edge`), и
  `create_message` такое отклоняет, а уже созданный шаг переживал смену
  синхронности молча и продолжал считаться корректным (находка приёмки
  2026-08-10). Сравнение с `FALSE`, а не «не TRUE»: `is_synchronous` nullable, и
  NULL значит синхронный по умолчанию (`edge_is_synchronous`) — иначе весь легаси
  разом уехал бы в алерт. ОТДЕЛЬНО ОТ AL26, потому что чинится иначе:
  «Восстановить связи» ищет канал повисшему шагу, а здесь канал есть —
  лечится возвратом синхронности либо удалением шага (карточка шага). Запись
  несёт процесс, подпись, метку канала и имена концов. ПЕРЕХОД: как у AL26,
  строка ведёт В ПРОЦЕСС из обоих мест. [тесты: backend/tests/test_alerts.py,
  SchemaAlerts.test.tsx]

## 2. Загрузка (фронт)

- **AL8.** Наблюдатель алерты не запрашивает вовсе (гейт роли ДО вызова —
  эндпоинт ему и недоступен); ошибки загрузки глотаются молча: алерты —
  вспомогательный индикатор, граф важнее. [код]
- **AL9.** Рефетч — хвостом каждой загрузки уровня (маунт, любая навигация,
  удаление узла/связи, создание/правка связи, undo/redo структурных операций,
  ресинк после ошибки персиста) плюс явно после создания/правки узла (мог стать
  подвисшим) и в undo/redo правки полей узла. НЕ рефетчится при чистых правках
  раскладки. [код]
- **AL9а.** (2026-08-10) У знака в ШАПКЕ (ProjectShell) свой экземпляр хука, и
  он грузится один раз на маунте, а оболочка живёт всё время работы — значит без
  отдельного повода знак протухает. Поводов два: (1) явный сигнал мутации от
  содержимого — ProcessWorkspace.onChanged (любая правка процесса) и удаление
  узла со страницы; (2) смена страницы/режима — дешёвая страховка для правок, у
  которых своего канала нет. Прежняя оговорка «в режиме „Процессы“ не
  рефетчится» СНЯТА: с появлением класса «Сообщения без связи» (AL26) алерты
  зависят от процессов, и удалённое повисшее сообщение оставалось в знаке до
  перезагрузки страницы. [тест: ProcessWorkspace.test.tsx]

## 3. Панель SchemaAlerts

- **AL10.** (v2, 2026-08-01) ДВЕ точки размещения (решение «вариант 3»):
  (1) знак в ШАПКЕ ProjectShell — глобальная видимость незавершённости с любой
  страницы; клик по пункту ведёт в редактор-карту к проблемному месту (цель
  передаётся через sessionStorage `archmap.pendingAlertLocate`, т.к. URL-locate
  умеет только узел, а алерты ведут ещё к связям и группам);
  (2) рейл тостов правого верхнего угла ОБЛАСТИ ХОЛСТА редактора-карты
  (MapEditorPage; не вьюпорта; canvas.md §6) — in-context locate + тост «Схема
  завершена» при обнулении. Обе точки только для архитектора. Переходы у них
  ЗЕРКАЛЬНЫ: из шапки уводит в редактор (`archmap.pendingAlertLocate`), из
  редактора — в процесс (`archmap.pendingProcess`, AL26); в обе стороны цель
  едет через sessionStorage, потому что роут её не выражает. Данные общими
  хуком `useSchemaAlerts` + разрешение цели `resolveAlertLocate` (pages/
  useSchemaAlerts.ts). В легаси TreePage панель жила только в рейле холста. [код]
- **AL11.** Общий счётчик `total = disconnected + intermediate + max(0,
  groups − 1) + container_own_docs + persons_inside + dangling_messages +
  unbound_participants + orphan_legs`: изолированные группы дают «число
  недостающих связей», при этом счётчик СЕКЦИИ показывает фактическое число групп
  (2 группы → в сумме 1); каждый контейнер со своими схемами, каждый вложенный
  пользователь, каждое повисшее сообщение, каждый участник без узла и каждый
  осиротевший ответ дают по 1. [тест: SchemaAlerts.test.tsx]
- **AL12.** `total == 0` (и тост не показывается) → компонента нет вовсе
  (null): «нулевого» значка не существует. [код]
- **AL13.** Индикатор — янтарная (#f59e0b) круглая кнопка 42×42 с
  баблом-счётчиком; на РОСТ total (включая первичную загрузку 0→N) — пульс
  расширяющегося кольца 1.4s ×3; prefers-reduced-motion отключает пульс и
  въезды. [глаза]
- **AL14.** Панель: ширина 296, maxHeight 460 со скроллом; пустые секции не
  рендерятся; закрытие — повторный клик, клик вне, Esc; при обнулении total
  закрывается принудительно. [код]
- **AL15.** Пункты кликабельны только при переданном onLocate (Enter/Space —
  тоже); в «source → target» конец-нарушитель подсвечен янтарным полужирным;
  на hover — иконка-прицел «Показать на схеме». [глаза]
- **AL16.** Тост «Схема завершена» стреляет только на переходе `total > 0 → 0`
  в рамках жизни компонента: на маунте с нулём не стреляет, ремаунт (смена
  режима) память сбрасывает; держится `TOAST_HOLD = 2500` мс, уезд 260 мс.
  [код]

## 4. Фокусировка (locate)

- **AL17.** Клик по пункту: свежий срез узлов, целевой уровень = САМЫЙ ГЛУБОКИЙ
  ОБЩИЙ ПРЕДОК (узел → его родитель; связь → общий предок концов; группа —
  общий предок всех членов); при несовпадении с текущим — навигация на уровень;
  затем LocateRequest `{kind, ids, token}`; token монотонный — повторный клик
  по тому же объекту фокусирует заново. [код]
- **AL18.** Запрос обрабатывается ОТЛОЖЕННО: эффект ждёт появления цели среди
  отрисованных объектов (раскладка асинхронна, кросс-уровневый переход
  ремаунтит холст); token фиксируется только по факту нахождения цели. [код]
- **AL19.** Центрирование: узел — setCenter на центр с zoom 1.2 (чуть крупнее
  обычного fitView), 600 мс; связь и группа — fitBounds их bbox c padding 0.4,
  600 мс (bbox связи — по обоим отрисованным концам). [код]
- **AL20.** Вспышка — янтарная двойная пульсация 2.1s по СИЛУЭТУ объекта
  (drop-shadow по alpha-форме, не bbox), класс lg-locate-flash снимается через
  2200 мс; янтарь сознательно отличен от синего RF-выделения и индиго-подсветки
  панели (canvas.md §4). [глаза]
- **AL21.** Группа подсвечивает лишь членов, отрисованных на целевом уровне под
  своими id (члены внутри контейнеров не находятся); для фиксации token
  достаточно одного найденного. [код]
- **AL22.** Связь ищется среди отрисованных по сырому edge_id И по членству в
  мастер-пучке (memberIds): алерт по связи, слитой в merge-стрелку (E2),
  фокусирует и подсвечивает несущий пучок (фикс 2026-07-16). [код]
- **AL23.** Связь, скрытая проекцией (конец = раскрытый контейнер, E6/C19),
  фокусируется фолбэком ПО КОНЦАМ: представители сырых концов на холсте (узел
  либо рамка раскрытого контейнера — id рамки = id узла, C3) вписываются
  fitBounds и пульсируют янтарём; token фиксируется — запрос не «висит»
  (фикс 2026-07-16). [код]

## Известные ограничения (зафиксированы, не баги)

- Повисшие сообщения бизнес-процессов (valid=false) в алерты НЕ интегрированы:
  подсветка есть только внутри sequence-диаграммы; интеграция — идея в tasks.md.
- pytest закрепляет только чистый расчёт (прямой вызов функции): HTTP-слой
  (порядок роутов, 403 наблюдателю, скоуп заголовка) и вся фронтовая часть
  (формула total, пульс, тост, locate) тестами не покрыты.
