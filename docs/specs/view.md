# Уровень и вид — спецификация поведения

Нормативный реестр инвариантов уровня (дети одного контейнера) и вида
(персистентная раскладка уровня: view_layout, владение позициями,
«Переразложить», breadcrumb-навигация). Формат — [README.md](README.md).
Смежное: own-on-first-render как поведение узла — [node.md](node.md) §6;
own-on-expand и раскрытия — [container.md](container.md) §2; гость —
[guest.md](guest.md); undo — [history.md](history.md); вьюпорт и ремаунт
холста — [canvas.md](canvas.md) §2.

Код: бэк `app/models/view_layout.py`, `app/routers/{views,nodes}.py`,
`app/projects.py`, `app/restore.py`, `app/tree.py`, `app/schemas/node.py`;
фронт `pages/MapEditorPage.tsx`, `components/LevelGraph.tsx` (commitLayout,
expanded), `graph/layout/{pipeline,engine}.ts`, `api/{client,projectScope,nodes}.ts`.

## 1. Модель данных

- **V1.** Единое хранилище раскладки — таблица `view_layout`: `project_id`
  (CASCADE), `view_id` (FK nodes, CASCADE, NULLABLE), `item_id` (строка БЕЗ
  FK), `payload` (JSON). «Вид» = контейнер уровня; `view_id NULL` — корневой
  вид проекта. Строка = геометрия одного объекта на одном виде. [код]
- **V2.** Уникальность `(project_id, view_id, item_id)` с
  `postgresql_nulls_not_distinct` — NULL корневого вида участвует в
  уникальности как значение. [код; отсутствие дублей —
  тест: backend/tests/test_view_layout.py]
- **V3.** Payload — только заданное: `{x?, y?, expanded?}` (все поля
  опциональны, неизвестные ключи через API не записываются). `expanded` —
  часть состояния вида: персистится, переживает перезаход, дети персистно
  раскрытых локалов догружаются цепочкой. [тест: backend/tests/test_view_layout.py]
- **V4.** `item_id` без FK — намеренно: строки «не показанных сейчас» проекций
  живут в БД и воскресают при возврате проекции; чтение графа БД не мутирует
  (инвариант F6а). Мусор чистится delete_node (V27) и «Переразложить» (V22).
  [тест: backend/tests/test_build_graph.py]
- **V5.** Колонок раскладки в `nodes`/`edges` нет (снесены миграцией
  aa11bb22cc33 вместе с таблицами ghost_positions/ghost_edge_handles/
  edge_waypoints; данные не мигрировались — пере-засев own-on-first-render).
  [код]

## 2. Легаси-строки (ручной слой стрелок, удалён 2026-07-09)

- **V6.** Строка, у которой x, y и expanded все отсутствуют (например, легаси
  «b:src>tgt» с одними хэндлами/изломами), при отдаче графа отфильтровывается
  — фронт легаси не видит и не пишет. [тест: backend/tests/test_view_layout.py]
- **V7.** Копия проекта режет payload до живых ключей `{x,y,expanded}`;
  опустевшие и «висячие» (view_id на несуществующий узел) строки не
  копируются. [код]
- **V8.** Легаси уничтожается «Переразложить» (весь вид) и delete_node
  (LIKE-чистка по uuid в ключе). Undo-снимки удаления сохраняют и
  восстанавливают легаси-строки бит-в-бит. [тест: backend/tests/test_relayout.py,
  test_delete_node.py, test_restore.py]

## 3. API и гейты

- **V9.** Единственная запись раскладки — `PUT /api/v1/views/{view_id}/layout`
  (200 `{version, graph_rev}` с 2026-07-16): `view_id = "root"` → NULL, не-uuid
  → 422, контейнер вида удалён → 404 (раньше 500 на FK); тело
  `{items: {item_id: payload | null}, base_version?}`, null = удалить строку
  (удаление несуществующего — no-op).
  [тест: backend/tests/test_view_layout.py, test_concurrency.py]
- **V10.** Апсерт app-level в одной транзакции (ON CONFLICT с NULL view_id
  различается между PG и SQLite тестов); payload заменяется ЦЕЛИКОМ —
  частичный мерж, обязанность клиента. Конкурентность — fence версии вида
  (см. §12); батчи БЕЗ base_version пишут по-старому last-write-wins
  (совместимость). [тест: backend/tests/test_view_layout.py, test_concurrency.py]
- **V11.** Роли: запись раскладки, relayout и все мутации — только архитектор
  (403 наблюдателю); чтение графа — обе роли. Скоуп — заголовок X-Project-Id
  (нет/битый → 400, нет проекта → 404, архив → 409).
  [тест: backend/tests/test_project_isolation.py; 403 — код]
- **V12.** Запись раскладки и relayout НЕ трогают updated_at/updated_by
  проекта — раскладка не смысловая правка; смысловые мутации зовут
  touch_project. [код]

## 4. Уровень и граф уровня

- **V13.** Уровень = дети одного контейнера. `GET /nodes/graph` (корень) и
  `GET /nodes/{id}/graph` отдают: локалы уровня, СЫРЫЕ рёбра (реальные концы;
  всё, что касается поддерева уровня хотя бы одним концом), реестр endpoints
  не-локальных концов (guest.md §1) и слой layout этого вида как есть.
  [тест: backend/tests/test_build_graph.py, test_view_layout.py]
- **V14.** Проекция концов на видимые сущности — обязанность ФРОНТА (зависит
  от раскрытий); сервер только отбирает рёбра. [тест: projection.test.ts]
- **V15.** Цепочки предков (breadcrumb, рамки) строит сервер: ancestors в
  порядке «корень → непосредственный родитель» — порядок нормативен.
  [тест: backend/tests/test_tree.py]
- **V16.** Пустой уровень (нет локалов) возвращается ранним return с пустым
  layout — даже если строки вида в БД есть (известная асимметрия); version и
  graph_rev при этом отдаются как у непустого (V47). [код]

## 5. Сборка уровня на фронте

- **V17.** Заход на уровень = ОДИН запрос getGraph → четыре стейта (nodes,
  endpoints, viewLayout, edges с обогащёнными именами), следом fire-and-forget
  загрузка алертов (alerts.md AL9). Ошибка load не ловится — уровень остаётся
  пустым, спиннер снимается. [код]
- **V18.** viewLayout в MapEditorPage — «зеркало БД»; правки приходят ТОЛЬКО из
  onLayoutChanged (единственный канал): null — удалить ключ, иначе заменить.
  [код]
- **V19.** Отказ фонового персиста → resyncOnPersistError: уровень
  перезагружается из БД (зеркало возвращается к истине), один resync на пачку
  отказов. [тест: persistGuard.test.ts]
- **V20.** X-Project-Id ставится клиентом из модульного синглтона projectScope
  для всех путей, кроме /projects и /auth. Скоуп выставляется СИНХРОННО при
  разборе маршрута в App — ДО маунта MapEditorPage, чей mount-эффект шлёт первые
  запросы уровня (фикс гонки 2026-07-16: установка эффектом опаздывала —
  эффекты родителя исполняются после эффектов ребёнка); дублируется в
  localStorage — рефреш не теряет место. [код; headless-гейт при фиксе]

## 6. Владение позициями (own-on-first-render)

- **V21.** «Владеемая» позиция = строка вида с ОБОИМИ x и y; локалы, гости,
  контейнеры — единообразно. Сохранённая позиция перетирает ELK
  (elk.layered RIGHT, спейсинги по N20, padding 30). [тест: pipeline.test.ts,
  levelGraph.test.ts, engine.test.ts]
- **V22.** Засев: каждая отображаемая ГОСТЕВАЯ сущность и каждый вышедший из
  раскрытия ребёнок БЕЗ строки получает свою ФИНАЛЬНУЮ позицию прогона
  (кольца + enforce + разведение + A10). Обычные локалы уровня НЕ засеваются —
  чистый ELK-уровень остаётся без строк локалов. [тест: pipeline.test.ts,
  ringPlacement.test.ts]
- **V23.** Конвейер в БД не пишет: засев возвращается интентами
  `{kind:"seed-positions"}`, применяет LevelGraph — и только если прогон не
  перегнан более новым (stale-прогон не пишет НИЧЕГО: ни интенты, ни
  гистерезис, ни setLayout; инвалидация и на unmount).
  [тест: pipeline.test.ts (интенты); порядок применения — код]
- **V24.** Конвергенция: зеркало кладёт seed в viewLayout → следующий прогон
  видит сохранённое, интент не повторяется, позиции не дрейфуют.
  [тест: pipeline.test.ts]
- **V25.** Гейт «наблюдатель не пишет» — фронт: ВСЕ записи канваса идут через
  commitLayout, начинающийся с `if (!isArchitect || !canArrange) return`
  (canArrange=false и у read-only блоков страниц — они не пишут даже у
  архитектора, context.md X13); дублирующий гейт в persistGroup; бэк —
  require_architect (V11). Наблюдатель
  раскрывает контейнеры ЭФЕМЕРНО (локальные override поверх сохранённого,
  живут до смены уровня). [код]
- **V26.** Own-on-expand: контейнер без владеемой позиции закрепляет текущую
  при раскрытии одним патчем `{expanded, x, y}` (container.md C6).
  Сворачивание пишет `expanded: null` — поле выкидывается, строка НЕ
  удаляется; строка, оставшаяся совсем пустой, отфильтруется при отдаче как
  легаси (V6). Раскрытия в undo-историю не попадают (history.md U10). [код]
- **V27.** Сдвиги ВЛАДЕЕМЫХ узлов из разведения гостей и цикла инвариантов
  персистятся интентом только ЗАМЕТНЫЕ (>1px от строки) — микро-дрейф в БД не
  ползёт. [тест: pipeline.test.ts]

## 9. Breadcrumb и навигация

- **V33.** Breadcrumb — цепочка AncestorRef, текущий уровень — последний
  элемент (null = корень «Контекст»). Переходы: drillDown — АППЕНД (кнопка
  «Войти»; для узла, раскрытого инлайн глубже уровня, промежуточная цепочка
  восстанавливается по parent_id); drillToPath — путь ЗАМЕНЯЕТСЯ целиком
  (дерево слева, «Войти к компонентам» гостя/контейнера — путь строится заново
  от корня); «Перейти к источнику» гостя — уровень его родителя (guest.md
  G22); клик по крошке/«вверх» — срез пути; navigateToLevel (кросс-уровневый
  undo, locate) — достройка breadcrumb по parent_id из полного списка узлов.
  [код; ancestors — тест: backend/tests/test_tree.py]
- **V34.** Кнопки входа — только в редакторе (drill-навигация); в read-only
  блоке страницы объекта кнопок «Войти» нет (лупа и двойной клик остаются).
  Гейты: локальный узел — «Войти» только у формы service (canHaveChildren);
  гость — «Войти к компонентам» только при has_children; свёрнутый гостевой
  контейнер — всегда (в редакторе). [код]
- **V35.** URL кодирует ТОЛЬКО проект (#/p/<id>): уровень в URL не попадает,
  перезагрузка страницы всегда открывает корень проекта; сам проект
  переживает перезагрузку (hash + localStorage). [код]
- **V36.** Смена проекта = полный ремаунт MapEditorPage (key=projectId): свежий
  корень, сброс breadcrumb и undo-истории. [код]

## 12. Конкурентные сессии (этап 0/1, docs/archive/plan-concurrency.md)

- **V44.** Fence версии вида: у каждого вида есть счётчик `view_state.version`
  (строка отсутствует = 0). Батч с `base_version`, не равным текущей версии, —
  409 «Вид изменён в другой сессии», НИЧЕГО не применяется; совпавший —
  применяется и бампает версию на 1. Проверка идёт и у пустого батча (версия
  при этом не двигается). [тест: backend/tests/test_concurrency.py]
- **V45.** Строка версии берётся `FOR UPDATE` ДО применения батча — она же
  мьютекс писателей вида: конкурентные батчи сериализуются, гонка INSERT
  одного ключа view_layout (двойной own-on-first-render сид → 500 по
  уникальному констрейнту) исключена по построению. Гонку создания самой
  строки версии закрывает savepoint. На SQLite тестов FOR UPDATE — no-op. [код]
- **V46.** Мутации мира вида ВНЕ батча раскладки тоже бампают его версию:
  relayout уровня; создание узла (вид родителя); удаление узла (вид родителя +
  DISTINCT-виды вычищенных строк раскладки, кроме умирающих каскадом видов
  поддерева); перенос узла между родителями (оба вида); restore снимка
  (родительские виды корней + виды восстановленных строк вне снимка).
  Отставший после любой из них батч отсекается fence'ом.
  [тест: backend/tests/test_concurrency.py]
- **V47.** `GraphResponse` несёт `version` (вида) и `graph_rev` (проекта) —
  базовая точка отсчёта клиента; `PUT layout` возвращает оба после записи
  (echo-suppression: свои записи не выглядят чужими).
  [тест: backend/tests/test_concurrency.py]
- **V47а.** Фенсированные батчи ОДНОЙ сессии сериализованы клиентской очередью
  (persistFenced, LevelGraph): base_version читается в момент СТАРТА задачи
  (после ответа предыдущей), не постановки — параллельные свои батчи не делят
  версию и не ловят самоконфликт 409 → ресинк («вспышка» исходной картинки
  посреди анимации первого раскрытия после «Переразложить»: derived-засев
  уровня в полёте + user-патч own-on-expand). Fence и политика 409 (V44,
  planPersistFailure) остаются против ЧУЖИХ сессий.
  [репро/контроль: spawn-probe --relayout-first --fast-click --slow-layout]
- **V48.** `projects.graph_rev` — курсор «СХЕМА поменялась»: инкрементируется
  мутациями узлов/рёбер/раскладки (атомарным UPDATE, не read-modify-write),
  включая структурные поля узла (имя/форма/иерархия — видны на холсте). В
  отличие от `updated_at` (V12) двигается и раскладкой; V12 при этом в силе —
  updated_at раскладка по-прежнему не трогает. МЕТА узла (роль/технология/
  статус/описание/внешность/openapi, доки) graph_rev НЕ двигает — её курсор
  `projects.meta_rev` (V53). [тест: backend/tests/test_concurrency.py,
  test_meta_rev.py]

## Известные ограничения (зафиксированы, не баги)

- Пустой уровень не отдаёт layout (V16) — асимметрия раннего return.
- Сворачивание контейнера без x/y оставляет строку с пустым payload —
  невидимый мусор до relayout/удаления (при отдаче фильтруется как легаси).
- Гейт 403 на PUT layout/relayout закреплён только объявлением Depends —
  HTTP-теста нет; тесты зовут функции роутеров напрямую.
- Батчи без base_version (сторонние клиенты) по-прежнему last-write-wins —
  осознанная совместимость; наш фронт всегда шлёт base_version (с коммита
  фронт-части этапа 0).
- Стейл-сид гостя, чей источник удалён в окно между поллингами, всё ещё может
  оставить строку-сироту (item_id без FK) — инертна, чистится relayout/
  delete_node; полная гигиена — вне этапа 0.
- Мутации бизнес-процессов graph_rev НЕ двигают (вне скоупа этапа 1: процессы
  не рисуются на холсте уровня).
- Рефетч поллинга может прийти во время набора в правой панели: черновики полей
  инспектора переживают (локальный стейт, ремаунт только по смене выбора), а
  устаревшее сохранение ловит CAS (V49) — потери нет, но канва и панель могут
  до сохранения показывать разные значения поля.
- Жест протяжки связи (connect) поллинг-гардом не считается жестом — рефетч
  посреди протяжки возможен (редко: окно 10 с); реконсиляция сохраняет
  идентичность узлов, но линия-превью может сброситься.
