# perf — производительность и отзывчивость рендерера

Скоуп: скорость конвейера раскладки (pipeline + worker), реакция UI на счёт,
деградации на больших сценах. ФОРМА автораскладки — node.md N20 (правится
эпиком renderer-perf отдельно, после выбора варианта глазами); здесь — только
«как быстро» и «что видит пользователь, пока считается».

Спека создана 2026-08-20 (эпик renderer-perf, docs/plan-renderer-perf.md) как
РЕЕСТР ЦЕЛЕЙ: бюджеты утверждены пользователем до реализации. Инварианты с
маркером `[ЦЕЛЬ]` — норматив, к которому код ПРИВОДИТСЯ; они заведомо
расходятся с текущим кодом до конца эпика (базлайн: Sentry-корень 133с).
По мере реализации маркер меняется на обычный ([тест]/[код]/[полигон]).

## 1. Размерные классы сцены

- **P1.** Класс сцены считается по ОТОБРАЖАЕМОМУ (после проекции): узлы =
  локалы + гости, рёбра = мастер-рёбра (groupArr). Классы:
  «типовая» — ≤50 узлов И ≤100 рёбер; «предельная» — ≤80 узлов И ≤200 рёбер;
  сверх того — «перегруженная» (вне гарантий скорости, деградации законны).
  Ориентиры из эталонов: Grafana-корень — типовая; Zabbix-корень (36/85) —
  типовая; Sentry-корень (51/128) — предельная. [код — после реализации]

## 2. Бюджеты времени

- **P2.** Полный прогон конвейера (проекция → раскладка → роутер → плашки),
  замеренный scripts/perf-probe.mjs на эталонах: типовая сцена — ≤1.5с;
  предельная — ≤5с. Бюджет на ОДИН прогон; операция из двух прогонов
  (двухфазный замер габаритов, view.md V2.2b) обязана укладывать В СУММЕ
  раскрытие/открытие в тот же бюджет ×1.5. [ЦЕЛЬ]
- **P3.** Хвост пост-обработки после применения раскладки (анимации, drawIn)
  бюджетом P2 не считается — он ограничен своими константами transitions.md.

## 3. Отзывчивость UI во время счёта

- **P4.** Любой пересчёт раскладки дольше INDICATE_AFTER_MS = 300 обязан
  показывать индикацию занятости: на холсте — явный признак «считаю раскладку»
  (в т.ч. на пустом холсте первого показа), на триггер-контроле (лупа/кнопка) —
  состояние занятости. Пустой холст или визуально «ненажавшаяся» кнопка без
  индикации — дефект. [ЦЕЛЬ]
- **P5.** Повторный клик по триггеру во время счёта того же интента не ставит
  второй пересчёт и не ломает первый (защита от прокликивания). [ЦЕЛЬ]
- **P6.** Счёт не блокирует главный поток: конвейер в Web Worker
  (transitions.md AN19), кадры UI живут во время счёта. [код — уже держится]

## 4. Деградация на перегруженных сценах

- **P7.** На типовых и предельных сценах анимации переходов (раскладка,
  раскрытие/сворачивание, drawIn) НЕ отключаются. [ЦЕЛЬ]
- **P8.** На перегруженной сцене анимации отключаются ЧЕСТНО и ЯВНО: разовый
  тост «схема перегружена: плавность не гарантируется, анимации могут
  отключаться» (один на вход в перегруженный вид, не на каждый пересчёт).
  Молчаливое «провисание» анимаций — дефект. [ЦЕЛЬ — решение пользователя
  2026-08-20]

## 5. Измеритель (нормативные инструменты)

- **P9.** Бюджеты P2 меряются scripts/perf-probe.mjs (wall-clock сценариев на
  живом стеке, сигнал __archmapLayoutInflight) на эталонных проектах
  «* Эталон». Атрибуция по стадиям — реплей захваченного входа:
  __archmapCaptureInput → perf-probe --capture → pipelineReplay.perf.test.ts
  (хук __ARCHMAP_TRACE, 12 марок в computeViewLayout). Мокапы форм раскладки —
  layoutMockup.perf.test.ts (переопределение __archmapElkOverride в engine.ts).
  Все три хука в проде мертвы (не выставлены). [код]
