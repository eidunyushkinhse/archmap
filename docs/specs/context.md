# Контекст-схема — спецификация поведения

Нормативный реестр инвариантов контекст-схемы как ВИДА целиком: модальный
read-only вид «фокус-узел + все его соседи по связям». Формат —
[README.md](README.md). Геометрия рёбер контекста (звезда, единый хэндл,
обходы, полки) — [edge.md](edge.md) E67–E71; группы-полосы под рамками —
[container.md](container.md) C32; здесь — всё остальное.

Код: бэк `app/routers/nodes.py` (get_node_context), `app/schemas/node.py`
(NodeContextResponse); фронт `components/NodeContextModal.tsx`,
`components/LevelGraph.tsx` (ветки isContext), `graph/layout/{context,pipeline}.ts`,
`components/NodeTreePanel.tsx` (точка входа).

## 1. Контракт бэка (GET /nodes/{id}/context)

- **X1.** Эндпоинт доступен ОБЕИМ ролям (наблюдателю тоже); узел чужого
  проекта или несуществующий → 404 «Узел не найден»; других ошибок нет. [код]
- **X2.** Сосед = другой конец связи, у которой РОВНО ОДИН конец в поддереве
  фокуса (сам узел + потомки любой глубины): сквозные связи потомков
  включаются с подъёмом на фокус; внутренние связи ветки и полностью внешние
  отброшены. [тест: backend/tests/test_context.py]
- **X3.** Проекция — СЕРВЕРНАЯ: в отдаваемых рёбрах внутренний конец уже
  заменён id фокуса, направление сохранено; реальные концы — в полях
  original_*; геометрия сознательно не отдаётся (раскладка звезды эфемерна).
  [тест: backend/tests/test_context.py]
- **X4.** Состав ответа: focus (полный NodeResponse с досчитанными
  child_count/has_children), focus_ancestors (цепочка корень → родитель — для
  рамок предков), neighbors (GhostNodeResponse), edges. Пустой лист без
  связей → пустые массивы, focus отдаётся. [тест: backend/tests/test_context.py]
- **X5.** Соседи приходят БЕЗ has_children/child_count (дефолты False/0 — в
  отличие от реестра уровня): сосед-контейнер в данных неотличим от листа,
  бейджей детей и входа у соседей нет ИЗ-ЗА ДАННЫХ, а не правила рендера.
  [код]
- **X6.** Мультирёбра к одному соседу → несколько рёбер, один сосед; соседи
  отсортированы по str(uuid) (детерминизм), рёбра — в порядке выборки БЕЗ
  сортировки. [код]

## 2. Открытие и закрытие

- **X7.** Единственная точка входа — клик по строке-ЛИСТУ в дереве узлов
  (промежуточный сервис с детьми кликом проваливается на уровень, не в
  контекст). Контекст открывается для сервиса-листа, БД, брокера; недоступен
  для персон (скрыты в дереве), гостей и с холста. Обе роли. [код]
- **X8.** Модалка — нативный dialog в top-layer: ширина min(1100px, 94vw),
  холст 74vh; закрытие — Esc, крестик и КЛИК МИМО (единственная модалка
  проекта с closeOnBackdrop); программно закрывается при любой навигации по
  уровням. [код]
- **X9.** Заголовок — имя узла из пропа дерева; при 0 соседей — подсказка
  «нет внешних связей», схема с одним фокусом всё равно рендерится; состояния
  «Загрузка…» и текст ошибки. [глаза]

## 3. Состав сцены

- **X10.** Фокус — обычный блок с цветом по своей реальной глубине; соседи —
  через ту же проекцию гостей, что на уровне (guest.md §2): лист-гость или
  свёрнутый контейнер-коробка, несколько соседей под одним предком
  схлопываются в одну коробку; мультирёбра сливаются в мастеров (E2).
  [тест: levelGraph.test.ts (projectGhosts)]
- **X11.** Рамки — ТОЛЬКО нативные рамки предков фокуса (bbox фокуса +
  соседей-членов); compound-рамки в контексте не строятся; фокус в корне —
  рамок нет. [код]
- **X12.** Раскрытие контейнера-соседа РАЗРЕШЕНО: эфемерно (персист гейтится),
  БЕЗ сетевых запросов (дети — из реестра соседей проекцией), показываются
  только связанные дети; двухфазная раскладка «на месте» (E70). Анимируется
  тем же оркестратором, что на уровне. [тест: levelGraph.test.ts (двухфазность);
  эфемерность — pipeline.test.ts (интентов нет)]
- **X13.** Свернуть раскрытого соседа НЕЛЬЗЯ: рамки с плашкой «🔍 ✕» в
  контексте не существует — раскрытие необратимо до закрытия модалки. [код]
- **X14.** Фокус не раскрывается и никуда не ведёт (лупа и «Войти» скрыты);
  его бейдж child_count и зона входа остаются видимыми, но неактивны
  (подсказка-лунка не показывается — протягивания в контексте нет). [код]
- **X15.** При наличии обходов-loop сцена расширяется двумя невидимыми
  распорками (1×1) для честного fitView: PAD 130 по X от кромки обхода,
  ±20 по Y. [код]
- **X16.** Вьюпорт: fitView {padding 0.2, maxZoom 0.85}, зум-лимиты RF
  (0.5–2), фон-точки и штатные Controls — как на уровне (canvas.md §1–2), пан
  ЛЕВОЙ кнопкой (рамки выделения нет). [код]

## 4. Read-only: что выключено в контексте

- **X17.** Запись состояния: полный запрет — view_layout не читается
  (ownedPositions игнорируются — звезда в чужой системе координат) и не
  пишется (позиции, expanded, own-on-expand); undo-история не пишется
  (клавиши и кнопки скрыты); интенты засева пусты по построению.
  [тест: pipeline.test.ts (позиции есть, autoRoutes undefined, интенты пусты)]
- **X18.** Редактирование: драг узлов выключен (плюс страховка в persistGroup);
  связи не создаются (хэндлы не стартуют, быстрой связи нет, плитки «вне
  уровня» нет); дроп шаблонов и Delete/Backspace выключены; двойные клики
  немые (ни детализации, ни инспектора гостя); плашка связи некликабельна;
  плейсхолдера «•••» нет. [код]
- **X19.** Отображение: фильтр «Вид схемы» не применяется (E71); реестр
  мостиков выключен; индиго-подсветки панели и locate недоступны (пропы не
  передаются); плашки капятся CTX_LABEL_W = 190; данные полок/обходов кладутся
  в рёбра только здесь. [код]
- **X20.** Конвейер в контексте: замена раскрытого локала детьми (R5)
  выключена — фокус остаётся целым узлом; подъём концов не выполняется
  (сервер уже спроецировал); раскладка — звезда layoutContext вместо ELK;
  кольца, keep-out, разъезды, A10, роутер, нуджинг, размещение плашек и T4
  пропущены целиком. [тест: pipeline.test.ts (частично); остальное — код]

## 5. Навигация

- **X21.** Навигации из контекста НЕТ: клик по соседу — только выделение,
  двойной клик — no-op, «Войти»/drill скрыты; модалка тупиковая — единственное
  действие внутри — эфемерное раскрытие соседа (X12), выход — закрытие. [код]

## 6. Раскладка звезды (сверх E67–E70)

- **X22.** Вертикальный шаг колонки `ROW = NODE_H + 60 = 160`; базовый зазор
  60. [тест: levelGraph.test.ts]
- **X23.** Отступ колонок от фокуса: `sideGap = max(CTX_LABEL_W + 60 = 250,
  клиренс рамок предков)`, где клиренс = вылет приватных рамок фокуса
  (BOUNDARY_PAD 30 + ступени BOUNDARY_STEP 34) + запас 48 — колонка
  гарантированно за рамками, не делимыми с соседом. [код]
- **X24.** Порядок в колонке: группы по глубине общего предка (глубже — ближе
  к центру, C32); при нечётном числе групп первая центрируется на горизонтали
  фокуса, остальные попеременно вниз/вверх на менее заполненную сторону;
  внутри группы — порядок сервера (str(uuid), не по имени). [код;
  двухфазность — тест: levelGraph.test.ts]
- **X25.** Длина полки считается от моноширинной оценки плашки
  `min(190, 6.3·len + 16)`; безымянная связь оценивается словом «связь»
  (E48/E69). [код]
- **X26.** 0 соседей — фокус в (0, −h/2) без NaN; сосед без ребра к фокусу —
  в правую колонку; лимитов числа соседей нет (ни кэпа, ни пагинации).
  [тест: levelGraph.test.ts (фокус/NaN); остальное — код]
- **X27.** Высота фокуса в раскладке — константа NODE_H = 100: DOM-замеры в
  звезде не участвуют (в отличие от уровня). [код]

## 7. Данные и свежесть

- **X28.** Ровно один GET на открытие (гонки гасятся снятием флага и сверкой
  id); перезапросов НЕТ никогда: правки из контекста невозможны, внешние
  изменения БД при открытой модалке не подтягиваются — staleness до
  переоткрытия. [код]

## Известные ограничения (зафиксированы, не баги)

- Мёртвый путь «детали связи» в NodeContextModal (EdgeDetailModal/
  EdgeChoiceModal, поля original_* контракта): недостижим — плашки
  некликабельны, двойной клик гейтится. Кандидат на чистку (tasks.md).
- Рамка раскрытого соседа не рисуется (с R4.1 гостевые рамки — compound-узлы,
  которые контекст не строит), хотя место под неё раскладка резервирует;
  раскрытие при этом необратимо (X13).
- «Замок» штатных RF Controls в контексте не заблокирован: кнопка может
  включить перетаскивание read-only узлов (персиста всё равно нет — гейты
  стоят). Не проверялось визуально.
- Соседи без has_children (X5) — асимметрия контракта с реестром уровня; при
  доработке бэка бейджи «включатся сами».
- Рёбра ответа без сортировки — детерминирован только порядок соседей.
- HTTP-слой эндпоинта (404/auth/изоляция) и вся модалка тестами не покрыты;
  бэкенд-тесты зовут функцию напрямую.
