# Гость — спецификация поведения

Нормативный реестр инвариантов гостя — проекции чужой ветки дерева на текущем
уровне: не-локальный конец связи, материализованный узлом. Спека — ЕДИНЫЙ ДОМ
гостевого поведения: сюда перенесены N13–N15 ([node.md](node.md)) и C21–C24
([container.md](container.md)) — на старых местах оставлены указатели.
Формат — [README.md](README.md).

Терминология (общая с container.md): **гость-лист** — атомарная проекция
узлом; **гостевой контейнер** — свёрнутый предок гостя (пунктирная коробка);
**гостевая рамка** — раскрытый гостевой контейнер. Смежное: тело и палитра
узла — node.md; раскрытия, рамки, keep-out рамок — container.md; рёбра гостя —
edge.md E13; персист позиций — [view.md](view.md).

Код: бэк `app/routers/nodes.py` (_build_graph, реестр endpoints), `app/tree.py`;
фронт `graph/layout/{projectGhosts,ringPlacement,keepGhostsOut,separateGuests}.ts`,
`graph/projection.ts`, `graph/nodes.tsx` (GhostBlockNode/ContainerNode),
`graph/assembleRf.ts`, `inspector/GhostInspector.tsx`.

## 1. Реестр endpoints (бэкенд)

- **G1.** Реестр endpoints строится для КАЖДОГО конца ребра уровня, не
  входящего в множество локалов: внешние гости, глубокие концы внутри
  поддерева, сам контейнер уровня и его предки. Ребро уровня = хотя бы один
  конец в поддереве контейнера. Отдаётся вместе с графом уровня (view.md V13).
  [тест: backend/tests/test_build_graph.py]
- **G2.** Запись реестра: id, name, role, technology, is_external, shape,
  status (дефолт existing), node_depth, has_children, child_count, ancestors
  (цепочка «корень → непосредственный родитель», порядок нормативен — держит
  breadcrumb; каждый предок несёт своё is_external), is_ghost. [код;
  ancestors — тест: backend/tests/test_build_graph.py, test_tree.py]
- **G3.** node_depth — шаги parent_id до корня (корень = 0); has_children /
  child_count — прямые дети по всему проекту; endpoints отсортированы по
  str(id) — ответ детерминирован. [тест: backend/tests/test_tree.py;
  сортировка — код]
- **G4.** Строки позиций «не показанных сейчас» проекций живут в БД намеренно
  и воскресают при возврате проекции; чтение графа их не чистит (view.md V4).
  [тест: backend/tests/test_build_graph.py]

## 2. Проекция на холст

- **G5** *(бывш. C21)*. Гость сворачивается к ПЕРВОМУ НЕраскрытому
  контейнеру-предку ниже общего предка (без общего предка — от корня); лист
  виден, только если предков нет или все раскрыты.
  [тест: levelGraph.test.ts (projectGhosts), pipeline.test.ts]
- **G6** *(переписан 2026-08-16 по факту эпика «связи, упирающиеся в рамку»)*.
  Конец-«предок текущего уровня» материализуется гостем-ЛИСТОМ самого предка
  (предков ниже общего у него нет). Конец «сам контейнер уровня» НЕ дропается:
  он остаётся концом и упирается наконечником в рамку уровня — конвейер всегда
  кладёт контейнер уровня в множество рамок-концов (container.md C19b,
  edge.md E6). Дропается только конец в контейнер, у которого рамки на этом
  уровне нет (свёрнутый локал). Прежняя редакция утверждала обратное и
  разошлась с кодом: правым оказался код.
  [тест: projection.test.ts «конец-рамка остаётся концом» / «без раскрытия
  дропается», pipeline.test.ts «собственная связь контейнера уровня видна
  изнутри»]
- **G7.** Дубль «узел+рамка» не материализуется, гость, раскрытый «вхолостую»,
  остаётся узлом — container.md C13. Раскрытый гость показывает ТОЛЬКО
  связанных детей (C4-контекст) — дети из реестра, кэш локальных детей для
  гостей не читается. [тест: pipeline.test.ts]

## 3. Визуал

- **G8** *(бывш. N13)*. Гость рисуется той же формой с ПУНКТИРНЫМ контуром
  "5 3"; несёт только имя/роль/технологию/статус/глубину/путь предков — без
  description, доков и правок (read-only). [код]
- **G9** *(бывш. N14)*. Кнопка «Войти к компонентам» — только в редакторе
  (drill-навигация) и только при has_children (у атомарного листа-гостя кнопки
  нет; на странице объекта кнопки «Войти» нет вовсе); бейдж child_count — при
  has_children; путь при входе строится ЗАНОВО (предки + узел), не аппендом к
  breadcrumb. [код]
- **G10.** Палитра гостя-листа — по СВОЕМУ node_depth и СВОЕМУ статусу
  (node.md N7–N10); гостевой КОНТЕЙНЕР красится по is_external и глубине
  ПРЕДКА в цепочке ancestors и статуса не несёт (в статус связи вносит
  existing). [код]
- **G11.** Свёрнутый гостевой контейнер — пунктирная коробка 190×100 с
  подписью «контейнер», всегда зона входа — container.md C1. [ссылка]
- **G12.** Фильтр «Вид схемы»: гость-лист приглушается по своему статусу
  (node.md N11); гостевой контейнер-коробка НЕ приглушается никогда; связь
  приглушена, если приглушён любой отображаемый конец; легенда статусов и
  условие показа панели фильтра считают гостей уровня (глубокие концы реестра,
  невидимые на холсте, — нет). [код]
- **G13.** Статус связи учитывает статус гостя-листа наравне с локалами
  (сильнейший из концов, edge.md E4). [код]

## 4. Размещение: кольца и keep-out

- **G14** *(бывш. C22 + N15)*. C4-инвариант: гость (и гостевая рамка) НИКОГДА
  не лежит внутри чужой родной рамки. Запретная рамка ровно одна — следующая
  глубже общего предка (концентричность); выталкивание — минимальный сдвиг к
  границе рамки, раздутой на `KEEPOUT_GAP = 28` (ровно к границе буфера);
  задвинуть гостя внутрь руками нельзя (живой кламп, node.md N22); автосдвиг
  не персистится, драг персистит уже скорректированную позицию.
  [тест: keepGhostsOut.test.ts]
- **G15** *(бывш. C23)*. Дефолт авто-гостя — boundary labeling на «кольце»:
  периметр запретной рамки + 28 (keep-out выполняется ПО ПОСТРОЕНИЮ, страховка
  обязана быть no-op). Сторона — по якорю (средний центр связанных локалов) и
  направлению потока (источник → левый край, приёмник → правый), споры —
  минимум пересечений тел пробным маршрутом; вдоль стороны — изотоническая
  раздвижка (PAV) вокруг центра масс с зазором 28; кольца разной глубины —
  изнутри наружу. Ручной (владеемый) гость кольцом не трогается.
  [тест: ringPlacement.test.ts]
- **G16** *(бывш. C24)*. Гостевая рамка садится на кольцо своим НАРИСОВАННЫМ
  rect (с паддингами), не голым bbox узлов; её группа жёсткая — двигается
  целиком. [тест: ringPlacement.test.ts, keepGhostsOut.test.ts]
- **G17.** Полка детей раскрытой гостевой рамки — container.md C10; keep-out
  раскрытых рамок, веса разъезда и цикл инвариантов — C25–C27; членство гостя
  в нативных/гостевых рамках — C16. [ссылка]
- **G18.** Own-on-first-render гостя: кольцевые позиции засеваются интентами
  конвейера НА ФИНАЛЬНЫХ позициях прогона; дальше гость владеет позицией как
  локал (node.md N19, view.md V22). Позиция персистится строкой view_layout
  ТЕКУЩЕГО уровня единым батчем с локалами.
  [тест: ringPlacement.test.ts, pipeline.test.ts, backend/tests/test_view_layout.py]

## 5. Интерактив

- **G19.** Двойной клик по гостю-ЛИСТУ → read-only GhostInspector: заголовок
  «Объект/Внешний объект · проекция» (по is_external), глиф формы, имя, роль,
  технология, «Расположение» = имена предков через « / », статус; node_depth
  и child_count не показываются. Двойной клик по гостевому КОНТЕЙНЕРУ —
  ничего. [код]
- **G20.** «Перейти к источнику»: непустые ancestors → drillToPath на уровень
  НЕПОСРЕДСТВЕННОГО родителя гостя (breadcrumb = вся цепочка предков); пустые
  (источник — корневой узел) → корневой уровень. [код]
- **G21.** Гость, открытый в панели, даёт устойчивую индиго-подсветку как
  узел (canvas.md CV16). [глаза]
- **G22.** Драг: гость — полноправный участник снапа и клампов (node.md
  N21–N24; кламп нативных рамок действует и в мультидраге); живой драг
  ре-роутит гостевые/сквозные рёбра настоящим роутером наравне с локальными,
  фолбэк без живого маршрута гостевые рёбра НЕ трогает (edge.md E58–E63).
  [тест: useLiveDragHandles.test.ts]
- **G23.** Delete/Backspace гостей не собирает (только локальные блоки,
  canvas.md CV29); правки полей гостя не существует нигде — PATCH-путей для
  проекции нет, description/доков нет в самом контракте (G2). [код]

## 6. Связи гостя

- **G24.** Хэндлы гостя и гостевого контейнера активны на СТАРТ связи
  (архитектор, вне контекста); гость — валидная цель быстрой связи (кандидаты
  — все узлы, кроме рамок/распорок/источника). [код]
- **G25.** Протягивание связи В гостя: гость-ЛИСТ принимает ПРЯМУЮ связь
  всегда (даже при has_children — лист не «зона входа»: подсказки-лунки нет);
  гостевой КОНТЕЙНЕР — зона входа: дроп по телу открывает пикер потомков
  контейнера (связь станет сквозной), дроп точно на хэндл — прямая связь в
  сам контейнер (хэндл выигрывает у зоны входа, edge.md E73). [код]
- **G26.** Пикер «объект вне уровня» исключает из выбора уже видимых на
  уровне: локалов, гостей и сам источник. [код]
- **G27.** Имена концов для модалок связи резолвятся из реестра endpoints
  (фолбэк — по локалам). [код]

## 7. Создание узлов в гостевой рамке

- **G28.** Дроп шаблона в раскрытую ГОСТЕВУЮ рамку разрешён (решение
  2026-07-13): parent_id создаваемого узла = контейнер рамки (узел чужой
  ветки); позиция пишется в вид ТЕКУЩЕГО уровня отдельной записью после
  создания (в POST позиция не передаётся — ушла бы в чужой вид). [код]
- **G29.** Созданный так узел на ТЕКУЩЕМ холсте не появляется, пока не станет
  концом ребра, касающегося уровня (дети гостевой рамки — только проекции
  реестра, G7); в дереве узлов он виден сразу, а засеянная позиция «ждёт»
  появления проекции (G4). [код]

## Известные ограничения (зафиксированы, не баги)

- Прямая связь в гостя-листа с has_children (G25) легальна и тоже рождает
  алерт-кейс: лист не зона входа by design.
- Рефреш кэша детей после создания узла в гостевой рамке перечитывает кэш,
  который для не-локального контейнера конвейер не читает — безвредный
  холостой вызов.
