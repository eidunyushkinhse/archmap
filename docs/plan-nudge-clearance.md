# План: клиренс канальной разводки — плечи не прижимаются к узлам

Статус: АНАЛИЗ ГОТОВ (2026-07-15), реализация не начата — ждёт команды.

## Жалоба (репро)

Дефолтная раскладка, раскрыт узел «Маркетплейс „Ярмарка"»: стрелка «Инициация
оплаты» (API Gateway → Payment API, d8d57a99) одним плечом лежит вплотную к
нижней грани узла «Сервис пользователей».

Замер (детектор hug_scan по живой БД): плечо y=234, пробег 190px, на 1.3px
ВНУТРИ тела узла (низ 235.3) — визуально линия лежит на грани.

## Диагноз

**Виновная доработка: d514d9b (2026-07-13, эпик «читаемые пучки» T2 —
near-кластеризация каналов в nudgeChannels).** Бисект по истории на
фиксированной сцене (scene.json, dump_gate):

| коммит  | что менял                        | прижатие d8d57a99      |
|---------|----------------------------------|------------------------|
| 3295f3e | shared-path penalty              | нет                    |
| e8fafca | T1 слоты в A* + спрямление джогов| 0.0px НА грани (top)   |
| 72af856 | фикс: JOG_CLEAR в спрямлении     | нет (вылечено)         |
| d514d9b | T2 канальная разводка near       | ВНУТРИ тела (bottom)   |
| …HEAD   |                                  | без изменений          |

Тот же класс бага уже чинился в 72af856 для спрямления джогов; следующий же
коммит внёс новый механизм сдвига линий (канальный нуджинг) без аналогичной
защиты. Причинность подтверждена: HEAD с выключенным nudgeChannels — прижатий 0,
плечо возвращается на клиренс-линию y=250.

**Механика (по трейсу канала):** горизонтальный канал из трёх групп в коридоре
235.3..262 (просвет 26.7px между «Сервисом пользователей» и узлом ниже):

- наше плечо, ось 250 (движимое);
- чужое плечо 78ea1c1e, ось 262 (движимое);
- 20px-хвост НАШЕГО ЖЕ ребра у дока, ось 262 (концевой → fixed, пинит шкалу).

До T2 в канал попадали только точные наложения: {78ea@262 + хвост@262} → 78ea
уезжал на 248, наша линия оставалась на 250 → «плетёнка» 248/250 в 2px — ровно
то, что T2 лечил. T2 склеил все три группы (union-find транзитивен), пин хвоста
дал shift=−8, жёсткая шкала «center + j·GAP» → таргеты [234, 248, 262]. Наша
линия командирована на 234 — в тело узла.

**Слепые зоны, позволившие это:**
1. Единственная защита сдвига (canApply → cutsBody) — «не глубже 2px в тело».
   Клиренса от узлов у нуджинга НЕТ ВООБЩЕ: роутер держит 12 (margin),
   спрямление джогов 8 (JOG_CLEAR), нуджинг — 0. Ось 234 при нижней грани
   235.33 проходит порог 233.33 «в слепой зоне».
2. Жёсткая шкала равных GAP не умеет сжиматься в тесном коридоре; лесенка
   двигает всю шкалу кратно GAP/2 и бессильна при пине.
3. Транзитивная склейка near-канала затягивает короткие концевые хвосты у
   доков — их пришпиленность диктует шкалу всему коридору.

**Вне скоупа:** HelixMon, 2 плеча в 2px от грани ObsCore — НЕ регрессия:
узлы стоят в 12px (NODE_SEP_PAD), рёбра между смежными гранями вынужденно
живут в щели (ступенчатый сброс margin роутера — задокументированное
поведение тесноты). Без нуджинга картина та же.

## План

**Ф1 — жёсткая гарантия (ядро, маленькая):** клиренс узлов в canApply.
NUDGE_CLEAR = 8 (= JOG_CLEAR, консистентно). Целевая ось ближе 8px к грани
узла при существенном совместном пробеге → вето сдвига (формула cutsBody с
прямоугольником, раздутым на NUDGE_CLEAR). Покрывает ВСЕ пути применения:
дефолтная шкала, лесенка, многопиновый VPSC, по-сегментный фолбэк. Вето — о
ЦЕЛИ сдвига: уже-прижатые роутером в вынужденной тесноте (HelixMon) не
трогаем и не ломаем.

**Ф2 — умное распределение (качество):** цели канала через VPSC для всех
каналов (обобщение существующей многопиновой ветки solveSeparation):
- переменные — оси групп; fixed-группы — пины (вес ∞);
- СТЕНКИ КОРИДОРА: клиренс-границы узлов (грань ± NUDGE_CLEAR), пересекающих
  пробег КОНКРЕТНОЙ группы (не всего канала — иначе лишние отказы), —
  псевдопины по краям;
- соседние группы ≥ gap; невыполнимость (пины/стенки сдвинуты с осей) →
  деградация gap 14→12→10→8; всё невыполнимо → канал не разводим (как ныне
  pinsConflict), Ф1-вето всё равно страхует.

На сцене «Ярмарки» даёт ~245 / ~253.3 / 262: клиренс 8 от обоих узлов, зазоры
~8 — читаемо, без плетёнки и без тела. Ветки «дефолт-шкала» и «лесенка»
схлопываются в VPSC-путь (они его частные случаи) — модуль упрощается.

Порядок: Ф1 → гейты → Ф2 → гейты. Лучше одним заходом (см. риск 1).

## Риски

1. **Ф1 без Ф2 возвращает плетёнку**: на сцене «Ярмарки» вето отменит сдвиг
   на 234, канал останется полуразведённым (248/250 в 2px) — цель T2 частично
   регрессирует до прихода Ф2. Потому фазы одним заходом.
2. **Сдвиг эталонов повсеместно**: любые схемы с каналами у узлов изменят
   маршруты → пересъём канона (сцены A/B), гейты: hug-детектор 0 невынужденных
   по всем проектам, скан нелегальных слияний 0, глазная проверка.
3. **Деградация gap до 8 сближает дуги мостиков** (JUMP_RADIUS=6: при gap<12
   дуги соседних плеч без просвета). Редкий кейс тесного коридора; альтернатива
   (нижняя граница 12) не решает «Ярмарку» (в полосе 243.3..254 два слота с
   gap 12 не помещаются). Принимаем 8, фиксируем комментом.
4. **Стенки по пробегу группы, не канала** — узел, перекрывающий чужой пробег,
   не должен сжимать чужую группу; ошибка охвата = лишние отказы разводки.
5. **Диff Ф2 заметный** (перелопачивает три ветки применения в одну); юниты
   каналов пересмотреть; смягчение — суммарная сложность модуля ПАДАЕТ.
6. **live==final**: нуджинг в живом драге — тот же код и входы, VPSC
   детерминирован → инвариант держится.
7. **Хвост-пин остаётся диктатором** (пришпиленность физична — конец в доке).
   Пин вне коридора стенок → канал целиком не разводится (Ф1 спасает от тела;
   короткое наложение у дока терпим). Опция НА ПОТОМ, если будет мешать:
   пин-группу из короткого концевого хвоста (<1.5×stub) исключать из шкалы.
