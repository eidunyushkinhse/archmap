devservices, autotools); процесс без манифеста; не процесс.

## 7. Что это значит для фазы 3 (решения владельца)

Ранжировано по цене и выигрышу на этих четырёх репозиториях:

1. **Шум параметров** (раздел 5): перечень служебных каталогов и файлов для разборщиков
   кода и словарь переменных ОС. Малая правка в `scan/`, поднимает точность параметров с
   55 % к 90 % и выше по выборке. Можно сделать до фазы 3 отдельной мини-фазой.
2. **Реестры каналов** (раздел 3): перечисление строк и словарь имён топиков в модуле,
   который импортируют вызовы клиента (Sentry 40 из 40), и декоратор потребителя с именем
   очереди (Zulip 14 из 15; `@assign_queue` конкретен, общий случай: декоратор проекта,
   первый аргумент которого строка, а модуль подключает клиент брокера). Это и есть путь к
   ориентиру «≥ 80 %» ТЗ.
3. **Манифесты не по имени, а по содержимому**: файл YAML с разделом `services:` и ключами
   `image`/`build` у сервисов читать как compose (Sentry `devservices/config.yml`: +7
   контейнеров), а `repo_link`/`repo_name` в нём давать подсказкой «сервис из другого
   репозитория» (+9 заглушек для агента). Puppet (Zulip: RabbitMQ, Redis, memcached,
   Smokescreen, go-camo) оставить в «не покрыто» с именем стека.
4. **Процессы по соглашениям кода без манифестов**: `cmd/<имя>/main.go` и `src/go/cmd/<имя>/`
   (Zabbix web service, Grafana `pkg/cmd/*`), `bin_PROGRAMS`/`sbin_PROGRAMS` autotools (Zabbix
   server, proxy, agent, get, sender), `build.xml` Java. Для Zabbix это 7 из 10 детей
   эталона; иначе репозиторий остаётся пустым.
5. **Дубли одного процесса из двух манифестов одного корня** (Grafana `grafana` и
   `grafana-server`; Zulip supervisor и Dockerfile): склейка по общему каталогу кода, когда
   команда одного указывает на бинарь другого. Освободит 426 маршрутов Grafana.
6. **Лишние объекты от хостинга и упаковки** (Zulip `zulip_ops`, Grafana `packaging/`): не
   трогать, это факты манифестов; агент или человек уберут при импорте.

Агентский шаг промпта (ТЗ, фаза 3) имеет смысл после пунктов 1 и 2: сейчас сводка честно
говорит «каналов нет», и агенту пришлось бы искать их заново.

## 9. Оракулы: полнота сборщика против независимой истины (2026-11-04)

Вопрос владельца: сборщик писала модель, откуда известно, что он не слеп к краевым случаям,
и как судья (та же модель) не спишет ошибку оракула на сборщик. Ответ: полноту внутри
«покрытой» семьи сборщик не гарантирует, её можно только измерить против истины, которая от
модели не зависит; а судью связывает протокол, записанный до прогона.

### 9.1 Протокол судьи

Оракулы лежат вне продукта: `~/archmap-etalons-2026-08-19/oracles/` (`common.py`,
`openapi_routes.py`, `net.py`), сырые выводы рядом в `out-*.txt`; каждая цифра ниже
воспроизводится командой из шапки скрипта. Сравнение делает скрипт, не человек: он печатает
три множества (совпало, только у оракула, только у сборщика). Судья участвует только в
объяснении «только у оракула», и каждое объяснение идёт в одно из вёдер с МЕХАНИЧЕСКИМ
критерием: «нет в коде» (литерал пути не встречается ни в одном файле кода бэкенда, не
считая генератов), «только в исключённых файлах» (все вхождения под исключениями из
`coverage.yaml`), «пропущено по правилу ТЗ» (файл в каталоге кода разработки §4 или
служебном §13.1, файл тестов по имени), «есть у сборщика без префикса» (путь документа
кончается путём сборщика). Всё остальное по умолчанию ПРОМАХ сборщика: бремя доказательства
на сборщике, а не на оракуле. Оракул обязан быть проще проверяемого и падать громко: пустое
пересечение это ошибка клея, а не вывод. Выборки печатаются с семенем, строки с
«файл:строка», так что второй читатель проверяет вёдра, не доверяя судье.

### 9.2 Внешняя истина: OpenAPI, который ведут авторы репозитория

Путь документа считается найденным, если сборщик знает его с одним из базовых префиксов из
`servers` документа (Zulip: `/api/v1` и `/json`, Grafana: `/api`). Корень без префикса
кандидатом не считается: он прячет ровно потерянный префикс (на Grafana такой прогон
«находил» `/folders` и скрывал девять хвостов). «Хвост» засчитывается, только если в нём есть
статический сегмент и сборщик сам пометил путь `prefix_unresolved`; иначе это совпадение имён
(`/{}` хвост любого пути), и путь идёт в промахи. Команда прогона печатается первой строкой
вывода (уточнение правил 2026-11-04 вечером, до запуска фазы 3б; прежние выводы рядом как
`*.v1.txt`).

| репозиторий | в документе | у сборщика | совпало | промах | хвост без префикса | нет в коде | исключено |
|---|---|---|---|---|---|---|---|
| Zulip (`zerver/openapi/zulip.yaml`) | 117 | 216 | 5 | 109 | 1 | 0 | 2 |
| Grafana (`public/openapi3.json`) | 206 | 346 | 124 | 39 | 13 | 28 | 2 |

**Zulip: слепое пятно подтверждено.** Zulip регистрирует API своей обёрткой
`rest_path(route, GET=…, POST=…)` (`zerver/lib/rest.py:220`, внутри обычный `path`): 134
вызова, 96 разных путей в `zproject/urls.py`, подключённых дважды (`api/v1/` и `json/`).
Разборщик Django знает только `path`, `re_path`, `url` и `include`, обёртку репозитория не
видит, поэтому почти весь публичный API Zulip в выводе отсутствует, хотя семья «покрыта» 220
маршрутами. Это ровно класс «корпоративная обёртка», которого стоило бояться.

**Grafana: три дефекта поменьше.**
1. Путь в обёртке. Генераты регистрации `pkg/services/ngalert/api/generated_base_api_*.go`
   пишут `group.Delete(toMacaronPath("/api/v1/provisioning/alert-rules/{UID}"), …)`.
   Разборщик Go файл читает, но путь не строкой уходит в подсказку «путь задан выражением»
   (105 подсказок с `toMacaronPath` в `hints.yaml`); 23 промаха из 39 именно оттуда. Литерал
   стоит в той же строке, основание у записи есть.
2. Префикс группы в другом файле. `apiRoute.Group("/folders", …)` в `pkg/api/folder.go`
   получает `apiRoute` параметром функции `registerFolderAPI`, а её вызов стоит внутри
   `r.Group("/api", …)` в `pkg/api/api.go`. 12 из 13 хвостов: `folders`, `playlists`, пути прав
   доступа в `accesscontrol/resourcepermissions/api.go`. Тринадцатый (`/user/email/update`)
   в коде стоит у корня, это артефакт документа.
3. Флаг `prefix_unresolved` стоит у 393 из 426 маршрутов, хотя пути в основном полные: корень
   `hs.RouteRegister` это поле структуры, а не вызов `New…()` в том же файле. Флаг честный
   (статически корень не виден), но агенту почти бесполезен; решение отложено.

Остальные 16 промахов: одиночные файлы, где литерал документа совпал с другой строкой
(`/health` в `pkg/server/ring.go`, `/reports` в `pkg/middleware/middleware.go`); человек отнёс
бы их к артефактам, по протоколу они остаются промахами. 28 путей документа в коде
отсутствуют: Enterprise, оракул их отделил сам.

**Sentry каналы: реестр покрыт целиком.** Перечисление `Topic` в
`src/sentry/conf/types/kafka_definition.py` содержит 52 имени, сборщик записал 52, множества
равны. Для каналов это единственная истина, которая не зависит от модели.

### 9.3 Грубая сетка (верхняя граница, не вердикт)

Сетка хватает любые литералы рядом со словами семьи и шумит; «открытые» ниже это кандидаты,
не промахи.

| репозиторий | параметры: сетка / знает / открытых | маршруты: сетка / знает / открытых | каналы: сетка / знает / открытых |
|---|---|---|---|
| Zulip | 27 / 23 / 0 | 815 / 180 / 395 | 438 / 14 / 133 |
| Sentry | 169 / 154 / 0 | 1041 / 416 / 157 | 121 / 10 / 43 |
| Grafana | 81 / 58 / 0 | 2461 / 791 / 492 | 83 / 1 / 28 |
| Zabbix | 6 / 0 / 0 | 161 / 1 / 61 | 7 / 0 / 3 |

Параметры: после механической классификации (исключённые файлы, код разработки, служебные
каталоги, файлы тестов, запись вместо чтения, `setdefault`) открытых кандидатов нет ни в
одном репозитории. Маршруты: открытые кандидаты у Zulip это те же `rest_path`, у Sentry и
Grafana в выборке клиентские адреса чужих API, прокси и фронтовые вызовы, то есть шум сетки.
Каналы: сетка тонет в словах предметной области (у Zulip `stream` и `topic` это сущности
чата, у Sentry имена метрик и задач); вердикта по ней нет, полнота каналов держится на
реестрах.

### 9.4 Что это меняет

1. Семантика статуса «покрыто» сильнее, чем он значит: разборщик отработал, а не нашёл всё.
   Кандидат на текст сводки (решение владельца): «покрыто» → «разобрано», полнота не
   обещается.
2. Фаза 3б сборщика (ТЗ §15): обёртки регистрации маршрутов Django в том же репозитории
   (функция, возвращающая `path`/`re_path`, с первым параметром-маршрутом и методами в
   именованных аргументах); путь в обёртке у Go на известном объекте маршрутизации; префикс
   группы через параметр функции регистрации в том же пакете Go. Проверка той же командой
   оракула: Zulip ≥ 100 совпадений из 117, Grafana промахов ≤ 16 и хвостов ≤ 1.
3. Оракулы входят в замер: эталон получает третий слой «пропуски сборщика» (найдено
   оракулом или скептиком, в коде есть), и доля ядра среди найденного в коде становится
   измеренной полнотой сборщика.
