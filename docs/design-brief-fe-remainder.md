# Бриф для Claude Design — «остаток слияния» в превью импорта (Ф-E)

Готовый промпт для Claude Design: собрать кликабельный прототип того, как в превью
импорта ArchMap пользователь разбирает остаток слияния четырьмя жестами. Контекст
решений — docs/plan-byoa-quality.md, раздел «Ф-E», решения 2026-09-18. Ниже — текст
промпта целиком, копировать от строки «---» до конца файла.

---

Ты проектируешь интерфейс для ArchMap — веб-сервиса многослойных архитектурных
диаграмм (C4: объекты-контейнеры и их компоненты, связи между ними; поверх — схемы
логики, спеки API, таблицы БД, каналы брокеров, параметры конфигурации). Знание о
системе приезжает импортом: несколько YAML-файлов (по одному от ИИ-агента на каждый
репозиторий) и zip-архивы, которые сливаются в один проект. Нужен прототип одной
механики: **разбор остатка слияния прямо в превью импорта**, до того как проект
создан.

## Экран, который ты расширяешь (существует, менять его каркас нельзя)

Окно «Создание проекта» шириной 904 px. Слева колонка 326 px: способы старта
(Пустой / Копия / Импорт / ИИ-агент), поля «Название» и «Описание». Справа — панель
ввоза, сверху вниз:

1. Полоса чипов-входов: `1 · zabbix.yaml`, `2 · grafana.yaml`, `zip 3 · plugin.zip`,
   чип «+», кнопка «Загрузить файлы…». Чипы — пилюли, активный подсвечен синим.
2. Тело активного входа: textarea с YAML либо карточка архива.
3. Живая сводка (dry-run, пересчитывается при каждом изменении входов):
   - зелёная строка `Готово к импорту: 158 объектов · 271 связь · из 3 файлов`;
   - серые строки `Корневые: Zabbix, Grafana, Плагин Zabbix для Grafana`,
     `Склеено узлов: 3` с основаниями (`Zabbix / Zabbix server — по коду`),
     `Без якоря: 41 объект — будут опознаваться по имени`;
   - `Замечания к файлу 2 · grafana.yaml:` — список строк для агента, кнопка
     «Скопировать замечания для агента»;
   - `Замечания к слитой схеме:` — список строк и серый абзац: «Эти замечания — о
     взаимном устройстве файлов, поэтому агенту одного репозитория их не починить. Их
     чинят там, где виден весь ландшафт: добавьте файлы остальных репозиториев,
     попросите нужного агента дорисовать связь или поправьте схему после импорта
     вручную»;
   - секция `Споры содержимого (2)`: карточки, в каждой заголовок
     `Схема логики · Приём метрик`, путь объекта серым, радиокнопки-кандидаты
     `2 · grafana.yaml · 41 строка, 6 вершин`, раскрывашка «Показать тело», для
     схем логики вариант «Взять все (тёзкам — номер)». Дефолт стоит всегда: если
     ничего не трогать, результат осмысленный.
4. Кнопка «Создать проект» внизу окна.

Второй экран той же механики — модалка «Импорт проекта из архива» (720 px):
догрузка архивов к живому проекту. Там список «Проверьте», те же споры с кандидатом
«Текущий проект» (полужирным), массовые кнопки «Везде оставить моё» / «Везде взять из
архивов», кнопка «Применить». Живое знание перетирается только явным выбором.

Визуальный язык: system-ui, в панели кегли 12–13.5 px; нейтрали slate (#0f172a
заголовки, #334155 текст, #64748b и #94a3b8 вторичное, #e2e8f0 границы, #f8fafc фон
карточек); акцент синий #2563eb / #1d4ed8 / фон #eff6ff; предупреждение янтарный
#b45309; успех #15803d; ошибка #dc2626. Карточки радиус 10, границы 1 px, чипы —
пилюли. Иконки — простые линейные SVG, без иконочных шрифтов. Desktop, модальное
окно, без адаптива.

## Проблема

Слияние клеит одинаковые объекты и сливает поля по правилу «богатое побеждает», но
часть вещей знать не может — это остаток. Сегодня остаток уходит строками текста в
«Замечания к слитой схеме» и в отчёт, а пользователь правит их после импорта руками
на холсте. Полевой замер: после слияния трёх реальных проектов (Zabbix, Grafana,
плагин Zabbix для Grafana) понадобилось семь правок, это 2 чтения и 9 записей через
API или полчаса кликов на холсте. Хотим, чтобы остаток решался в превью, до создания
проекта, теми же движениями, что уже есть у споров содержимого. Слова «поправьте
схему после импорта вручную» из серого абзаца должны исчезнуть.

## Четыре жеста (все — на реальных данных ниже)

**1. Перевесить конец связи с контейнера на его компонент.** Агент одного
репозитория видит соседний продукт коробкой, поэтому связь упирается в контейнер.
Сегодняшняя строка замечания: `связь «Grafana → Датасорс Zabbix (backend)»: конец в
контейнере «Grafana», у которого есть компоненты, — уточните её до конкретного
компонента: «Grafana / Сервер Grafana», «Grafana / Веб-приложение», «Grafana / БД
Grafana» и ещё 3`. Бывает и «оба конца в контейнерах». В превью известно всё слитое
дерево, так что показывать можно полный список компонентов, вложенный (компонент
может быть на третьем уровне: «Сервер Grafana / Рантайм плагинов»). «Оставить как
есть» — законный выбор и дефолт: связь в контейнер допустима, после импорта её
покажет панель незавершённости.

Пять таких связей из полевого случая:

| Связь | Что перевесить | Куда |
|---|---|---|
| Grafana → Датасорс Zabbix (backend) · gRPC | начало | Grafana / Сервер Grafana / Рантайм плагинов |
| Grafana → Датасорс Zabbix (frontend) · module.js | начало | Grafana / Веб-приложение |
| Grafana → Панель Problems · module.js | начало | Grafana / Веб-приложение |
| Датасорс Zabbix (backend) → Zabbix · HTTP JSON-RPC 2.0 | конец | Zabbix / Zabbix web-интерфейс |
| Датасорс Zabbix (frontend) → Grafana · HTTP/JSON | конец | Grafana / Сервер Grafana / HTTP API |

**2. Добавить связь, известную только при слиянии.** Факт совместного
развёртывания невидим из любого одного репозитория. Пример: `Grafana / Сервер
Grafana / Рантайм плагинов → Zabbix / БД Zabbix`, подпись «Direct DB Connection:
читает history/trends штатным SQL-датасорсом», технология SQL, канал синхронный.
Естественный крючок — замечание об изолированной группе: `группа из 12 объектов не
связана с остальной схемой: «Плагин Zabbix для Grafana», «Датасорс Zabbix
(backend)», «Датасорс Zabbix (frontend)», «Панель Problems» и ещё 8 — дорисуйте
связь с ядром или проверьте, не потерялась ли она`. Но связь пользователь может
захотеть добавить и без подсказки. Нужны: выбор начала и конца по слитому дереву,
подпись, технология, тип канала (синхронный / асинхронный). Никаких предложений
«скорее всего вы имели в виду»: связь добавляет только человек.

**3. Склеить два объекта в один с выбором имени.** Слияние никогда не клеит похожие
имена само (ложная склейка хуже дубля), только предупреждает: `«Пользователь
Zabbix» и «Пользователь» (на верхнем уровне) похожи — возможно, один объект из
разных файлов; если да, приведите имена к одному`. Жест: «это один объект» → имя
(одно из двух либо своё — в полевом случае им стало «Оператор мониторинга»),
связи обоих переносятся на него. Обратный ответ «это разные» тоже нужен, чтобы
замечание перестало мозолить глаза. «Администратор» из того же файла остаётся
отдельным — механика не должна подталкивать клеить всё подряд.

**4. Спор полей равной содержательности.** Два файла заполнили одно поле объекта
по-разному, и ни один из них не «видел объект изнутри» (не раскрыл компонентами и не
назвал его репозиторий). Сегодня побеждает первый файл, а в отчёт уходит строка
`description: оставлено «БД Zabbix: history, trends, конфигурация» (файл 1),
отброшено «База данных Zabbix, прямое подключение датасорса» (файл 2)`. Жест: тот же
радиовыбор, что у споров содержимого, дефолт — первый файл, у кандидатов подписи
происхождения (`1 · zabbix.yaml`). Примеры: объект «БД Zabbix», поля «Описание» и
«Технология» (`PostgreSQL 16` против `PostgreSQL`); объект «Zabbix web-интерфейс»,
поле «Роль» (`веб-интерфейс` против `API`). Если один файл раскрыл объект изнутри,
спора нет — его вклад побеждает молча, показывать нечего.

## Принципы (жёсткие)

- **Дефолт всегда осмысленный.** Пользователь может не тронуть ни одного остатка и
  нажать «Создать проект» — получит то же, что сегодня. Ни одного обязательного шага,
  ни одного нового режима или переключателя. Идеал продукта: «нажал — получил».
- **Никаких ключей склейки на экране.** Якоря, репозитории, хосты — внутренняя
  механика; пользователь видит имена объектов и пути «Grafana / Сервер Grafana».
  Никаких новых автоматических сопоставлений: каждый остаток закрывается явным
  действием человека или остаётся как есть.
- **Универсально.** Те же жесты уместны после импорта одного файла, после догрузки
  архива к живому проекту и после слияния десяти репозиториев. Ничего специфичного
  для «федерации».
- **Спокойный тон.** Остаток — не ошибка и не долг, а «что слияние оставило вам».
  Без тревожных цветов на каждой строке, без пульсации, без счётчиков-упрёков.
  Пользователь продукта прямо просил, чтобы предупреждения не мозолили глаза.
- **Масштаб.** Остатков может быть 40+ (слитая схема на 150 объектов, контейнер на
  полсотни компонентов). Интерфейс не должен превращаться в стену текста:
  группировка, свёртки, счётчики «решено N из M», «и ещё N».
- **Ничего не удаляется автоматически.** Все четыре жеста только добавляют или
  уточняют; «оставить как есть» доступно у каждого остатка.
- **Словарь продукта:** «объект» (не «узел»), «связь», «компонент», «контейнер»,
  «схема», «вход», «файл», «архив», «Текущий проект». Тексты по-русски.
- **Догрузка к живому проекту:** живые объекты и связи — полноправные кандидаты, живое
  знание не перетирается без явного выбора; массовые кнопки остаются.

## Что нужно получить

Кликабельный HTML-прототип (один файл на вариант, без фреймворков, данные зашиты) на
данных случая Zabbix + Grafana + плагин: 158 объектов, 271 связь, 3 входа, склеено 3,
споры содержимого 2, остаток — 5 связей в контейнер, 1 изолированная группа из 12
объектов, 1 пара похожих имён, 3 спора полей.

Два варианта компоновки, чтобы сравнить рядом в браузере:

- **Вариант А — остаток встроен в существующие секции.** Строка замечания к слитой
  схеме становится действием на месте; споры полей живут в «Спорах содержимого»;
  секции остаются там, где они есть.
- **Вариант Б — одна секция «Разобрать перед импортом».** Споры содержимого и все
  четыре жеста собраны в один список дел со счётчиком «решено N из M», сгруппированный
  по типу; строки «Замечания к слитой схеме» остаются только для того, что действием
  не закрывается.

В каждом варианте показать состояния: (1) по умолчанию, ничего не тронуто; (2) после
разбора трёх остатков, включая одну добавленную связь и одну склейку; (3) остатка
нет вовсе; (4) остатков 40+; (5) сценарий догрузки к живому проекту с кандидатом
«Текущий проект». Для жеста 1 показать выбор компонента во вложенном дереве, для
жеста 2 — форму новой связи, для жеста 3 — выбор имени с правкой.

Не проектировать: саму механику слияния, холст, левую колонку окна, панель
незавершённости после импорта, новые способы сопоставления объектов, мобильную
версию. К прототипам приложить короткие заметки: какие решения приняты, где было
неочевидно, какие вопросы остались к продукту.
