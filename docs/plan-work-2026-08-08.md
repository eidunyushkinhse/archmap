#### Замер (стенд `example-voting-app`, слабая модель, один и тот же промпт-скелет)

Считано ОДНИМ измерителем по сохранённым выводам, чтобы «до» и «после» были
сравнимы. «Подвисший» = атомарный узел без связей (как в `app/alerts`).

| Метрика | ДО | После правки 1 | После правки 2 |
|---|---|---|---|
| Акторов внутри системы | 2 файла из 4 | 0 из 3 | 0 из 3 |
| Подвисших объектов, vote | 2 | 2 | 0 |
| Подвисших объектов, result | 4 | 2 | 0 |
| Подвисших объектов, worker | 4 | 0 | 0 |
| Выдуманных («опосредованных») связей | 1 | 0 | 0 |
| Имён, взятых из примера | 0 | 0 | 0 |

**Правка 1** — раздел «Связи», правило про людей, запрет опосредованных рёбер.
Акторы и выдуманные связи ушли сразу; подвисшие — нет.

**Правка 2** — правило в описании слоя 3: «создал компоненты — перенеси на них
связи контейнера». Причина была видна в выводе: агент рисовал ребро на уровне
контейнера (`vote → redis`) и клал внутрь компоненты, к которым уже ничего не
вело. После правки связи поехали на компоненты (`Избиратель → web-api`,
`queue-publisher → redis`) — подвисших не осталось.

⚠️ Третий прогон правки 2 (worker) СНАЧАЛА НЕ РАЗОБРАЛСЯ: модель написала путь
слэшем без пробелов — «worker/queue-reader». Это следствие самой правки: пока
рёбра ссылались на голые имена, слэшей в них не бывало, а требование адресовать
связи компонентов их принесло. Резолвер дозаливки доков такой фолбэк имел давно,
резолвер импорта СХЕМЫ — нет; добавлен (последним по очереди, чтобы не задевать
настоящие имена со слэшем). После этого прогон разбирается: 9 узлов, 7 связей,
подвисших нет.

⚠️ Замер вскрыл ошибку в НАШЕЙ проверке, а не только в промпте: `warn_content`
считала подвисшим и контейнер, чьи связи несут дети. Домен так не считает —
`app/alerts.compute_alerts` исключает контейнеры, потому что прямых связей у них
быть не должно. Исправлено, зеркалит алерты.
