# План: движок холста на больших схемах (ветка feat/render-scale)

Старт 2026-11-21. Сессия Fable 5.2 в папке `~/archmap-perf`. Живой план эпика: цифры замеров,
решения, запросы к другим сессиям и итоги фаз пишутся сюда.

## Зачем

Владелец после первого боевого использования ArchMap (2026-11-21): «Рендерер, который рисует
схему архитектуры, просто непозволительно медленный на большом количестве объектов. А большое
количество объектов встречается практически в любой архитектуре, которую собирает агент. Нужно
движок оптимизировать, и оптимизировать прям сильно».

## Порядок

1. Стенд и замер. Где уходит время: запрос графа на бэкенде, раскладка (ELK, VPSC, разводка
   рамок), маршруты стрелок, сборка и отрисовка React Flow, анимации переходов. Сценарии:
   открытие уровня холодное и тёплое, раскрытие и сворачивание контейнера, перетаскивание
   узла, переход между уровнями, страница объекта, режим «Развёртывание». Цифры показать
   владельцу до любых правок; цель «во сколько раз быстрее» ставит он.
2. План фаз по цифрам. Каждая фаза: правка, замер, регрессионный чек по спецификациям, коммит.

Из CLAUDE.md: оптимизация только после замера; кэш с инвалидацией по курсорам только если
замер показывает боль; атомарные ядра с инвариантом порядка эффектов (конвейер раскладки
`LevelGraph`) не выносить частями.

## Границы с параллельными сессиями

Параллельно идут ещё две сессии:

- main (`~/project`, Opus): бэкенд, MCP, сборщик фактов, CI, деплой, миграции, схемы API.
- `feat/redesign` (`~/archmap-redesign`, Fable): фронт вокруг холста и интерфейс процессов.

Зона движка:

- `frontend/src/components/graph/**`, кроме `CanvasToolbars.tsx` и `CanvasNotice.tsx` (их
  перекрашивает редизайн; пропсы менять по договорённости);
- `frontend/src/components/LevelGraph.tsx`, `frontend/src/embed/` (живая схема лендинга на том
  же холсте), `frontend/scripts/`;
- `docs/specs/**`: правишь движок, проходишь регрессионный чек по `docs/specs/README.md` и
  обновляешь спецификацию в том же коммите;
- на бэкенде эндпоинты графа, вида и контекста (`graph_queries.py`, `context_graph.py`,
  `connectivity.py`, `routers/views.py` и места, где они зовутся), если узкое место там.

Геометрия узлов (шрифт, отступы, размеры) принадлежит движку. Цвета и вид холста задаёт
редизайн в своём плане заданием, применяется оно после слияния движка или руками движка.

Не трогать:

- миграции и Pydantic-схемы: их делает main, запрос — раздел «Нужно от бэкенда»; ветка
  получает правку слиянием main;
- `mcp/`, `scan/`, остальной бэкенд, фронт вокруг холста. Если правка движка требует тронуть
  страницу с холстом (`MapEditorPage`, `NodePage`, `DeploymentPage`), правка минимальная и
  записывается в раздел «Пересечения»;
- `CLAUDE.md`, `QWEN.md`, `tasks.md`, `spec.md`, `docs/docs-delta.md` правятся последним
  коммитом перед слиянием в main, когда main уже влит в ветку.

## Как живёт ветка

- Регулярно вливать main в `feat/render-scale` (`git merge main`, не rebase). `api.gen.ts` при
  конфликте генерировать заново (`npm run gen:api`), руками не править.
- В main ветка едет через `--no-ff` по фазам после приёмки владельцем. `ROUTER_VERSION`
  поднимать, когда меняется результат маршрутов.
- Память Claude Code: проверить, что в контексте есть индекс «ArchMap — Memory Index». Если
  его нет, читать и писать в `/home/eidunyushkin/.claude/projects/-home-eidunyushkin-project/memory/`.
  Свои записи — отдельными файлами. `MEMORY.md` правят три сессии, поэтому только точечной
  правкой одной строки, без перезаписи файла целиком.
- Ноутбук 7,6 ГБ на три сессии: `VITEST_MAX_WORKERS=2`, тесты под `nice`, без параллельных
  субагентов, браузер для замеров закрывать после прогона.
