## Выводы

1. Фича работает END-TO-END на боевых промптах ОБЕИХ веток обёртки: кнопка →
   оркестратор → петля строитель/скептик (2 круга) → пакет → превью без ошибок
   (импорт: 0 ошибок / 6 штатных предупреждений; каналы: 0/0).
2. Скептик в поле бьёт ровно по слабым классам своего чек-листа: дословность
   имён каналов (импорт), состав полей сообщений против кода публикации
   (каналы) — оба класса раньше были невидимы до заливки. Ложных сомнений нет
   (V1-порог держит), непогашенное доносится дословно.
3. Правило чистых каталогов работает в обе стороны: грязный archmap-orch/
   эксперимента и приманка в archmap-docs/ снесены.
4. Кандидаты (НЕ в работе): (а) легитимизировать сомнения о полноте отдельной
   формой строки («в модели нет узла «X», хотя код…») — сейчас скептик выходит
   за жанр сам (Redis), но форма кривая; (б) типографский символ при сохранении
   блоков — принять как известное ограничение (семантика цела); (в) кириллические
   опечатки Haiku в путях отчёта («зerver») — безвредны, доказательства читаемы.

Пользователь прошёл путь сам на чистом клоне zabbix/zabbix: оркестраторный
промпт с кнопки → Haiku → заливка → круги замечаний. Итог — проект
«Zabbix Manual» (cc94d9a0), сохранён с 2 алертами isolated_groups после
«порочного круга» починки. Три находки пользователя и разбор:

**1. Два файла в панели после круга замечаний**: обновлённый architecture.yaml
перетаскивается в панель, где уже лежит прежний — оба мерджатся, пользователю
пришлось догадаться удалить старый. Решение пользователя: диалог в момент
«Скопировать замечания для агента» — «текущие файлы устареют, убрать?»
(фикс Ф5).

**2. «Порочный круг» починки — диагноз: галлюцинация действия у агента.**
Лог сессии (bb3d08a9): круг замечаний №1 — Read + 4 точечных Edit (честная
починка: SQLite убран, направление listener развёрнуто); круги №2–4 — **ноль
вызовов инструментов**, на каждое замечание агент отвечал только текстом
«Исправление: добавлена связь…», файл не менялся с 15:49 (mtime — улика).
Пользователь трижды вставлял байт-в-байт тот же контент, валидатор честно
повторял то же замечание. ArchMap импортировал ровно содержимое файла. След
мутации круга №1: правка «escalator → database» легла второй связью
«preprocessor → database» (дубль с двумя подписями в проекте). Механизм
отказа слабой модели: повторяющийся однотипный вход в длинной сессии →
деградация в «ответ по шаблону прошлого успеха» без инструментов. Фиксы Ф5:
гвард «вход не изменился» в панелях (ловит ровно это) + раздел обёртки
«замечания валидатора → точечная правка субагентом + проверь файл перед
отчётом».

**3. «Ты» в замечаниях** («дорисуй связь…») против конвенции «вы» продукта —
фикс Ф5, все валидаторные тексты на «вы»; промпты агентам остаются на «ты».

**Семантическая оценка «Zabbix Manual»**: скептик прогона отработал отлично —
все сомнения с файл:строка подтверждаются грепом (React отсутствует; «только
symfony/yaml, не полный Symfony» — composer.json:8; SQLite «#error not
supported» — server.c; направление listener→trapper развёрнуто — Accept в
serverlistener.go:90; Kubernetes-плагина нет в src/go/plugins/; «JSON-RPC» на
деле свой TCP-протокол — CZabbixServer.php:479), ложных сомнений ноль.
Инвентарь финала честный, включая неочевидный history-storage: Elasticsearch
(реальная опция — src/libs/zbxhistory/history_elastic.c). Главные дефекты:
(а) НЕТ alerter'а (src/libs/zbxalerter) — реального отправителя уведомлений,
его роль ошибочно у escalator, поэтому изоляция группы
escalator/web_service/External Notifications — ЧЕСТНЫЙ маркер настоящей дыры
(не нарисован вход эскалатора — база); (б) недожатые починки: «PHP + Symfony»
осталось (React убрал, Symfony нет), «JSON-RPC» и Kubernetes честно
непогашены; (в) артефактный дубль preprocessor → database. Ручная правка —
минут пять (добавить alerter/связь с БД, снять дубль, поправить technology).
