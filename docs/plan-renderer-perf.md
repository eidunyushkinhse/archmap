# План эпика «Производительность и качество рендерера» (старт 2026-08-20)

СТАТУС: Ф0 (измеритель + базлайн + атрибуция) сделана 2026-08-20. Ветка эпика —
feat/renderer-perf. Дальше: Ф1 — спека с НФТ на ревью пользователя.

## Мотив

Эталонные проекты BYOA-эпика (Zabbix 7 — 117 узлов/212 рёбер, Sentry — 51/199,
Zulip — 44/104, Grafana — 38/53) оказались первым честным стресс-полигоном
рендерера, и он его не пережил. Жалобы пользователя (2026-08-20, все
воспроизведены зондом):

1. **Зависания без индикации**: раскрытие узла на тяжёлых сценах занимает
   десятки секунд; всё это время холст пуст или кнопка «не нажалась» — пользователь
   в заблуждении, прокликивает повторно. Sentry: «Консьюмеры Kafka» раскрывать
   «можно даже не пытаться».
2. **Пропадание анимаций** от среднего размера сцены: анимации раскладки и
   раскрытия — элемент UX (отслеживание «что откуда взялось»), а не только
   эстетика.
3. **«Вертикальные сосиски» автораскладки**: рендерер складывает узлы в одну
   вертикаль возле «основного» узла (корни Zabbix/Grafana/Zulip). Причина
   архитектурная: N20 — ELK layered направлением RIGHT; звёздная топология
   корня (хаб + соседи) даёт два слоя, и весь второй слой становится одной
   колонкой.

## Ф0 — СДЕЛАНА: измеритель и базлайн

### Инструменты (все закоммичены в эпике)

- **scripts/perf-probe.mjs** — wall-clock замер сценариев пользователя на живом
  dev-стеке (headless-Chromium): открытие карты/страницы объекта, серия
  раскрытий по именам узлов; на каждый шаг — время до тишины, время конвейера
  в полёте (__archmapLayoutInflight), число прогонов, максимальный фриз
  главного потока (разрыв rAF), размер сцены. Роль viewer (раскрытия эфемерны).
  Флаги: --collapse-first (свернуть персист перед сценарием, глубже-сначала),
  --capture <файл> (захват последнего входа конвейера для реплея).
  Запуск: `set -a; source backend/.env; set +a; node scripts/perf-probe.mjs
  --project "Sentry Эталон" --collapse-first --expand "Sentry,Консьюмеры Kafka"`.
- **Трассировка стадий конвейера** — хук `__ARCHMAP_TRACE` (globalThis) в
  computeViewLayout, 12 марок по стадиям; без хука — мёртвый no-op.
- **Захват входа** — `__archmapCaptureInput = true` → pipelineClient сохраняет
  последний PipelineInput (`__archmapLastPipelineInput`).
- **Оффлайн-реплей** — frontend/src/components/__tests__/pipelineReplay.perf.test.ts:
  `ARCHMAP_REPLAY=<вход.json> npx vitest run pipelineReplay` (из frontend/),
  тайминги стадий → `<вход.json>.timings.json`. Без переменной тест скипается.

### Атрибуция (реплей Zabbix-корня, 36 узлов/85 рёбер, ~34.6с прогон)

| Стадия | мс | Доля |
|---|---|---|
| T4 мини-проход (плашки-препятствия, повторный buildAutoRoutes) | 25 373 | **73%** |
| Роутер: A*+rip-up+слоты+сварка (проход 1) | 8 616 | **25%** |
| ELK уровня | 386 (холодный) / 0 (тёплый) | ~1% |
| Всё остальное (проекция, кольца, инварианты, нуджинг, джоги, плашки) | <250 суммарно | <1% |

### Выводы Ф0

1. **98% времени — роутер стрелок** (A* с rip-up и его T4-повтор). Раскладка
   узлов (ELK, кольца, разведения) — пренебрежимо дёшева. «Мини-проход» T4
   стоит ×3 полного прохода.
2. **Главный поток свободен** (макс. фриз ≤0.4с — это маунт DOM): весь счёт в
   воркере. Значит (а) индикация занятости тривиально возможна — рисовать есть
   чем; (б) браузер не «висит», он молча ждёт.
3. **Открытие уровня = двойная цена**: двухфазный замер (фолбэк-габариты →
   замер → пере-прогон) гонит конвейер дважды; персист раскрытий заставляет
   платить за тяжёлую сцену при каждом возврате на карту.
4. **Суперлинейность по рёбрам**: 49 рёбер — 4.8с; 85 — 72с; 128 — 133с.
   При этом Zulip (89 рёбер) втрое дешевле Zabbix (85) — состав сцены
   (рамки/плашки/плотность) влияет сильно, третья степень или хуже.
5. Пропадание анимаций — следствие тех же таймаутов (каскад стартует после
   счёта; детали уточнить в Ф1 по transitions.md).

## Фазы

- **Ф0 — измеритель + базлайн.** СДЕЛАНА (выше).
- **Ф1 — спека и НФТ (гейт: ревью пользователя).** Инвентаризация текущих спек
  (view/transitions/node N20/canvas) на актуальность; НОВАЯ спека
  производительности и автораскладки (кандидат: docs/specs/perf.md +
  правка N20): бюджеты «раскрытие ≤ Xс при N узлов/M рёбер», пороги деградации
  анимаций, ОБЯЗАТЕЛЬНАЯ индикация занятости >300мс, требования к форме
  раскладки (анти-сосиска: компактный аспект, звезда/сетка для хабовой
  топологии). Целевые числа предлагает Claude, утверждает пользователь.
- **Ф2 — быстрые UX-победы** (до глубокой оптимизации, каждая — отдельный
  коммит): индикация «считаю раскладку» на холсте и на лупе/кнопке; защита от
  повторного прокликивания; возможно спиннер на пустом холсте первого показа.
- **Ф3 — оптимизация роутера** (по атрибуции Ф0, каждая правка — замер против
  базлайна): первоочередные подозреваемые — T4 мини-проход (73%!) и A*-проход.
  Направления (проектировать после Ф1): профилирование ВНУТРИ buildAutoRoutes
  (какая часть A* горит: сетка? эвристика? rip-up-итерации?), сокращение
  dirty-набора T4, переиспользование obstacle-структур между рёбрами,
  инкрементальность, бюджет времени прогона с деградацией качества. Гарантия
  качества: дампы маршрутов до/после (прецедент перф-прохода ~3× эпика
  стрелок: байт-в-байт); спеки edge.md держат поведение.
- **Ф4 — качество автораскладки («анти-сосиска»)** по спеке Ф1: раскладка
  хабовых уровней (корень) без вертикальной колонки — варианты: ELK-опции
  (aspect ratio, компактизация), пост-обработка второго слоя, force/radial для
  звёздных топологий (ОСТОРОЖНО: контекст-движок на ELK не сажать — и наоборот,
  bespoke-звезду уровню не навязывать без спеки). Сверка глазами пользователя.
- **Ф5 — контроль**: полный прогон perf-probe по всем эталонам против НФТ
  спеки; регрессия структурными сигнатурами (dump-levels); обновление спек.

## Риски и ограничения

- Роутер — самый выстраданный модуль проекта (эпики стрелок V1/V2, «читаемые
  пучки», перф-проход ~3×; спека edge.md — 528 строк инвариантов). Любая
  оптимизация — только с дампами маршрутов до/после и прогоном тестов рёбер;
  качество маршрутов НЕ жертвуется молча — жертвы утверждает пользователь.
- Двухфазный замер и персист раскрытий — механики со спековыми инвариантами
  (V2.2b, view.md): менять только через спеку.
- Гистерезис/скоуп-механики уже борются с чурном маршрутов — оптимизация не
  должна их сломать (осцилляции вернутся).
- Пользователь готов помогать: DevTools-аналитика, решения «чем жертвовать».
