# План эпика «Производительность и качество рендерера» (старт 2026-08-20)

СТАТУС: Ф0 (измеритель + базлайн + атрибуция) сделана 2026-08-20. Ветка эпика —
feat/renderer-perf. Дальше: Ф1 — спека с НФТ на ревью пользователя.

## Мотив

Эталонные проекты BYOA-эпика (Zabbix 7 — 117 узлов/212 рёбер, Sentry — 51/199,
Zulip — 44/104, Grafana — 38/53) оказались первым честным стресс-полигоном
рендерера, и он его не пережил. Жалобы пользователя (2026-08-20, все
воспроизведены зондом):

1. **Зависания без индикации**: раскрытие узла на тяжёлых сценах занимает
   десятки секунд; всё это время холст пуст или кнопка «не нажалась» — пользователь
   в заблуждении, прокликивает повторно. Sentry: «Консьюмеры Kafka» раскрывать
   «можно даже не пытаться».
2. **Пропадание анимаций** от среднего размера сцены: анимации раскладки и
   раскрытия — элемент UX (отслеживание «что откуда взялось»), а не только
   эстетика.
3. **«Вертикальные сосиски» автораскладки**: рендерер складывает узлы в одну
   вертикаль возле «основного» узла (корни Zabbix/Grafana/Zulip). Причина
   архитектурная: N20 — ELK layered направлением RIGHT; звёздная топология
   корня (хаб + соседи) даёт два слоя, и весь второй слой становится одной
   колонкой.

## Ф0 — СДЕЛАНА: измеритель и базлайн

### Инструменты (все закоммичены в эпике)

- **scripts/perf-probe.mjs** — wall-clock замер сценариев пользователя на живом
  dev-стеке (headless-Chromium): открытие карты/страницы объекта, серия
  раскрытий по именам узлов; на каждый шаг — время до тишины, время конвейера
  в полёте (__archmapLayoutInflight), число прогонов, максимальный фриз
  главного потока (разрыв rAF), размер сцены. Роль viewer (раскрытия эфемерны).
  Флаги: --collapse-first (свернуть персист перед сценарием, глубже-сначала),
  --capture <файл> (захват последнего входа конвейера для реплея).
  Запуск: `set -a; source backend/.env; set +a; node scripts/perf-probe.mjs
  --project "Sentry Эталон" --collapse-first --expand "Sentry,Консьюмеры Kafka"`.
- **Трассировка стадий конвейера** — хук `__ARCHMAP_TRACE` (globalThis) в
  computeViewLayout, 12 марок по стадиям; без хука — мёртвый no-op.
- **Захват входа** — `__archmapCaptureInput = true` → pipelineClient сохраняет
  последний PipelineInput (`__archmapLastPipelineInput`).
- **Оффлайн-реплей** — frontend/src/components/__tests__/pipelineReplay.perf.test.ts:
  `ARCHMAP_REPLAY=<вход.json> npx vitest run pipelineReplay` (из frontend/),
  тайминги стадий → `<вход.json>.timings.json`. Без переменной тест скипается.

та же пропорция — T4 мини-проход 63.1с (74%), роутер проход 1 — 20.9с (25%),
ELK 0.4с, всё прочее <1%. Атрибуция не случайность одной сцены.

### Выводы Ф0

1. **98% времени — роутер стрелок** (A* с rip-up и его T4-повтор). Раскладка
   узлов (ELK, кольца, разведения) — пренебрежимо дёшева. «Мини-проход» T4
   стоит ×3 полного прохода.
2. **Главный поток свободен** (макс. фриз ≤0.4с — это маунт DOM): весь счёт в
   воркере. Значит (а) индикация занятости тривиально возможна — рисовать есть
   чем; (б) браузер не «висит», он молча ждёт.
3. **Открытие уровня = двойная цена**: двухфазный замер (фолбэк-габариты →
   замер → пере-прогон) гонит конвейер дважды; персист раскрытий заставляет
   платить за тяжёлую сцену при каждом возврате на карту.
4. **Суперлинейность по рёбрам**: 49 рёбер — 4.8с; 85 — 72с; 128 — 133с.
   При этом Zulip (89 рёбер) втрое дешевле Zabbix (85) — состав сцены
   (рамки/плашки/плотность) влияет сильно, третья степень или хуже.
5. Пропадание анимаций — следствие тех же таймаутов (каскад стартует после
   счёта; детали уточнить в Ф1 по transitions.md).

## Фазы

- **Ф0 — измеритель + базлайн.** СДЕЛАНА (выше).
- **Ф1 — спека и НФТ.** РЕШЕНИЯ ПОЛЬЗОВАТЕЛЯ ПРИНЯТЫ 2026-08-20:
  (1) бюджеты утверждены — >300мс → индикация + защита от прокликивания;
  типовая сцена (≤50 узлов/≤100 рёбер) ≤1.5с счёта; предельная (~80/200) ≤5с
  с индикацией; (2) анимации ЧЕСТНО отключаются ВЫШЕ предельной сцены, с
  разовым тостом «схема перегружена, плавность не гарантируется» — ниже
  предельной не отключаются никогда; (3) форма раскладки — выбор глазами из
  2–3 визуальных вариантов на РАЗНЫХ эталонах (Sentry-корень НЕ идеал, лишь
  ближе всех к желаемому). НФТ записаны в docs/specs/perf.md (инварианты
  P1–P9, целевые с маркером [ЦЕЛЬ]). Мокапы вариантов — layoutMockup.perf.test.ts
  на свёрнутых корнях эталонов без сохранённых позиций; страница сравнения
  (4 корня × 4 формы: текущая / звезда / stress / force) опубликована:
  https://claude.ai/code/artifact/5ae74bcc-5864-4a86-b312-8ea20ef024d9 —
  ЖДЁТ ВЫБОРА ФОРМЫ ГЛАЗАМИ. Отброшены до показа: ELK radial (стек на циклах),
  layered wrapping (не влияет на широкий слой), mrtree (непоследователен).
  Числа: текущая — аспект 0,39–0,77 (колонна везде, кроме Sentry); звезда
  1,54–1,64; stress 1,09–2,18; force ~1,0; наложений тел нигде нет.
  ДОЗАМЕР ПО ВОПРОСАМ ПОЛЬЗОВАТЕЛЯ (stress vs force, общность правила):
  на корнях-звёздах органика ДЕШЕВЛЕ текущей для роутера (радиальные маршруты
  короче коридоров колонны), а на ВНУТРЕННИХ потоковых уровнях — в 2–4 раза
  ДОРОЖЕ (Sentry-уровень: 2,8с layered против 9,5–13,4с органики) и грязнее
  по маршрутам (layered выравнивает поток в параллельные коридоры).
  Устойчивого победителя stress/force по скорости нет. ВЫВОД-ПРЕДЛОЖЕНИЕ:
  правило topology-aware в ОДНОЙ стадии layoutLevel (звёздам — органика,
  потокам — layered), не «if root»; страница дополнена разделом уровней
  и ценой роутера на карточках.
  ВЫБОР ПОЛЬЗОВАТЕЛЯ: ОРГАНИКА = FORCE (2026-08-20). Обзор «доли хаба»
  (scripts/hub-survey.py, 32 уровня ≥5 рёбер по 6 проектам) для сравнения
  «топологическое правило vs исключение для корня»: метрика hub1 = доля
  мастер-рёбер самого связного узла разделяет чисто — звёзды ≥0.60 (все 6
  корней 0.62–1.00, включая федеративный 0.70, И внутренние звёзды:
  «Консьюмеры Kafka» 1.00 — самый больной уровень базлайна, «Grafana» 0.88,
  «Воркеры очередей» 0.70, «Служебные процессы» 0.70), потоки ≤0.50
  (Zabbix server 0.32, Sentry 0.31, Zulip 0.27). Исключение-для-корня
  пропустило бы ВСЕ внутренние звёзды. Порог-кандидат HUB_SHARE=0.55
  (зазор 0.50–0.60 пуст). Риск: сильно разбавленная мультихаб-федерация
  может нырнуть под порог — зафиксировать в спеке как открытый вопрос.
  РЕВЬЮ QWEN (docs/review-layout-rule-qwen.md → ответ
  docs/review-layout-rule-response.md): оба топ-риска подтверждены
  экспериментально — v1-обзор завышал hub1 внутренних уровней (артефакты
  приближения; «Консьюмеры Kafka» 1.00 → 0.40 на боевой семантике), а плотные
  мультихабы (хаб-гость) на force дорожают ×2.9–3.3 И визуально хуже.
  ПРАВИЛО v2 (по Δ-цене, а не середине зазора): force если диаметр ≤ 2 ИЛИ
  h1u ≥ 0.75, иначе layered; guard E<5 / <3 соседей хаба. В force-зоне нет ни
  одной подорожавшей сцены. aspectRatio у elkjs-force не работает (проверено
  байт-в-байт) — ожидаемый аспект force ≈ 1.0 в N20. ОТКРЫТЫЙ ВОПРОС после
  Ф3: форма плотных мультихабов (Консьюмеры 0.48, Воркеры 0.55 — колонны
  остаются на layered; кандидат решения — звезда-сеятель).

## Уроки эпика (для следующего захода)

- Атрибуция ПЕРЕД оптимизацией окупается многократно: V8-профиль (vite-node +
  NODE_OPTIONS=--cpu-prof) и счётчики __routeCounters нашли всё; догадки до
  замера дважды оказывались неверными (заливки скретча — дёшевы, wrap-свёртка
  ELK — пустышка).
- Гарантия «маршруты байт-в-байт» (дампы до/после на 4 сценах, Sentry-референс
  через stash) позволила крутить самый выстраданный модуль без страха.
- Ловушка cwd: python-патчи из корня, vitest/vite-node из frontend/ — потерянный
  cd дважды прогонял «изменения», которых не было (проверять «patched» И diff).
- Скептик-раунд с исполнимыми проверками (Qwen) дважды изменил решение формы —
  протокол «проверка, которой возражение снимается» сильнее мнений.
- Замеры под CPU-контеншном (фоновые прогоны) льстят/врут — контрольные числа
  снимать на тихой машине; флейки сьюта под контеншном — тоже.

## Риски и ограничения

- Роутер — самый выстраданный модуль проекта (эпики стрелок V1/V2, «читаемые
  пучки», перф-проход ~3×; спека edge.md — 528 строк инвариантов). Любая
  оптимизация — только с дампами маршрутов до/после и прогоном тестов рёбер;
  качество маршрутов НЕ жертвуется молча — жертвы утверждает пользователь.
- Двухфазный замер и персист раскрытий — механики со спековыми инвариантами
  (V2.2b, view.md): менять только через спеку.
- Гистерезис/скоуп-механики уже борются с чурном маршрутов — оптимизация не
  должна их сломать (осцилляции вернутся).
- Пользователь готов помогать: DevTools-аналитика, решения «чем жертвовать».
