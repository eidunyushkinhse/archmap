Что обе версии делают неверно (материал следующей правки промпта, по отчётам скептиков):
- связи с брокером неполны с обеих сторон конвейера: нет relay → Kafka и Kafka → snuba (Sentry),
  потребители NATS угаданы, а не найдены по Subscribe (Grafana); канал шаблоном вместо констант кода;
- связи процессов с базами и кэшами, в которые они пишут, не рисуются (Sentry консьюмеры, Zabbix
  конвейер через разделяемую память, ui → Elasticsearch);
- внешние службы без кода в репозитории попадают внутрь системы без external (Grafana settings-service,
  image-renderer); производный образ той же программы остаётся отдельным контейнером (Grafana custom,
  Sentry self-hosted у кандидата);
- удаление записи сборщика не оговаривается в модели (Sentry devserver, Zabbix mock_server);
- нет правила source для процессов с общей фабрикой или общим кодом (Sentry консьюмеры, Zabbix прокси):
  старая версия подгоняет пути, кандидат оставляет source пустым;
- имена баз берутся производными, а не из конфигурации (Zabbix DBName);
- крупные подсистемы ядра выпадают без реестра (Grafana секреты, дашборды, аннотации, Advisor);
- добавленные связи с брокером без `sync: false` у кандидата Sentry (26 связей);
- ветвление шаблона супервизора (режимы воркеров Zulip, группа `[group:zulip-workers]`) не разбирается:
  старая версия показала оба режима соседями, кандидат выбрал режим не по умолчанию; эксплуатация
  Zulip Cloud (puppet/kandra) смешана с продуктом; host у внешних узлов не заполнен, хотя адреса в
  коде есть; связи наблюдения направлены в компонент вместо контейнера.

## 6. Вывод судьи

Счёт скептиков по девяти пунктам на четырёх репозиториях: кандидат ближе к коду в 15 пунктах, старая
версия в 6, поровну в 15. Ни в одной паре скептик не назвал старую версию ближе в целом: Sentry и
Grafana «B ближе», Zabbix «небольшой перевес у B», Zulip «почти поровну». Обвязка measure2 показывает
то же без слепоты: на Sentry и Grafana кандидат выигрывает по фактам (общий код подан с адресом,
тёзка не переименована, файл параметров Grafana принят вместо отказа), замечаниям и рекомендациям без
потерь; на Zabbix полнее вдвое по компонентам при той же цене; на Zulip полнее, но менее точен.

Что именно дали три новые фразы, видно напрямую: оба случая файлов общего кода (Sentry 1, Grafana 7)
кандидат подал с адресом, старая версия оставила без адреса; обе тёзки (sentry, Grafana) кандидат
сохранил, старая версия переименовала Grafana и сломала шапку фактов; запись «общий код» у Zabbix
кандидат отдал компоненту с адресом, старая версия упомянула в описании. Побочные эффекты фраз
скептики не нашли: имена, source и люди у кандидата не хуже.

Минусы кандидата не связаны с новыми фразами и общие для обеих версий (дисперсия строителя, а не
промпт): дубль процесса (Sentry self-hosted и sentry, Grafana grafana-server), задания cron и
воркеры компонентами на Zulip, добавленные связи с брокером без `sync: false` на Sentry, по одному
неверному каналу на Sentry и Grafana. Это материал следующей правки промпта (раздел 5), которую судья
предлагает делать отдельным кандидатом и мерить тем же протоколом.

Рекомендация судьи: кандидат принять и слить `feat/prompt-measure` в main (`--no-ff`), эталоны v2
Zabbix 7, Zulip и Grafana считать принятыми (материалы в `~/archmap-etalons-2026-08-19/etalons-v2/`),
старые эталоны 2026-08-19 оставить историей.
