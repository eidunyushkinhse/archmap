# План эпика «Единый импорт проекта»

Дата груминга: 2026-09-02 (решения пользователя приняты в диалоге).
Происхождение: замечания П2+П3 приёмки эпика архива (docs/plan-archive-export.md),
пункт-заглушка «Импорт проекта (zip)» в кебаб-меню «Действия со схемой».

## Цель

Один сценарий ввоза знания вместо двух: «Импорт» принимает N входов ЛЮБОГО типа
(YAML C4 и/или zip-архив знания) в обеих точках входа —

- **создание проекта** (модалка создания: табы «Импорт» и «Из архива» сливаются);
- **догрузка к существующему** (кебаб «Импорт проекта (zip)»: один или несколько
  архивов доливаются к текущему проекту с мерджем).

Схемы мерджатся, семьи фактов (доки, БД, каналы, конфиги, спеки, процессы)
доезжают к смердженным узлам; конфликты разрешаются пользователем в превью.

## Решения груминга (2026-09-02)

1. **Конфликты семей при склейке узлов — РАЗРЕШЕНИЕ В ПРЕВЬЮ** (решение
   пользователя, выбрано и для создания, и для догрузки). Конфликт — это два
   вклада в один merged-узел с одинаковым ключом и РАЗНЫМ телом: доки-тёзки,
   две спеки OpenAPI, параметр-тёзка с другим default/description, тёзки
   таблиц/каналов с разными телами. Превью показывает каждый конфликт с
   кандидатами и происхождением; пользователь выбирает; apply применяет выбор.
   Байт-в-байт равные тела — дедуп молча, это не конфликт (сравнение тел доков —
   ПОСЛЕ strip_header: шапки разных экспортов различаются node-путём).
2. **Догрузка аддитивна по дефолту, перезапись — только осознанным выбором в
   превью**: дефолт каждого конфликта «живое vs архив» — «оставить моё»;
   перетирание живой записи случается только если пользователь явно выбрал
   кандидата из архива. Массовой галки «перезаписывать всё» в v1 нет.
3. **Таб «ИИ-агент» остаётся отдельным** (витрина BYOA): сливаются только
   «Импорт» + «Из архива». Панель импорта внутри обоих табов — одна и та же,
   единая (принимает и YAML, и zip).
4. **Смежные хвосты BYOA втягиваются в эпик** (оба): чекбокс федерации
   multi_product в SyncRepoModal; раздел «## Поле source» строительного промпта
   адаптируется под федерацию (заглушки соседей выходили с пустым source —
   бэклог матрицы федерации 2026-08-16).

Решения, предложенные исполнителем на груминге (пользователь видел, не возразил):

- **П3, имя/описание проекта**: поля прячутся ⇔ ровно один вход и он архив
  (имя/описание из манифеста, «копия одного архива»); N входов или YAML —
  произвольные поля, как сейчас. При догрузке манифест на имя проекта не влияет.
- **Скалярные C4-поля узла** (role/technology/description/…): при создании —
  прецедент C4-мерджа (содержательное побеждает, тай-брейк — порядок входов,
  факт строкой отчёта; ЭТО НЕ интерактивный конфликт). При догрузке — fill-only:
  заполненное живое поле не перетирается, расхождение — строкой отчёта.
  Интерактив в v1 — только для семей фактов; C4-поля к нему не подключаем
  (иначе конфликтная модель раздувается на порядок при копеечной пользе).
- **Процессы не мерджим никогда**: авторские sequence-диаграммы не склеиваются;
  тёзки получают суффикс « (2)» + замечание.
- **Привязки шагов процессов** («%% archmap-doc: путь/имя») резолвим ПО
  ПРОИСХОЖДЕНИЮ (шаг архива-2 → док архива-2) ДО любых переименований доков —
  неоднозначность после склейки невозможна по построению.
- **Догрузка — только через превью-план** (паттерн синка и всех дозаливок):
  меняется живой проект, применение вслепую запрещено.
- **Раскладка**: при создании — авто (аксиома эпика архива в силе: раскладку не
  возим); при догрузке существующие узлы НЕ двигаются (view_layout не трогаем),
  новые узлы доложит конвейер.
- **Кебаб-кнопка принимает только zip**: YAML-в-существующий уже есть в том же
  меню — «Импорт схемы» (синк по якорям, create/update). Вместе они закрывают
  давний этап B repo-import целиком.
- **API**: превью/apply создания — новый multipart-эндпоинт (N файлов «yaml и
  zip вперемешку» + вставленные тексты); догрузка —
  POST /projects/{id}/import-archive/preview | /apply. Старый одноархивный
  /projects/import-archive поглощается новым (фронт — единственный потребитель;
  MCP на архив не завязан).

## Архитектура

Один конвейер на оба сценария:

```
входы (N: yaml-тексты + zip-архивы [+ self-export при догрузке])
  → parse_import каждого C4 → merge_imports (происхождение вкладов)
  → семьи каждого архива перевешиваются на merged-узлы (по происхождению)
  → конфликт-объекты (family, node_path, key, кандидаты с происхождением)
  → превью (сводка + отчёт слияния + конфликты)
  → apply(resolutions) — создание проекта ЛИБО дифф к живому проекту
```

- **Происхождение**: MergeReport уже несёт node_files (какие входы внесли вклад
  в каждый merged-узел — наследие Ф7 скептика). Для перевески семей нужно
  сильнее: соответствие «(вход, узел входа) → merged-узел» — вытащить из
  _Merger наружу (Ф0). Адрес семьи в архиве N (путь по C4 архива N) резолвится
  в узел ЕГО C4, оттуда — в merged-узел.
- **Догрузка = тот же конвейер**, вход №0 — self-export текущего проекта
  (build_archive уже готов; в память, не на диск). Применение — ДИФФОМ:
  merged-узел с вкладом входа №0 = живой узел (id сохраняется, C4-поля
  fill-only); merged-узел без вклада №0 — создаётся; ничего не удаляется.
  Матчер узлов один — identity.py (сильнейший общий ключ); вторых правил
  сравнения не заводим (урок тюнинга-2).
- **Конфликт-объект**: стабильный id = (family, node_path, key). Мердж
  детерминирован ⇒ id совпадают между preview и apply; протокол стейтлесс,
  резолюции передаются словарём id → выбор. Выбор для доков/таблиц/каналов:
  «кандидат i» | «взять все (тёзкам суффикс)»; для скаляров (спека, поля
  параметра): «кандидат i». Дефолты: создание — «взять все» (доки) /
  первый-содержательный (скаляры); догрузка — «оставить моё».
- **Fence догрузки**: apply несёт base graph_rev+meta_rev из превью; проект
  изменился между preview и apply → 409 «обновите превью» (паттерн CAS в
  проекте живёт; сверить детали с sync_apply при реализации).
- **Отчёт**: пофайловые замечания с адресацией по происхождению уже есть
  (split_remarks) — расширяются на архивы как на входы; сводка по семьям — их
  родные отчёты (вторых форматов не заводим, норма эпика архива).

## Фазы

Гейт каждой фазы: полный (tsc -b, eslint, vitest — из frontend/; ruff, pytest —
из backend/), коммит, пуш. Известные флейки vitest — протокол «изолированный
прогон зелёный → повторить коммит».

- **Ф0 — происхождение вкладов наружу.** _Merger отдаёт соответствие
  «(вход, узел входа) → merged-узел»; тесты на склейку/переезды. Чистый бэк,
  ничего пользовательского.
- **Ф1 — конфликтная модель + превью создания (бэк).** Разбор zip как входа
  (капы _read_zip живут), семьи на merged-узлах, конфликт-объекты, multipart
  preview N смешанных входов. Сюда же — два сценария имени/описания (П3).
- **Ф2 — apply создания + UI создания.** apply(resolutions); единая панель
  импорта (чипы .yaml/.zip, вставка текста, живое превью с конфликтами), таб
  «Из архива» удаляется, «ИИ-агент» получает ту же панель; отчёт применения.
- **Ф3 — догрузка (бэк).** Self-export входом №0, дифф-применение к живым id,
  fence, preview/apply эндпоинты, отчёт.
- **Ф4 — догрузка (UI).** Оживление пункта кебаба «Импорт проекта (zip)»:
  модалка N zip → превью с конфликтами (дефолт «оставить моё») → применение →
  отчёт; массовые действия («везде моё» / «везде из архива N»).
- **Ф5 — хвосты BYOA.** Чекбокс multi_product в SyncRepoModal (сквозь
  sync-эндпоинты до промпта); раздел «## Поле source» под федерацию. Правки
  промптов — UPDATE_PROMPT_SNAPSHOTS + ревью git diff снапшотов ТЕМ ЖЕ коммитом.
- **Ф6 — полевой прогон и фикспойнты.**
  1. Регресс: один архив Ярмарки v2 → создание — результат байт-в-байт прежний
     (0 конфликтов; повторить md5-фикспойнт 52 файла / 0 различий).
  2. Федерация: два архива (Zabbix + Grafana из полевых прогонов) → один
     проект, конфликты видимы и разрешаемы.
  3. Догрузка: архив к живому проекту с рукотворным конфликтом (дока-тёзка) —
     дефолт «оставить моё» держит, выбор из архива перетирает.
  Документация: spec.md, tasks.md, README MCP не трогаем (архива там нет).

## Итоги Ф6 — полевой прогон (2026-09-02)

Все проверки на живом стеке (curl multipart + headless-зонд), временные проекты
снесены, БД вернулась к исходным 35 активным.

1. **Фикспойнт создания**: архив Ярмарки v2 → превью (0 споров, П3 manifest) →
   создание → экспорт: md5 zip БАЙТ-В-БАЙТ равен исходному, 52 файла /
   0 различий — планка приёмки эпика архива удержана единым путём.
2. **Федерация**: Ярмарка + Zabbix-эталон → 151 узел / 249 связей, 0 ложных
   склеек, 0 споров (продукты не пересекаются); у Zabbix-эталона семей нет —
   счётчики честно Ярмаркины.
3. **Споры**: оригинал + мод-архив (правлены тело дока, default параметра,
   спека) → ровно 3 спора с точными кандидатами; всё прочее дедупнулось
   (13 таблиц, 48 параметров — не задвоены). Применение с резолюциями
   «cand:1» для дока и спеки: мод-тела доехали, параметр остался оригинальным
   по дефолту; resolved_conflicts=3.
4. **Догрузка**: к дублю Ярмарки её мод-архив → «Нового: 0», 3 спора с
   current-кандидатом и дефолтом «оставить моё». Применение с дефолтами: md5
   экспорта НЕ изменился (аддитивность доказана побайтово). Явный выбор
   «взять из архива» для дока: изменился РОВНО один файл экспорта. Fence:
   протухшая ревизия → 409, свежая → 200.
5. **UI-смоук headless**: модалка создания (zip-чипы, карточка архива, «Из
   архивов: …», споры) и модалка догрузки (споры, метка «моё», массовые
   кнопки) — скриншоты сняты, зонд probe-unified-ui.mjs.
6. Находки: (а) дубль «Текущий проект — текущий проект» — починен a5bcb3c
   (метка начертанием); (б) применение догрузки бампает ревизии и при нуле
   изменений — ОСОЗНАННО оставлено (лишний ресинк чужих сессий безвреден,
   fence-протокол прост); (в) полевое подтверждение промпт-правки Ф5
   (заглушки соседей с host) возможно только мультирепо-прогоном живого
   агента — при следующей федерации пользователя.

## Находка приёмки пользователя (2026-09-02): изолированный плагин в федерации

Кейс: Monitoring = создание из «Zabbix Эталон»+«Grafana Эталон», затем догрузка
«Плагин Zabbix для Grafana» → плагин со своим окружением остался изолированной
группой. Диагноз по повтору пути и экспериментам (двухслойный):

1. **Данные (главное в этом кейсе).** Все три архива — из до-федеративной
   эпохи: у эталонов НЕТ host-примет (только repo+path у части узлов), плагин
   уложен одиночным промптом (корень «Плагин…», docker-compose-окружение —
   детьми корня; repo плагина повешен на узел «grafana»). Ни именам (разные
   родители, «zabbix-server» ≠ «Zabbix server»), ни якорям (host против
   repo+path — нет общего типа) зацепиться не за что; мердж по правилу
   «ложная склейка хуже дубля» честно НЕ клеит и кричит в превью (fuzzy-пары,
   «нет общих корневых», «группа из 12 не связана»). Эксперимент: те же архивы
   с приметами сегодняшнего федеративного промпта (host у «Zabbix server» /
   «Zabbix web-интерфейс» / корня «Grafana»; repo плагина — его корню, host —
   узлу «grafana») при создании ИЗ ТРЁХ РАЗОМ дают 4 склейки и СВЯЗНУЮ схему
   без изолированных групп — механика identity работает.
2. **Механика (найден реальный дефект): асимметрия создания и догрузки.**
   Node.source_ref хранит ОДИН сильнейший якорь (решение arch-sync), поэтому
   узел {repo, path, host} после создания теряет host; self-export догрузки
   несёт только source_ref → у пары «заглушка с host vs узел с repo» снова нет
   общего типа. Тот же набор fed-архивов: создание разом — склейка есть,
   «создать из двух + догрузить третий» — заглушки Zabbix не клеятся (Grafana
   склеилась: host был её ЕДИНСТВЕННЫМ ключом и стал source_ref). Лечение —
   хранить НАБОР ключей узла (source_refs) — отдельный эпик-кандидат
   (миграция, матчеры, контракт C4); записан в tasks.

## Ловушки (перенос из прошлых эпиков + новые)

- Сравнение тел доков «байт-в-байт» — только ПОСЛЕ strip_header (шапка несёт
  node-путь и разъезжается между экспортами при одинаковом теле).
- Кириллица в Content-Disposition → 500 (пройдено в архиве; догрузка отдаёт
  JSON, но помнить при любых новых скачиваниях).
- Мультипарт с N UploadFile + текстовые поля — проверить смесь на живом
  uvicorn, не только TestClient (границы кодировок).
- Моки api на фронте прячут форму тел — в тестах модалок валидировать фикстуры
  model_validate-схемами бэка (урок федерации).
- Тексты промптов под абсолютным сторожем: правка раздела source — снапшоты
  тем же коммитом, дифф снапшотов = ревью.
- «Пример сильнее правила»: федеративную адаптацию source вести через ПРИМЕР
  (в _federated уже есть source у узлов — проверить, что у заглушек соседей
  он есть в примере, а не только в тексте правила).
- ELK/раскладка к эпику не относятся — руки в движок не запускать.
- Находка Ф0 (2026-09-02): пост-шаг стабилизации _regroup после К3 недостижим
  через merge_imports (вердикт different всегда «мостится» парой вкладов —
  _bridged запрещает объединение; спай в 86 тестах + 30k случайных схем — ноль
  срабатываний). НЕ чинить в этом эпике: порядконезависимость держится и без
  него (тест 6 перестановок зелёный), ветка покрыта белоящичным тестом. Если
  когда-нибудь ослабят _bridged — перенос происхождения уже под тестом.

Решения приёмки Ф2а (2026-09-02):

- Шаг, чей адрес совпал с адресом победителя спора, привязывается к ТЕЛУ
  победителя — семантика верная: адрес это «узел + имя», выбор кандидата
  канонизирует тело имени. Проигравшая дока с РАЗОШЕДШИМСЯ адресом даёт шаг без
  привязки + замечание (покрыто тестом).
- Узлы-тёзки с одинаковым merged-путём (якорь развёл их в одном родителе):
  id спора неуникален, адресация семей путём неоднозначна → файл пропускается с
  замечанием. Известное ограничение v1 (то же было у одноархивного импорта);
  чинить только по полевому спросу.

## Вне скоупа (осознанно)

- Массовая перезапись живого по флагу (overwrite-галка догрузки) — при спросе.
- Интерактивные конфликты для C4-полей узла — при спросе.
- Мердж содержимого процессов.
- Импорт YAML через кебаб-кнопку догрузки (это синк — «Импорт схемы»).
