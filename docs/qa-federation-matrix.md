**Семантика (критерий «нет НОВЫХ классов лжи»):**

  по-прежнему отсутствует, «PHP + Symfony» в technology (в composer.json —
  только symfony/yaml). П13 «technology из манифестов» этот случай не ловит:
  правило формально соблюдено, врёт трактовка.

**Разбор деградации Zulip.** Остаток — 5 связей «контейнер → его собственный
ребёнок» (`background-workers → email-senders` и т.д.). Проверено: этих имён
НЕ БЫЛО ни в одном нашем замечании (0 вхождений в обоих кнопочных текстах) —
агент выдумал их сам под интро «дописывай недостающие связи». Наш текст на
такую связь отвечает бессмысленно («уточните до конкретного компонента» — цель
уже компонент), поэтому круги её не лечат. Это НЕ следствие фиксов тюнинга, но
и не лечится ими.

## Находки матрицы (кандидаты второй итерации, НЕ в работе)

1. **Пример в промпте перебивает правило федерации (главная).** Раздел П1
   стоит на позиции 5099 блока А, встроенный ПРИМЕР документа — на 8292, и в
   примере под корнем лежат сервисы без контейнера-продукта. Zabbix-агент
   раздел прочитал (сохранён в builder-prompt.txt дословно) и не исполнил:
   7 узлов в корне, заглушки соседа нет. Grafana и плагин исполнили верно —
   значит 2/3, дисперсия на грани. ФИКС: показать федеративный вариант в самом
   ПРИМЕРЕ (или ставить раздел после примера) — четвёртое подтверждение урока
   «цель с ответом»: правилу нужен образец.
2. **Перечень П5 переносит имя компонента в чужой контейнер.** Замечание
   предлагало «zabbix-ui / web-api», агент написал «zabbix-server / web-api» —
   имя взял, привязку потерял; ошибка «узел не найден» стоила лишнего круга
   ДВАЖДЫ (изолированный Zabbix и федерация). ФИКС: did-you-mean на ошибки
   резолва узлов в связях по образцу Ф8б — «узел «zabbix-server / web-api» не
   найден — есть «zabbix-ui / web-api»».
3. **Мягкий матч П3 дал ложную склейку.** `grafana-zabbix` (плагин: своё repo,
   host grafana) слился с `grafana-server` (ядро: repo grafana, host grafana) —
   совпадение host погасило противоречие repo; отсюда 6 из 12 схемных строк
   («имя/родитель/role/technology/description отброшено») и путаница ролей.
   ФИКС: гасить противоречие сильного поля совпадением слабого ТОЛЬКО если у
   одной из сторон сильного поля НЕТ. Проверено на обоих полевых кейсах:
   заглушка{host} + продукт{repo} склеятся (нужно), два содержательных с
   разными repo — раздельно (нужно).
4. **Связь «контейнер → собственный потомок» не имеет своего класса** (5 штук
   у Zulip, часть intermediate_edges у федерации). ФИКС: отдельное замечание
   «иерархия уже выражает вложенность: удалите связь или перевесьте её»
   вместо бессмысленного «уточните до компонента».
5. **Гонка П6**: скептик стартовал раньше, чем строитель сохранил
   `architecture.yaml` в корне — отчёт №1 холостой («файл отсутствует»), один
   круг аудита потерян. Прежде файл лежал в archmap-orch/, который оркестратор
   создавал сам. ФИКС: в шаг 3 обёртки — «убедись, что файл результата
   существует, прежде чем запускать скептика».
6. Правило П13 про technology не ловит трактовки («Symfony» при наличии только
   symfony/yaml) — сузить до «называй пакет, который реально в манифесте».

## Вердикт

Изолированные: **2 улучшения (Zabbix, Sentry), 1 деградация метрики (Zulip)**,
причина которой установлена и лежит вне тюнинга. Регрессий, вызванных фиксами,
не обнаружено; сентинелы байт-в-байт держат.
Федерация: **главная цель достигнута** — продукты собираются контейнерами и
склеиваются без перегонов и дожимов (4 из 6 критериев), но алерты и схемная
секция не упали из-за ложной склейки П3 и невыполненного раздела у одного
агента. Обе причины названы поимённо и лечатся кандидатами 1–3.

## Оговорки честности

- Прогоны мои, транспортом API с кнопочными текстами; клики по окнам не
  имитировались (состав действий 1:1 с UI-путём).
- Zulip и федерация не доводились до нуля алертов — матрица меряет путь при
  ФИКСИРОВАННОМ усилии (≤2 круга на файл), а не предельно достижимое.
- Каналы гонялись только для Sentry (доказать 0 алертов полным путём);
  у Zulip и федерации канальный поток не запускался — их broker_edge_channels
  (6 и 2) структурно ожидаемы.
- Сравнение с прежними раундами — по докам qa-zabbix-7/qa-zulip-brokers/
  qa-f8-validation/qa-multirepo-federation; условия совпадают по протоколу, но
  прогоны разные, дисперсия слабой модели значительна (2/3 на разделе П1 —
  прямая иллюстрация).
