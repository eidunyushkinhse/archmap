# Мультирепо-QA: федерация Zabbix 7 + Grafana 13 + плагин Зобнина (2026-08-15)

Задача пользователя: пройти пользовательский путь создания проекта из ТРЁХ
репозиториев (zabbix/zabbix, grafana/grafana 13.2.0-pre, alexanderzobnin/
grafana-zabbix) свежеслитым паттерном «строитель+скептик+валидатор» и выписать
инсайты. Протокол прежний: Haiku headless, один оркестраторный промпт с ручки
(variant=orchestrated, system_name=Zabbix+Grafana) на все три репозитория, как
велит спека; обратная связь — кнопочные тексты пофайловых замечаний Ф6; проект
«Zabbix+Grafana» (2255a2be) оставлен для приёмки.

## Ход

1. Три параллельных оркестраторных прогона (у каждого свои строитель и скептик,
   по 2 круга аудита у всех; Grafana — 22 419 файлов, масштаб выдержан). Финалы
   несут новую Ф5-строку «останутся замечания валидатора — пришлите их в этот
   же чат» — раздел обёртки дошёл до поля.
2. Тройное превью v1 → ГЛАВНАЯ находка: **система раздвоилась** (см. инсайт 1).
3. Перегоны Zabbix и Grafana с пользовательской подсказкой hints «оформи свой
   продукт контейнером, соседний — заглушкой» (штатное поле окна): Grafana
   послушалась (и выдала битый YAML — Н1-класс), Zabbix — наполовину (заглушку
   добавил, контейнер нет). Дожим Zabbix вторым сообщением в сессию — сработал.
4. Пофайловые круги замечаний по кнопочным текстам Ф6 (parse-ошибка файлу 2 —
   в ЕГО корзину; изоляции и контейнерные концы — владельцам). Превью v4: ok,
   склейки федерации собраны.
5. Создание проекта: 49 узлов / 39 связей / 4 склейки. Алертов 23 (9 сирот,
   11 контейнерных связей, 3 группы) — зеркало советующих остатков, обычная
   доводка руками/кругами; ноль здесь не целевой (см. инсайт 6).

## Инсайты

1. **Конвенция «имя системы = название проекта» ломается на ФЕДЕРАЦИИ
   продуктов.** Каждый агент растворяет свой продукт прямо в корне
   «Zabbix+Grafana»: компоненты Grafana (Frontend, NATS, Query Router) легли
   рядом с россыпью zabbix-*, а заглушки соседей («Grafana» у Zabbix-агента,
   корневой «Zabbix» у Grafana-агента) не нашли пары — Grafana существовала в
   проекте ДВАЖДЫ (заглушка + россыпь), Zabbix симметрично. Для «одной системы
   из микросервисов» конвенция работает (каждый сервис — законный ребёнок
   корня, склейка по заглушкам живёт — Ярмарка-кейс); для «двух продуктов под
   одной крышей» продукт обязан быть КОНТЕЙНЕРОМ под корнем. КАНДИДАТ:
   промпт сам учит мультипродуктовому случаю (абзац «проект объединяет
   несколько продуктов? свой продукт — контейнером с его именем, чужие — 
   заглушками на том же уровне»); UI-вариант — переключатель у окна создания.
2. **Штатный рычаг hints работает, но как полумера**: слабая модель исполняет
   подсказку частично (Grafana оформила контейнер, Zabbix — только заглушку
   соседа), дожимается вторым сообщением в живую сессию. Плюс перегон Grafana
   с hints сломал YAML (Н1: двоеточие в незакавыченном значении) — петля
   замечаний починила за круг; parse-ошибка легла в корзину СВОЕГО файла (Ф6).
3. **Якорная склейка source сильнее имён — в обе стороны.** «Server» (файл
   Zabbix) склеился с «zabbix-server» (плагин) по якорю при РАЗНЫХ именах и
   разных родителях — блестяще. Обратная сторона: два узла «grafana» с
   ПРОТИВОРЕЧАЩИМИ источниками остались раздельны («встречается в файлах как
   РАЗНЫЕ объекты») — защита от тёзок сработала против воссоединения продукта.
   КАНДИДАТ: заглушка (узел без детей и без source.repo) могла бы матчиться
   мягче — противоречие якорей считать только между двумя СОДЕРЖАТЕЛЬНЫМИ
   узлами.
4. **Ф6/Ф7 в первом реальном мультирепо отработали по назначению**: изоляция
   из узлов одного файла — его агенту (группа 4 узлов Grafana в v1, группы
   после переупаковки в v3); parse-ошибка — файлу; конфликты склеек, похожие
   имена, межфайловые контейнеры — схемной секции, включая живые Ф7-тексты
   («связь «Grafana → Server» (файл 1) упирается в контейнеры, компоненты
   которых описаны в файлах 1 и 2, — агент файла 1 их не видит…»). Пофайловые
   кнопки делают петлю ТРЁХ агентов управляемой — замечания не смешиваются.
5. **Порядок файлов решает конфликты склейки, и это неочевидно из UI**:
   заглушка «Grafana external: true» файла 1 победила настоящую Grafana
   (external: false, Go + React) только потому, что файл Zabbix шёл первым.
   КАНДИДАТ: при склейке «заглушка против содержательного» побеждать должен
   содержательный, а не первый; как минимум — подсказка в UI про порядок.
6. **Сходимость мультирепо медленнее одно-репо**: три слабых модели чинят
   каждая своё, контейнерные концы конвергируют лениво (связь уточняется до
   компонента частично), 2 круга на файл срезали часть, но не всё. Пользователь
   доводит руками или дополнительными кругами — 23 алерта на создании честно
   отражают остаток. Формула «ноль алертов гарантированно доводим» остаётся
   верной по механике, но ЦЕНА растёт с числом репозиториев.
7. **Сборные замечания при мульти деградируют в схемные**: «объектов без
   единой связи: 17» собирает сирот всех файлов в одну строку — общего
   файла-виновника нет, уходит пользователю, хотя каждый сирота чинится своим
   агентом. КАНДИДАТ: сборные списки генерить по-файлово (строка на файл).
8. Скептики всех трёх прогонов дали по два круга с доказательствами; шов
   «замечания валидатора в живую сессию оркестратора» работал во всех пяти
   кругах пути (точечные правки, файл проверялся).

## Оговорки честности

- Прогоны и круги — мои (транспортом API с кнопочными текстами); пользовательские
  клики по окнам не имитировались, но состав действий 1:1 с UI-путём.
- «Zabbix Manual»-сравнение: мультирепо-путь длиннее одно-репо на два перегона
  с hints и один дожим — вся дельта порождена инсайтом 1 (федерация), а не
  паттерном аудита.
- Проект создан с 23 алертами осознанно (советующие остатки; доводка руками —
  штатный финал пути); «Zulip Audit QA» с нулём остаётся эталоном одно-репо.
- Семантика содержимого (верность связей Grafana внутри) в этом раунде
  выборочно не сверялась с кодом — фокус раунда был на МЕХАНИКЕ федерации;
  скептики прогонов работали штатно.
