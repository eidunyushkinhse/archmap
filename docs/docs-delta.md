# Изменения продукта относительно docs.archmap.tech

Живой список того, что появилось или изменилось в ArchMap после написания
пользовательской документации (github.com/eidunyushkinhse/archmap-docs, русская версия
принята 2026-10-18). По нему обновляют сайт: пункт снимается, когда страница сайта
обновлена. Ведётся с 2026-10-23 по просьбе владельца; пополнять в том же коммите, что и
фича. У каждого раздела — какие страницы сайта затронуты (`user/…`, `architect/…`,
`admin/…` — папки `content/` репозитория документации).

## Снято 2026-10-27

Разделы 1–4 (статус страницы, версии документации, схема развёртывания Ф0–Ф6 с приёмкой)
перенесены на сайт коммитом документации 7e95770 (archmap-docs, 2026-10-27): пять новых
страниц («Посмотреть, где развёрнуты объекты», «Посмотреть прежние версии документации»,
«Разместить объекты по площадкам», «Согласовать страницу объекта», «Зафиксировать версию
документации и вернуться к ней»), правки смежных страниц, девять новых и пять переснятых
снимков экранов (в том числе «Свойства» с «Принадлежностью» и «Размещением»). Английская
версия не обновлялась (бэклог tasks.md).

## Снято 2026-10-28

MCP: файл с машины агента без перепечатки (2026-10-28, MCP 0.10.0, docs/plan-mcp-upload.md) —
инструмент `archmap_upload_url` (одноразовая ссылка на 10 минут, до 2 МБ, `curl -T` без токена
в команде), `{name, upload_id}` в `files` любого инструмента, эхо размера и sha256 у каждого
инструмента с файлами. На сайт НЕ переносится (решение владельца 2026-10-28): загрузку агент
делает сам по описаниям инструментов, а механика для того, кто подключает агента, описана в
`mcp/README.md` репозитория ArchMap. Раздел «Передать агенту большой файл», добавленный
коммитом 981a493 (archmap-docs), снят коммитом db4ed2e.

Синхронизация: каналы связей (починка по репорту с рабочего проекта, 2026-10-28) —
канал брокера и тип канала у связей переносятся из YAML (раньше терялись), связи одной пары
различаются каналом, у живой связи без канала он заполняется из YAML; в плане окна
**Обновить из репозитория** появилась группа **Изменённые связи**. На сайт перенесено
коммитом документации c0d905f (archmap-docs): список групп плана на `architect/sync.md`
называет новую группу. Аргумент `channel` у `archmap_update_edge` страницу MCP не меняет
(аргументы инструментов она не перечисляет).

## 7. Элемент архитектуры (эпик 2026-10-29, в работе)

На сайт — после приёмки эпика (Ф11 docs/plan-c4-elements.md); до неё пункты копятся здесь.
Страницы — перечень в §6.10 плана (`user/levels.md`, `architect/nodes.md` и смежные, новая
страница-понятие).

- Ф1 (2026-10-29): поле «Элемент архитектуры» в API и MCP. У объекта с вложенными хранится
  элемент (система, контейнер или «не задан» — читается как система), сервер отдаёт
  действующий элемент (система, контейнер, компонент). Правка с отказами: элемент задаётся
  только у сервиса и не внутри контейнера, в контейнере не может лежать база данных,
  брокер или другой контейнер. MCP: аргумент `element` у `archmap_create_node` и
  `archmap_update_node`, строка «Элемент архитектуры» в карточке `archmap_node`, пометка
  контейнера в дереве `archmap_schema`. В интерфейсе пока не виден.
- Ф2 (2026-10-29): элемент архитектуры в форматах обмена. Экспорт YAML и архив знания
  пишут `element: system | container` после `shape`, только если задан (без элементов —
  прежний документ, формат архива тот же). Ввоз файлом берёт поле как есть, а
  недопустимое снимает с замечанием в превью: элемент не у сервиса; элемент у объекта
  внутри контейнера (он компонент). База данных или брокер внутри контейнера выносится
  на уровень выше — к родителю контейнера (у корневого — на верхний уровень), контейнер
  остаётся; замечание называет новое место. Несколько файлов: «не задан» уступает
  значению, «Система» против «Контейнера» — вопрос «спор поля» в превью; замечание,
  когда файл положил объекты в чужой контейнер. Догрузка архивом и синк из репозитория
  доливают элемент только в пустое, расхождение — строкой отчёта; новую базу в живом
  контейнере создают уровнем выше (синк — строкой плана), живую базу не переносят.
- Ф3а (2026-10-29): конфигурация и спецификация — у ближайшего контейнера. Пометка
  «зависит от:» в схеме компонента находит параметр контейнера; подсказка редактора
  схемы подписывает его «Конфигурация «orders» · X». Под параметром строка «зависит:»
  перечисляет схемы контейнера и его компонентов, схему компонента — с его именем.
  Замечание «Обращения к неописанным параметрам» называет контейнер, где искали, а у
  схемы системы советует перенести её контейнеру или компоненту. Промпт для агента со
  страницы компонента показывает параметры контейнера. Ввоз конфигурации предлагает
  адресами контейнеры и предупреждает, если адрес — система или компонент. Спецификация
  из пакета для компонента ложится его контейнеру (строка в превью), у системы —
  остаётся с предупреждением. Предупреждения ввоза схем и перечня операций говорят
  «система» или «контейнер с компонентами».
- Ф3б (2026-10-29): рекомендации и статус страницы по элементу. Для страницы
  `architect/alerts.md` (таблица классов и вводная): классов 16; заголовки «Связи в
  систему или контейнер» (было «Связи в контейнер»), «Связи с собственной частью» (было
  «Связи в собственный компонент»), «Системы и контейнеры со своей документацией» (было
  «Контейнеры со своей документацией»), «Пользователи внутри системы» (было
  «Пользователи внутри контейнера»), новый «Конфигурация и спецификации у компонентов».
  У «Систем и контейнеров…» серый совет по элементу: у системы — «спецификация,
  конфигурация и схемы логики описывают её контейнеры — перенесите их вложенным
  объектам», у контейнера с компонентами замечание только на свои схемы логики —
  «схемы логики описывают код компонентов — перенесите их компонентам» (спецификация и
  конфигурация у контейнера — норма). Новый класс: строка «api · конфигурация,
  спецификация», серым «место — у контейнера «orders»». Те же слова в `archmap_alerts`.
  Для страниц про статус страницы (`architect/nodes.md` и смежные): статус свой у
  контейнера (в том числе с компонентами) и компонента, у системы складывается из всех
  вложенных объектов, кроме вложенных систем, — подсказка «Статус системы складывается
  из вложенных объектов», счётчик «N из M» по ним же; карточка `archmap_node` — та же
  строка.
- Ф4 (2026-10-29): размещение по единицам. Для страниц про схему развёртывания и
  размещение (холст «Развёртывание», окно «Размещение», булавка в дереве, ввоз и
  экспорт площадок) и для MCP (`archmap_deployment`, `sites` у `archmap_update_node`):
  площадки задаются контейнеру — листу вне контейнера или контейнеру с компонентами; у
  компонента размещения нет — отказ «Площадки задаются контейнеру: «api» — компонент
  контейнера «orders»», в YAML `sites` у компонента пропускаются с замечанием
  «размещение задаётся контейнеру «orders» — площадки у компонента пропущены». Систему
  размещают целиком — набор получают её контейнеры. На холсте контейнер с компонентами
  — одна сплошная карточка, компоненты не рисуются; пунктир и число внутри — только у
  цельной системы (число её контейнеров); уровень открывается только у системы, у
  контейнера — «Внутри контейнера «orders» отдельного размещения нет: компоненты
  развёртываются вместе с ним». У компонента в дереве нет булавки, щелчок по нему
  показывает его контейнер. Подтверждения: «Все вложенные объекты будут размещены там
  же, включая те, что сейчас стоят на других площадках:» и «Размещение всех вложенных
  объектов будет снято:». Рекомендация «Конфигурация и спецификации у компонентов»
  называет и «площадки» компонента. MCP: «Без размещения» — только контейнеры, у
  компонента — «Размещения нет: это компонент — площадки задаются контейнеру «orders»».

## 6. Алерт «Контейнеры со своей документацией» теперь видит и конфигурацию (2026-10-28)

Страницы: `architect/alerts.md` (строка таблицы про этот алерт). Пилот документирования
(четыре починки, tasks.md «Сделано» 2026-10-28): контейнер — не владелец конфигурации,
AL24 замечает параметры у контейнера (`has_config`), промпт конфигурации предлагает
адресами только листовые сервисы, превью ввоза предупреждает о владельце-контейнере.
На сайте строка таблицы объясняет алерт только схемами логики и спекой и советует
«Распределить по детям» — параметры этой кнопкой не переносятся, их описывают заново у
компонентов. Нужна одна фраза в объяснении и в совете; решение владельца — править ли
(остальные три починки пользователь на сайте не видит: предупреждения превью, предел
загрузок и ключ происхождения спеки сайт не описывает).
