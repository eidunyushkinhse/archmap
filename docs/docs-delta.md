# Изменения продукта относительно docs.archmap.tech

Живой список того, что появилось или изменилось в ArchMap после написания
пользовательской документации (github.com/eidunyushkinhse/archmap-docs, русская версия
принята 2026-10-18). По нему обновляют сайт: пункт снимается, когда страница сайта
обновлена. Ведётся с 2026-10-23 по просьбе владельца; пополнять в том же коммите, что и
фича. У каждого раздела — какие страницы сайта затронуты (`user/…`, `architect/…`,
`admin/…` — папки `content/` репозитория документации).

Разделы 1–4 (статус страницы, версии документации, схема развёртывания Ф0–Ф6 с приёмкой)
перенесены на сайт коммитом документации 7e95770 (archmap-docs, 2026-10-27): пять новых

## Снято 2026-10-28

MCP: файл с машины агента без перепечатки (2026-10-28, MCP 0.10.0, docs/plan-mcp-upload.md) —
инструмент `archmap_upload_url` (одноразовая ссылка на 10 минут, до 2 МБ, `curl -T` без токена
в команде), `{name, upload_id}` в `files` любого инструмента, эхо размера и sha256 у каждого
инструмента с файлами. На сайт НЕ переносится (решение владельца 2026-10-28): загрузку агент
делает сам по описаниям инструментов, а механика для того, кто подключает агента, описана в
`mcp/README.md` репозитория ArchMap. Раздел «Передать агенту большой файл», добавленный
коммитом 981a493 (archmap-docs), снят коммитом db4ed2e.

Синхронизация: каналы связей (починка по репорту с рабочего проекта, 2026-10-28) —
канал брокера и тип канала у связей переносятся из YAML (раньше терялись), связи одной пары
различаются каналом, у живой связи без канала он заполняется из YAML; в плане окна
**Обновить из репозитория** появилась группа **Изменённые связи**. На сайт перенесено
коммитом документации c0d905f (archmap-docs): список групп плана на `architect/sync.md`
называет новую группу. Аргумент `channel` у `archmap_update_edge` страницу MCP не меняет
(аргументы инструментов она не перечисляет).

## 10. Связи без повторов (2026-11-02)

Идея владельца 2026-10-29: одноимённые связи не повторяются ни на схеме, ни на странице объекта.

- Подпись стрелки, на которую легли несколько связей (свёрнутая система, контекст схемы
  проекта, схема на странице объекта), перечисляет РАЗЛИЧНЫЕ подписи: десять связей
  «пользуется» от пользователя к разным объектам системы дают один пункт «пользуется», а не
  десять одинаковых строк. Если подпись у всех связей одна, стрелка подписана как обычная
  связь, без маркера списка. Двойное нажатие на подпись по-прежнему открывает окно
  **Выберите связь** со всеми связями. При раскрытой системе у каждой стрелки своя подпись,
  как и раньше.

Затронутые страницы сайта (`grep -rn 'Связи' content`, только перечень, сайт не правился):
`user/edges.md` (раздел «Просмотреть связи на схеме»: подпись стрелки и окно **Выберите
связь**, шаг 4), `architect/edges.md` (раздел «Изменить или удалить связь», шаги 1–2).
