# Эксперимент: порог уверенности скептика (2026-08-15)

Вопрос: какой формулировкой порога уверенности снабдить промпт агента-скептика
(будущая фича «аудит пакета вторым агентом»), чтобы давить ложные сомнения, не
теряя настоящих. Метод — «стенд» с известными ответами: эталонный
architecture.yaml по Zulip, где статус КАЖДОГО утверждения известен из
семантического аудита — 6 подсаженных конфабуляций полевых классов и ~9 истинных
утверждений-ловушек (включая «tornado потребляет notify_tornado» — то, на чём
скептик соврал в оркестровом эксперименте). Вход фиксирован, варьируется ТОЛЬКО
блок порога в промпте. Haiku, 18 прогонов (V0/V1 по 6, V2/V3 по 3).

Подсажено: узел Elasticsearch (+ребро «индексация»); «Redis хранит сессии»;
corporate → django-api «по HTTP» (один процесс); tornado → БД «читает события»
(нарушение ядра дизайна); несуществующая очередь «emails_queue»; технология
«Angular» у web.

## Варианты порога

- **V0** — без порога (базовые правила: доказательство при вердикте, «не выдумывай
  ради объёма»).
- **V1** — «сомнение только при конкретном доказательстве (цитата строки или пустой
  поиск); умозаключения не записывай; не уверен — молчи: пропущенное сомнение
  дешевле ложного».
- **V2** — жёсткий протокол: «не существует» только после трёх разных поисков с их
  перечислением; «неверно» только с цитатой; недотянувшее — в секцию-карантин
  «НЕ ПРОВЕРЕНО».
- **V3** — «адвокат автора»: перед каждым сомнением обязан поискать сильнейшее
  подтверждение утверждения; нашёл — сомнение не пишется.

| Вариант | n | Полнота (пойма́но подсаженного) | Ложные сомнения | Разброс по прогонам |
|---|---|---|---|---|
| V0 | 6 | **27/36 = 75%** | **0** | 3–6 из 6 |
| V1 | 6 | **26/36 = 72%** | **0** | 3–6 из 6 |
| V2 | 3 | 9/18 = 50% | **2** (единственные в эксперименте) | 2–4 |

По классам подсаженного (доля прогонов, поймавших; все 18):
Angular — 18/18; emails_queue — 18/18; Elasticsearch — 13/18; tornado→БД — 13/18;
Redis-сессии — 9/18; corporate-HTTP — **4/18**.

## Выводы

1. **Базовая ложноположительность изолированного скептика — около нуля.** 17 из 18
   прогонов не дали ни одного ложного сомнения даже без порога; ни один не тронул
   ловушку «tornado потребляет notify_tornado». Ложное сомнение оркестрового
   эксперимента было, по-видимому, наведено большим документом/дисперсией, а не
   систематикой. Страх «скептик конфабулирует симметрично строителю» на чистом
   стенде НЕ подтвердился.
2. **Жёсткий порог вреден — эффект Гудхарта.** Оба ложных сомнения эксперимента
   родил именно V2 (придирка к конвенции направления стрелок; придирка к имени
   компонента), и он же провалил полноту: Elasticsearch ушёл в карантин
   «НЕ ПРОВЕРЕНО» вместо сомнения (модель не хочет платить «три поиска» и
   складывает туда настоящую ложь), один прогон закруглился «остальное
   подтверждено» скопом. Ритуал доказательства вытесняет суть.
3. **V0 и V1 статистически неразличимы** (75% против 72% при разбросе 3–6 на обоих);
   преимущество V1 в первой тройке прогонов было шумом. Полноту лимитирует не
   порог, а способность НАЙТИ: классы ловятся тем хуже, чем дальше проверка от
   «grep имени» (имена — 18/18, «что где хранится» — 9/18, «один ли это
   процесс» — 4/18).
4. **Выбор: V1.** При равной полноте и нулевых FP он бесплатен и страхует ровно тот
   режим, где ложные сомнения наблюдались в поле (большой документ, длинная
   сессия, контекстное давление) — правило «умозаключение — не сомнение; не
   уверен — молчи» стоит одну строку. V2 отвергнут с доказательствами, V3 —
   цена без выгоды (и риск самоуспокоения адвокатом).
5. **Главный рычаг качества скептика — не порог, а чек-лист целей** (урок «цели с
   ответом» в третий раз): слабые классы надо называть в промпте поимённо с
   методом проверки — «связь по HTTP между частями одной кодовой базы: проверь,
   не один ли это процесс (INSTALLED_APPS, wsgi, монтирование urls)»; «каждое
   „хранит X“ в описании узла-хранилища: найди настройку, которая это
   доказывает (SESSION_ENGINE, CACHES, …)». Это пойдёт в дизайн промпта скептика
   фичи.

## Оговорки честности

- n=3 у отвергнутых вариантов: для V2 вывод устойчив (провал и по полноте, и по FP,
  и механизм виден в текстах отчётов), для V3 «цена без выгоды» — направленный
  сигнал, не строгая статистика.
- Стенд измеряет изолированного скептика на компактном документе (12 узлов /
  12 связей); поведение на больших документах и внутри оркестровой петли может
  отличаться — V1-страховка выбрана в том числе на этот случай.
- Один и тот же эталон для всех прогонов: возможна специфика именно этих шести
  классов; классы выбирались по реальным полевым конфабуляциям двух проектов.
