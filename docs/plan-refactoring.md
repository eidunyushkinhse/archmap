## 3. Риски

### 3.1. Если НЕ рефакторить
- God-компоненты растут (NodePage уже 1088, LevelGraph 1677) — каждое изменение
  дороже, локальные правки задевают 20 ответственностей.
- UI без тестов → КАЖДОЕ изменение проверяется только глазами пользователя
  (так уже происходит — ручное тестирование после каждого блока).
- Нет CI → коммит с поломанным гейтом возможен с любой другой машины/агента
  (`--no-verify`, чужой клон); solo-проект с ИИ-агентами особенно уязвим.
- CLAUDE.md устарел → агенты на Claude получают неверный контекст (команды,
  сущности) и наступают на грабли.
- Дублирование стилей/тостов → расползание дизайна при каждом новом экране.

### 3.2. Риски САМОГО рефакторинга (чем рискуем, подгоняя под стандарты)
- **Декомпозиция LevelGraph без UI-тестов** — главный риск: оркестрация
  (драг/персист/undo/locate) не покрыта ничем, кроме глаз; разбор god-object'а
  вслепую может сломать канвас — ядро ценности продукта. → Митигация: декомпозиция
  ТОЛЬКО после фазы 2 (рендер-тесты).
- **Включение TS strict на 31k строк** — лавина ошибок strictNullChecks; фиксы в
  UI без тестов = риск регрессий. → Митигация: strict после фазы 2, чинить по модулям.
- **Удаление легаси (TreePage)** — потеря единственного входа BYOA «Доки от агента»
  и фронт-поверхности алертов. → Митигация: удаление ТОЛЬКО после переноса обеих
  фич (хвосты (б) + решение по BYOA).
- **Дедупликация inline-стилей** — визуальные регрессии (пользователь проверяет
  глазами). → Митигация: мелкими порциями, с глазной проверкой.
- **Извлечение домена из nodes.py** — низкий риск: 174 бэк-теста покрывают.
- **CI** — рисков нет, чистый выигрыш (можно в любой момент).
