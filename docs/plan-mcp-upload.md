# План «Файл с машины агента без перепечатки» (2026-10-28 — ВЫПОЛНЕН в тот же день, ветка feat/mcp-upload)

По репорту агента пользователя с рабочего проекта (28.10): удалённый MCP принимал файлы
только текстом внутри вызова (`files: [{name, content}]`), то есть модель перепечатывала YAML
заново. На файле 72 КБ превью показало 204 связи вместо 205 и искажённые подписи, пять файлов
на 151 КБ в один вызов не поместились вовсе, а контрольной суммы полученного никто не отдавал.
Локально `paths` были только у импорта и архивов.

## Решения

1. **Канал загрузки — одноразовая ссылка, а не токен в команде.** `POST /api/v1/uploads`
   (владелец по токену или сессии) выдаёт путь с ключом (256 бит, в БД только sha256,
   срок 10 минут); `PUT` по ссылке без аутентификации принимает файл потоком с потолком
   `UPLOAD_MAX_MB` (по умолчанию 2 МБ) и отвечает `size` и `sha256`; `GET /uploads/{id}` отдаёт
   принятый текст владельцу. Токен агента в shell-команду и историю не попадает.
2. **Одноразовая — ссылка, не загрузка.** Превью и применение читают одни и те же входы,
   поэтому загрузка живёт до срока и читается сколько угодно; повторный `PUT` по той же
   ссылке — 409. Это поправка к репорту, который предлагал «до первого использования».
3. **Подмена `upload_id` → текст на стороне MCP.** Удалённый сервер живёт в процессе
   бэкенда и забирает содержимое `GET /uploads/{id}` токеном вызывающего; эндпоинты
   импорта, синка, доков, разведки и фактов не меняются. `files` принимает `{name, content}`
   и `{name, upload_id}` вперемешку.
4. **Адрес ссылки — глазами агента.** Удалённо запросы в API идут по внутреннему адресу, а
   ссылку агент откроет сам: `remote.public_base_of` берёт `X-Forwarded-Proto`/`-Host`
   (nginx поставки, Ingress) или схему и `Host` запроса `/mcp`; локально — `ARCHMAP_URL`.
   Новой настройки с публичным адресом не потребовалось.
5. **Эхо целостности у всех инструментов с файлами** — размер и sha256 каждого входа и
   каким путём он пришёл (текстом вызова, загрузкой, с диска). Считается в MCP от того,
   что реально дошло: расхождение с `sha256sum` у агента — сигнал перепечатки с ошибками
   (оговорка в тексте: хвостовой перевод строки тоже меняет хеш).
6. **Локально `paths`** у синка, доков, разведки и фактов — текстовые файлы встают в `files`
   под своим именем (`_read_input`, предел 64 МБ). У импорта `paths` остаётся своим (yaml + zip).
7. **Хранение в БД** (таблица `uploads`, миграция `74b412a21668`): воркеров несколько,
   рестарты бывают; просроченные строки чистятся при каждой новой ссылке; живых загрузок у
   пользователя не больше 16; неудачные `PUT` ограничены по адресу (30 в минуту); в демо-режиме
   выключено.
8. **Удалённые схемы строятся из локальных** (`_remote_schema`): аргументы-пути убраны,
   `files` — вариант без слов о диске и обязателен там, где локально его заменяли `paths`.

## Что отвергнуто

- base64 частями через MCP — та же генерация моделью; MCP resources — у клиента нет
  стандартного способа приложить файл к вызову инструмента; передача токена в `curl` —
  секрет в истории shell и журналах.

## Состав

- бэкенд: `app/uploads.py`, `app/routers/uploads.py`, `app/models/upload.py`,
  `app/schemas/upload.py`, настройка `upload_max_mb`, миграция; тесты `tests/test_uploads.py`
  (ссылка → PUT → GET, одноразовость, срок, предел по заголовку и по потоку, чужая загрузка,
  непринятая, не-UTF-8, демо и «только чтение», предел живых, лимит неудачных PUT, ключ не в БД);
- MCP 0.10.0: `archmap_upload_url` (37-й инструмент, удалённо 34), `_resolve_files` +

  подстановка по `upload_id`, эхо, `paths` локально, отказы, публичный адрес из заголовков);
- документация: `mcp/README.md` («Файлы с машины агента»), страница «Подключить своего
  агента через MCP-сервер» на сайте, spec.md, docs-delta, tasks.md.

## Проверка

Живой прогон на dev-стенде: `archmap_upload_url` → `curl -sS -T repo-a.yaml <ссылка>` →
`archmap_import_preview` с `{name, upload_id}`: sha256 в ответе загрузки, в эхе превью и у
`sha256sum` совпали; повторный `PUT` — 409; содержимое прочитано владельцем.

## Открытое

- Helm-чарт не задаёт предел тела запроса у Ingress (у nginx-ingress по умолчанию 1 МБ):
  это касалось и ввоза архивов до этого эпика; при жалобе — аннотация
  `nginx.ingress.kubernetes.io/proxy-body-size` в values.
- Бинарные файлы (zip) по ссылке не принимаются к инструментам: `GET /uploads/{id}` отдаёт
  текст, а архивы удалённо по-прежнему ввозят в интерфейсе.
