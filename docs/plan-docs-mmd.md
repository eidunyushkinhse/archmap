# Переезд «Доки от агента» на .mmd без манифеста — план

**СТАТУС: фазы 0–5 сделаны кодом 2026-08-08, ждут ручной проверки.** Порядок работ —
`docs/plan-work-2026-08-08.md` (шаг 3).

Решение принято 2026-08-08. Пакет агента перестаёт быть YAML-манифестом: агент
кладёт N самодостаточных `.mmd`-файлов, окно спеки принимает один файл спеки.
Обратной совместимости не держим — манифест уходит целиком (внешних
пользователей нет, дублировать два формата дороже, чем переписать один).

## Зачем

- Mermaid внутри YAML — главное место отказа слабой модели: литеральный блок с
  отступами, кавычки и двоеточия в подписях. Файл `.mmd` этой проблемы не имеет.
- Метаданные едут ВНУТРИ содержимого, поэтому перетаскивание файла и вставка
  текста из буфера работают одинаково. С манифестом вставка текстом была
  полумерой (пакет — это минимум два артефакта).
- `.mmd` — обычный файл: рендерится в IDE и на GitHub, человек видит его в
  репозитории без ArchMap.
- Исчезает связка «имя файла ↔ ссылка в манифесте»: имя схемы живёт в шапке,
  поэтому файл может называться как угодно и коллизий имён не бывает вовсе.

## Целевой контракт

Файл `archmap-docs/<что угодно>.mmd`:

```
%% archmap-name: Приём заказа
%% archmap-kind: operation
%% archmap-operation: POST /orders
%% archmap-node: orders-db
graph TD
  A["Приём запроса"] --> B["Валидация корзины"]
```

- Шапка — только ВЕДУЩИЕ строки-комментарии до первой строки диаграммы.
- Все поля необязательны. Деградация: `name` → имя файла без расширения;
  `kind` → `overview`; `node` → объект, из окна которого открыт импорт.
  Ничего из этого не блокирует импорт, всё правится в превью.
- `archmap-node` — путь/имя узла в поддереве объекта окна (тот же резолвер, что
  у манифеста: полный путь « / », голое имя, однозначный хвост).
- Идентичность схемы прежняя: (узел, имя). Дубль внутри одного пакета — ошибка.

⚠️ **Ловушка:** `%%{init: …}%%` — это ДИРЕКТИВА mermaid, а не комментарий.
Парсер шапки обязан брать только строки с префиксом `%% archmap-`, иначе
поломает конфигурационные директивы агента.

Окно спеки: пакет — один файл спеки (`.yaml`/`.json`), объект известен из окна.
Поле `origin` (нашлась / сгенерирована / синтезирована) — либо строкой
`# archmap-origin: generated` в самой спеке, либо убрать как информационное.
Чекбокс «Перезаписывать занятые» из окна спеки убирается, на бэк уходит
`overwrite=true` всегда: спека у объекта одна, замена и есть смысл окна.

## Лимиты

Сейчас разъезд: бэк режет пакет на 32 файла, фронт на 16 — это баг и сегодня.

| Что | Было | Станет |
|---|---|---|
| Файлов в пакете (бэк / фронт) | 32 / 16 | 100 / 100 |
| Схем на объект | 50 | 100 |
| Одна диаграмма | 200 000 символов | без изменений |
| Пакет целиком | потолка НЕТ | 16 МБ |

Общий потолок обязателен: сто файлов по 2 МБ сегодня уедут одним POST.

## Фазы

Каждая фаза — отдельный коммит с зелёным гейтом.

### Фаза 0 — шапка как чистая функция
`backend/app/mmd_header.py`: разбор ведущих `%% archmap-*` строк →
`(name, kind, operation, node)` + признак, что шапки не было. Содержимое схемы
сохраняем ЦЕЛИКОМ, вместе с шапкой: так повторная заливка того же файла
идемпотентна, а экспорт не теряет данные.
**Якорь от протухания:** образец шапки хранится ДАННЫМИ и прогоняется через
парсер тестом — тот же приём, что держал пример манифеста в docs_prompt.py.
Иначе через месяц промпт будет учить одному, а парсер ждать другого.

### Фаза 1 — бэкенд логики: приём файлов вместо манифеста
- `docs_import.py`: `build_docs_plan(node, files, …)` вместо
  `(nodes, manifests, assets, overwrite)`; `parse_manifest`/`ParsedManifest`/
  `assets` уходят. Резолвер узлов (`by_path`/`by_bare`/хвост) переиспользуется
  как есть — он не про манифест, а про адресацию.
- Канал правок из превью: сегодня вид схемы правится ПЕРЕЗАПИСЬЮ текста
  манифеста на фронте (kindOverrides). Без манифеста нужен структурный канал —
  `overrides: [{file, name?, kind?, node?}]` в запросе применения.
- Лимиты из таблицы выше + потолок пакета.
- Тесты `test_docs_import.py` переписываются.

### Фаза 2 — промпт под .mmd
- Агент создаёт `archmap-docs/*.mmd`, по файлу на логический процесс, с шапкой;
  в финальном ответе ПЕРЕЧИСЛЯЕТ созданные файлы (сегодня посылка атомарна —
  один манифест; N файлов легко захватить мышью не полностью).
- Правило именования файлов сводится к «латиницей, коротко» — имя схемы живёт
  в шапке, поэтому промахнуться мимо ссылки больше нельзя.
- Пример .mmd хранится данными и парсится тестом (см. Фазу 0).
- Тесты `test_docs_prompt.py` переписываются.

### Фаза 3 — фронт: окно логики
Переработка `DocsAgentModal` под список файлов без манифеста: превью строкой на
файл с правкой имени/вида/объекта. Сюда же целиком уезжает находка №7 ручной
проверки (тексты окна) — отдельным заходом её делать нельзя, разметка меняется.

### Фаза 4 — окно спеки
Бэк: приём одного файла спеки без манифеста, `overwrite=true` всегда, решение по
`origin`. Фронт: убрать чекбокс, тексты находки №8.

### Фаза 5 — стенд и замер — СДЕЛАНА

Прогон нового промпта слабой моделью (haiku) по стенду, репозиторий `repo-vote`:

| Что мерили | Результат |
|---|---|
| Файлов создано | 2 (`get-index.mmd`, `post-vote.mmd`) |
| Шапка разобрана без замечаний | 2 из 2 |
| Вид и операция проставлены верно | 2 из 2 (`operation`, `GET /`, `POST /`) |
| Лишний «%% archmap-node» | 0 (обе схемы про основной сервис — адрес и не нужен) |
| Файлы перечислены в финальном ответе | да |

То есть слабая модель формат берёт с первого раза — и это ожидаемо: писать
комментарий в начале файла проще, чем выдерживать отступы литерального блока
YAML, на которых она и ломалась.

#### Исходная формулировка
Прогон промпта по стенду волны 3 (`docs/plan-qa-2026-08-08.md`) слабой моделью:
доля файлов с корректной шапкой, доля схем, доехавших без ручной правки, против
нынешнего формата. Без замера правка промпта остаётся верой.

Прогон нужен свой: волна 3 плана QA правит ДРУГОЙ промпт — `import_prompt.py`
(схема из репозитория: акторы, компоненты без связей, честность рёбер), а здесь
`docs_prompt.py`. Разные модули, разные метрики; делать вместе не обязательно.
(Ранняя оценка утверждала обратное — это была ошибка.)

## Что теряем осознанно

- Атомарность посылки: был один файл, стало N. Смягчение — перечень файлов в
  ответе агента и счётчик принятого в окне.
- Возможность задокументировать за прогон произвольный узел проекта: адрес в
  шапке ограничен поддеревом объекта окна. Это и раньше было так по промпту
  (в задание кладётся срез поддерева), но манифест технически позволял больше.
