# QA-прогон: документируем Zabbix 7 через Haiku (2026-08-13)

Полевой тест всей BYOA-связки на чужой большой системе слабой моделью — «как хорошо
пользователь смог бы задокументировать Zabbix 7 на текущем ArchMap».

## Условия

- Репозиторий: zabbix/zabbix, ветка release/7.0 (коммит 430aea1), shallow, 355М (C,
  PHP-фронт, Go agent2, схема БД на ~200 таблиц в database/{mysql,postgresql}).
- Агент пользователя: Haiku (claude CLI, headless, свежая сессия на каждый основной
  промпт, `--continue` для замечаний).
- Жёсткие правила: агенту давались ТОЛЬКО промпты ArchMap; каждый промпт ≤2 прогонов;
  никаких правок выдачи руками — файлы грузились как есть (включая преамбулы и fence);
  обратная связь — только текстами штатных кнопок «Скопировать замечания».
- Путь пользователя: «Из репозитория» (system_name=Zabbix 7, depth 3, ru) → проект;
  страница корня → «Доки от агента» (пакетом, logic, ru); страница узла mysql →
  «Описать структуру». Итог остаётся в проекте «Zabbix 7» (b0b82b79) для приёмки.

## Итоговое состояние проекта

- **Архитектура**: 27 узлов (система, server с 8 компонентами, agent/agent2, ui,
  web-service, java-gateway, 3 узла-БД, акторы и внешние сервисы), 27 связей.
- **Логика**: 19 схем (16 операций + 3 обзора) по 6 узлам, все с паспортами и
  осмысленным содержанием (trapper/preproc/escalator/discovery/poller/connector,
  agent2, ui, web-service).
- **Данные**: 203 таблицы / 1570 колонок на узле mysql — полная схема Zabbix, с PK,
  обязательностью и расшифровками enum-подобных значений.
- **Связка пометки→структура РАБОТАЕТ сквозь двух разных агентов**: обратный индекс
  mysql — 68 строк из 11 схем, 22 таблицы с обращениями (топ: hosts 8, items 8,
  triggers 7, events 6); колоночных обращений 2 (честно по промпту «не выдумывай»).
- **Алерты**: AL29 — 46 (все unknown_table), AL8 промежуточные рёбра — 2, изолированные
  группы — 2, AL24 доки у контейнера — 2.

**Вердикт**: пользователь ПОЛУЧАЕТ задокументированный Zabbix за ~9 обращений к слабой
модели, но платит пять раундов переписки за импорт и почти теряет структуру БД (спасла
случайность — потерянная решётка комментария). Самое ценное: пометки, написанные одной
сессией Haiku в диаграммах, резолвятся в структуру, залитую другой сессией, — пивот
выдержал полевой тест.

## Находки (кандидаты в бэклог, по убыванию веса)

1. **Промпт данных не знает узлов проекта.** Промпт доков несёт срез схемы — 19/19
   схем легли точно; промпт данных среза не несёт — Haiku дважды выдумал адрес
   («Zabbix Storage», потом контейнер). Фикс: параметризовать промпт данных
   узлами-БД проекта (то самое предложение из дизайн-обсуждения пивота).
2. **Имена в пометках и имена в структуре пишут РАЗНЫЕ сессии** — и они расходятся:
   пометки «action, action_condition, action_operation» против таблиц схемы
   «actions, conditions, operations». 46 алертов AL29 — в основном этот класс плюс
   не-БД I/O. Гипотеза: промпт доков должен велеть СВЕРЯТЬ имена с миграциями
   (или пометки писать тем же прогоном, что читает схему БД).
3. **Слитный маркер «читает/пишет:»** — естественная для языка форма; парсер берёт
   из неё только «пишет», читающая половина факта молча теряется. Дёшево научить
   парсер обеим пометкам разом (+ запрет в промпте).
4. **БАГ: дозаливка данных обходит правило «у контейнера структуры не бывает»** —
   CRUD отдаёт 409, а build_data_plan молча планирует таблицы на контейнер, при том
   что UI рендерит секцию «Структура» только на shape=database: применённое стало бы
   невидимым. Тот же класс: docs-import позволил обзорные доки контейнерам
   (zabbix-server, zabbix-agent2) — итог AL24×2. Импорт-пути должны энфорсить те же
   правила формы, что CRUD.
5. **Петля замечаний не лечит YAML-квотинг на слабой модели**: «исправь строку 29» →
   добросовестная перепечатка с той же ошибкой (исправил со второго раза). Текст
   ошибки импорта должен подсказывать лечение («возьмите значение с „: “ в кавычки»),
   как это уже делает data_import после своего урока.
6. **Лесенка ошибок**: битый YAML прячет проверки рёбер; каждая вскрытая ступень —
   отдельный поход к агенту (5 раундов на импорт). Частично лечится п.5; радикальнее —
   пре-квотинг «: » на нашей стороне до парсера.
7. **Пометки на не-таблицах** («/proc/*», «конфиг», «metrics to trapper»,
   «history_cache») — Haiku пометил любой I/O; всё это унеслось в AL29 как шум.
   Промпту доков нужен явный периметр: пометка — только про таблицы БД.
8. **«Объект не найден» не называет допустимых** — слабая модель гадает вслепую.
   Перечислить в ошибке узлы-БД проекта (их 1–3).
9. **Альтернативные бэкенды = параллельные узлы**: mysql, postgresql, elasticsearch
   как три БД одной инсталляции. Промпту импорта нужен пункт «варианты одного слота —
   один узел, а не N».
10. **Номер строки в ошибке YAML** считается от начала fenced-блока и не совпадает с
    тем, что видит пользователь в своём буфере (преамбула агента). Мелочь, путает.
11. Haiku изобретает свои заголовки («archmap-kind: storage») — толерантный разбор
    их молча съел, это правильно; но потерянная решётка у archmap-node превращает
    адрес в невидимый YAML-ключ — тоже молча. Возможно, предупреждение «в файле есть
    ключ archmap-node, но адресом он не является».

## Ограничения прогона

Один прогон, одна модель, один репозиторий; спеки OpenAPI и процессы не гонялись
(не в скоупе ожиданий). Проект «Zabbix 7» оставлен в базе как есть — можно смотреть
глазами; тестовые артефакты (выдачи Haiku, протокол) — в скратчпаде сессии.

## Что осталось и что вскрылось нового

- **Замечание «объекты без связей» на слабой модели лечится ампутацией**, и это
  воспроизвелось дважды: раунд 1 — 31→27 узлов, раунд 2 — 30→14 (срезан почти весь
  слой компонентов). Текст промпта сам подталкивает («не создавай компонент без
  связей»). Гипотеза: предупреждение о висячих НЕ предлагать агенту вовсе (оставить
  человеку и алертам) либо формулировать «наЙДИ связи, удаление — крайняя мера».
- Остаточные AL29 — настоящие расхождения имён с DDL (Haiku не проверил hosts_tags
  против host_tag и т.п.) плюс казус «history_str и т.д.» — «и т.д.» внутри списка
  пометки стало ссылкой. Класс «имена из головы» правкой промпта сжат 46→7, но не
  обнулён: слабая модель правило «открой DDL и проверь» выполняет не всегда.
- Колоночных обращений 0 (в раунде 1 — 2): точность на уровне таблиц. Честно по
  правилу «не выдумывай», но потолок пользы ниже желаемого.
- Цена улучшения глубины: v2-архитектура беднее (14 узлов против 27) — совокупность
  ампутации висячих и меньшей охоты Haiku к слою компонентов в этом прогоне.

## Вердикт раунда 2

Целевые классы ошибок закрыты: адресация структуры — с первого раза, YAML — с
первого раза, шум алертов упал в 6.4 раза, ER рендерится. Открытые направления —
«ампутация вместо связывания» и глубина/стабильность слоя компонентов (обе — про
поведение слабой модели на замечаниях, а не про валидацию).
