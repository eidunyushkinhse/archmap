# Ф8: тюнинг BYOA до нуля алертов + валидация на Sentry и Zulip (2026-08-14)

Задача пользователя: дотюнить BYOA-промпты так, чтобы свежие прогоны Haiku на тех же
Sentry и Zulip дали проекты БЕЗ алертов. Итог: **«Zulip v2» (6035b6e4) — 0 алертов,
«Sentry v3» (95b0dfc5) — 0 алертов**; оба описаны Haiku по промптам ArchMap, обратная
связь — только тексты штатных кнопок/окон. Промежуточный «Sentry v2» (34000568,
2 алерта изолированных групп — стадия до Ф8з) оставлен в базе для сравнения; удалить
после приёмки.

## Хроника валидации

**Zulip v2** (10+ обращений к Haiku): импорт 41/48 за 2 круга («исчезли: никто»);
каналы 18/68 — минимум Ф8д покрыт целиком, включая notify_tornado (в v1 — 9 AL30);
данные 53→54 таблиц; доки 30 схем: Ф8а-каталог убрал класс «Django-имена» ПОЛНОСТЬЮ
(в v1 битыми были все 51), остаток — контейнерная адресация (дожата 2-м кругом) и
не-таблицы (перенесены в прозу; счётчик 97→81 при целых канальных). Финалом —
недостающую таблицу zerver_pushdevicetoken агент ДОПИСАЛ В СТРУКТУРУ по замечанию
(правильная ветка!), а 9 схем с битыми скобками (`{"…?"]`) починил по mermaid-замечаниям
формата Ф8и: 30/30 парсятся. Алертов **0**.

**Sentry v2→v3**: импорт 41/54 за 3 круга; каналы 53/172 — Ф8е поймала выдуманное
импортом имя канала на связи («sentry-tasks» — в коде НЕТ такого нигде); данные
135→147 таблиц; доки — прогон №2 свежей сессией с полным каталогом: 12 схем,
mermaid 12/12. Хвост изолированной пары «Оператор → Admin UI» вскрыт Ф8з-превью,
Haiku дорисовал связь по замечанию — проект пересоздан как v3 (пакеты легли
транспортом без повторных прогонов). Алертов **0**.

## Находки раунда (кандидаты — НЕ в работе)

1. **«Соглашательство» слабой модели** (V2-1): на замечание «канала нет ни в пакете,
   ни у брокера» Haiku добавил НЕСУЩЕСТВУЮЩИЙ канал как «логический» с описанием
   маршрутизации в реальные (валидатору не возразишь — имя появилось). Кандидат:
   в текст Ф8е-замечания добавить «канала нет в коде — НЕ добавляй его в пакет».
2. **Ложная подсказка копируется устёгшей моделью слепо** (V2-3) — закрыто Ф8ж, но
   урок общий: любая машинная подсказка обязана молчать при неуверенности.
3. **Мягкая ампутация с рационализацией**: «таблиц нет в структуре → удалю пометки
   (обоснование)». Amber-гвард Ф7а, отправленный агенту ТЕКСТОМ, вернул все пометки —
   гвард работает и как замечание, не только как индикатор.
4. **Пакеты в репозитории заражают следующие прогоны**: свежая сессия унаследовала
   лживое имя из файлов прошлых кругов. Кандидат: промпты могли бы велеть агенту
   пересоздавать archmap-docs/ с нуля (или пользователю — чистить перед пере-прогоном).
5. **Семантическую ложь валидатор не ловит в принципе**: в Sentry-доке 001 осталась
   пометка «читает: sentry_projectcodeowners» (таблица реальна и описана, но чтение
   её на этом шаге сомнительно — унаследовано от мусорной подсказки до Ф8ж).
   Единственная известная сомнительная пометка на оба проекта; правится руками за
   минуту, оставлена как есть — маркер границы метода.
6. Обращения к кэшам Sentry остались прозой (у sentry-cache структура есть, лечился
   бы квалификатор «sentry-cache / …» — модель тонкость не удержала; обратный индекс
   кэша беднее, алертов нет).

## Оговорки честности

- «Ноль алертов» ≠ «идеальная документация»: валидатор сторожит согласованность
  (пометки ↔ структура ↔ связи ↔ каналы), а не семантику каждого факта (п. 5 выше).
- Протокол местами шире «кнопок»: (а) YAML прикладывался к замечанию при возобновлении
  оборванной сессии — у реального пользователя сессия одна и документ в ней уже есть;
  (б) data-промпт повторно вставлялся в живую докс-сессию — штатный паттерн «один чат
  с агентом»; (в) выбор файлов пакета (только *-real) — пользовательское действие.
- Дублирование алгоритма связности превью/алерта осталось (санкция «alerts.py не
  трогать»); паритет закреплён тестом-зеркалом, слияние в один helper — мелкий хвост.
- MEMBERTEAM-класс имён («то же имя, слитно/раздельно») в did-you-mean проходит по
  difflib-ноге; отдельная нормализация нужна была только суффиксной ноге.
