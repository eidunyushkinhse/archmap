## 1. Страница

- Вид собран из языка интерфейса (`frontend/src/ui/tokens.css`): те же цвета, радиусы 8 и 12 px,
  шрифт Inter. Шрифт лежит рядом со страницей (`fonts/`, лицензия OFL там же), сторонних запросов
  страница не делает. Кнопки прямоугольные, пилюль и карточек-плашек нет, разделы разделены
  волосяной линией, колонка 1200 px.
- Один файл `index.html` со стилями и скриптом внутри. `landing-anim.js` больше не нужен.
  Скрипт делает четыре вещи: показывает блоки при прокрутке, запускает ролик только пока его рамка
  на экране, ведёт подписи сцен под роликом первого экрана и листает шесть вкладок раздела
  «За каждым узлом». При системной настройке «меньше движения» ролики сами не запускаются
  (первый кадр и кнопки плеера), блоки видны сразу, вкладки не листаются.
- У адресов кадров и роликов стоит метка `?v=<дата съёмки>`: имена файлов от версии к версии
  те же, и без метки вернувшийся посетитель увидел бы прежние кадры из кэша. После пересъёмки
  метка меняется во всех адресах `landing-shots/` разом.
- Порядок разделов: первый экран с роликом → «Одна точка правды» → «Система, подсистема…» →
  «Любой уровень можно открыть» (живая схема) → «За каждым узлом…» (шесть вкладок) → процессы →
  статусы (ролик) → развёртывание → агент → «Попробуйте в деле» и «Поставить себе».

## 4. Ролики

Оба ролика снимает `scripts/landing-videos.mjs` (шапка файла описывает устройство). В кадре
только настоящий интерфейс и настоящие анимации продукта в реальном времени; дорисован один
курсор съёмки.

**Что изменилось против прежних роликов.** Окно съёмки 1280×800 вместо 1600 px: текст интерфейса
на странице почти в натуральную величину. Курсор — системная стрелка, летит по слабой дуге с
профилем минимального рывка, перед щелчком короткая пауза, щелчок — сжатие стрелки и мягкий круг.
У ролика есть сюжет, паузы стоят там, где зрителю есть что прочитать.

**hero** (1920×1200, около 21 с, петля). Один путь вокруг системы «Заказы»:

| Сцена | Что происходит |
|---|---|
| Архитектура | страница системы «Заказы», лупа раскрывает её на месте, двойной щелчок по Order API |
| Логика | страница Order API, одна прокрутка до «Логики», окно схемы «Создание заказа», ссылка «Оформление заказа» |
| Процессы | процесс «Оформление заказа», шаг «создать заказ» и его панель, вкладка «Развёртывание» |
| Развёртывание | весь проект по площадкам, «Заказы» в дереве, уровень одной системы |

Ролик собран из шести дублей. Стык стоит на щелчке, после которого продукт показывает загрузку
или дольше четверти секунды готовит окно; на стыке растворение 0,3 с, курсор в обоих дублях в
одной точке. Конец за 0,5 с растворяется в первый кадр. Под роликом подписи сцен: текущая
выделена, щелчок перематывает к началу сцены (там стоит ключевой кадр файла). Времена сцен
скрипт печатает строкой `data-scenes` (начало растворения); в `data-cues` страницы стоит его
середина, то есть на 0,15 с позже. Перемотка к сцене с ключевым кадром занимает 30–50 мс, с одним
ключевым кадром на весь ролик занимала до 0,6 с.

**status** (1890×810, около 8 с, бесшовная петля). Мок «Уведомления заказов»: «Как есть» →
«Переход» → «Как будет» → «Как есть». Смена вида в продукте мгновенная, растворением она не
подменяется; ритм задают паузы.

**Данные стенда** (готовятся один раз через интерфейс, дубли только читают; сторож в скрипте
обрывает любую запись и бракует дубль):

- копия эталона с именем «Маркетплейс «Ярмарка»» (сам эталон «… v2» не трогается);
- на схеме страницы «Заказов» объекты расставлены плотно, раскрытие «Заказов» сохранено: после
  раскрытия продукт сам вписывает схему в окно, и на прежней широкой расстановке масштаб был
  0,43, на плотной 0,80;
- уровень «Заказы» холста «Развёртывание» открыт заранее и расставлен: «Кластер prod» слева,
  Managed PostgreSQL над «Кластером резерв» в середине, пустые площадки справа; уровень «Весь
  проект» тоже открыт заранее (первый показ уровня пишет раскладку);
- мок «Уведомления заказов» по §2.4 прежнего плана.

**Пересъёмка** (стек поднят через `./dev.sh`; нужны ffmpeg со сборкой x264, VP9 и x11grab и Xvfb,
память `landing-videos`):

```
XVFB=<обёртка Xvfb> node scripts/landing-videos.mjs --out <папка> --trace --keep-master
node scripts/landing-shots.mjs --out <папка>                      # кадры
node scripts/landing-shots.mjs --only deploy-canvas --project "Онлайн-касса"
```

`--only hero` или `--only status` снимает один ролик, `--keep-master` кладёт рядом мастер без
потерь (из него ролик перекодируется без пересъёмки, на лендинг он не едет). Прогон обоих роликов
занимает 6–8 минут. Проверки ролика: формат yuv420p и 60 к/с, нет кадров-повторов внутри
движения, нет покоя длиннее 2,5 с, первый и последний кадр совпадают (PSNR выше 40 дБ у hero и
45 дБ у status), ключевые кадры hero стоят на началах сцен, размер файла hero до 2,5 МБ и status
до 0,6 МБ.

Грабли съёмки:

- разницу соседних кадров мерить фильтром `psnr` со сдвигом на кадр; `signalstats YDIF` и
  `tblend=difference` на статической сборке ffmpeg 7.0.2 дают ложные периодические всплески;
- x11grab ставит метки времени с шагом 16 или 17 мс, и пересчёт по ним на сетку 60 к/с сам рождает
  повторы и пропуски: кадры захвата берутся по порядку;
- настенные часы WSL2 шагают назад примерно раз в полминуты: тайминги только по монотонным часам,
  дубль с таким шагом переснимается;
- пока идёт запись, на машине не должно работать ничего тяжёлого, второй браузер в том числе.

## 5. Просмотр локально

```
node scripts/landing-serve.mjs <папка лендинга>      # http://localhost:8791/
```

`python3 -m http.server` для просмотра не годится: он не понимает запросы Range, браузер не может
перемотать ролик, и щелчок по подписи сцены возвращает его в начало. На сервере (nginx) Range
есть.

## 6. Выкладка

Делает владелец, как прежде: `tar | ssh` в чистую папку рядом, прежняя версия уходит в
`/root/archmap-stand/landing-before-<дата>`, новая встаёт на место (память `public-stand`).
Распаковывать поверх старой папки нельзя: в ней останутся `landing-anim.js` и прежние кадры.
После выкладки смоук с десктопа и телефона, обновление страницы через Ctrl+F5.

## 7. Что продукт показал при съёмке (не чинилось)

- Смена вида «Как есть · Переход · Как будет» мгновенная, без перехода. Плавная смена украсила бы
  и продукт, и ролик, но это движок холста: без слова владельца не трогается.
- После раскрытия на схеме страницы подпись рамки проекта частично уходит под кнопки масштаба.
- Окно схемы логики появляется через 0,6 с после щелчка (mermaid раскладывает схему), в первый
  раз за сессию — через 0,8 с.
- Холст «Развёртывание» на всём проекте «Ярмарки» (31 карточка) мелок, читается уровень одной
  системы.
- На экране процесса панель шага закрывает правых участников, путь схемы логики в панели
  обрезается многоточием.
- В таблицах ER-диаграммы длинный комментарий растягивает таблицу на всю ширину.
- Подсказки кнопок масштаба холста на английском (есть в открытых вопросах редизайна, tasks.md).
