# ArchMap MCP — сервер для ИИ-агента пользователя

Даёт агенту (Claude Code, Claude Desktop и любому MCP-клиенту) прямой доступ к
ArchMap: читать архитектуру, строить её по исходникам, поддерживать в
актуальном состоянии и дописывать документацию — без копипасты YAML руками.

До этого сервера работал паттерн BYOA: агент выдавал YAML/`.mmd`, человек
переносил их в интерфейс. MCP убирает перенос, оставляя те же правила формата
(промпты) и ту же двухшаговость (превью → применение).

## Что умеет

**Чтение**

| Инструмент | Зачем |
|---|---|
| `archmap_projects` | список проектов; с него начинают |
| `archmap_schema` | дерево объектов и связи; `node_id` — только поддерево |
| `archmap_node` | карточка объекта: путь, мета, связи, схемы логики, спека |
| `archmap_alerts` | незавершённость схемы (шесть классов замечаний) |
| `archmap_processes` | бизнес-процессы: список или шаги сценария |
| `archmap_export` | схема в YAML ArchMap — то, что подают обратно на импорт/синк |

**Правила формата** — те же промпты, что выдаёт интерфейс. Вызывать ДО того,
как строить YAML или `.mmd`: они задают слои C4, правила связей и запреты.

| Инструмент | Зачем |
|---|---|
| `archmap_import_prompt` | как построить YAML архитектуры по репозиторию |
| `archmap_docs_prompt` | как оформить `.mmd` схемы логики и OpenAPI-спеки |

У обоих есть `variant`: `builder` — строительный промпт (по умолчанию),
`orchestrated` — обёртка «построил → аудит скептика → починил» (агенту нужны
субагенты), `skeptic` — только промпт аудита готового пакета. У
`archmap_import_prompt` есть ещё `multi_product` — проект объединяет несколько
самостоятельных продуктов (федерация репозиториев): свой продукт агент строит
контейнером, соседние — заглушками.

**Запись пачкой** — всегда парой «превью → применение».

| Инструмент | Зачем |
|---|---|
| `archmap_import_preview` / `archmap_import_apply` | новый проект из YAML |
| `archmap_sync_preview` / `archmap_sync_apply` | обновить схему живого проекта из кода |
| `archmap_docs_preview` / `archmap_docs_apply` | залить схемы логики и спеки |

**Точечные правки**: `archmap_create_node`, `archmap_update_node`,
`archmap_create_edge`, `archmap_update_edge`.

### Чего сервер НЕ умеет — и почему

**Удалений нет ни одного.** Снос объекта уводит с собой поддерево, связи, схемы
логики и спеки — такое делают глазами, а не «на всякий случай» из разговора.
Чтобы пометить лишнее, агент ставит `status=deprecated`; физически удалит
человек кнопкой «Принять переход», увидев полный список того, что исчезнет.

**Нет «текущего проекта».** Каждый инструмент требует проект явно — именем или
uuid. Скрытое состояние на сервере сделало бы результат зависимым от порядка
вызовов, а агент этот порядок не контролирует.

**Имя проекта не угадывается.** Если под строку подходит несколько проектов,
сервер отвечает ошибкой со списком, а не берёт первый похожий: правки, уехавшие
не в тот проект, обнаруживает человек, и поздно.

## Установка

```bash
cd mcp
python3 -m venv venv
./venv/bin/pip install -r requirements.txt
```

## Настройка клиента

Добавьте в конфиг MCP-клиента (для Claude Code — `.mcp.json` в корне проекта,
для Claude Desktop — `claude_desktop_config.json`):

```json
{
  "mcpServers": {
    "archmap": {
      "command": "/абсолютный/путь/mcp/venv/bin/python",
      "args": ["-m", "archmap_mcp.server"],
      "env": {
        "PYTHONPATH": "/абсолютный/путь/mcp",
        "ARCHMAP_URL": "http://localhost:8000",
        "ARCHMAP_USERNAME": "ваш-логин",
        "ARCHMAP_PASSWORD": "ваш-пароль"
      }
    }
  }
}
```

Переменные окружения:

- `ARCHMAP_URL` — адрес бэкенда, по умолчанию `http://localhost:8000`;
- `ARCHMAP_USERNAME`, `ARCHMAP_PASSWORD` — учётка ArchMap, **обязательны**.

Токен сервер добывает сам и держит в памяти процесса, перелогиниваясь при
истечении: выдачи JWT в интерфейсе нет, и просить токен у человека значило бы
отправить его в DevTools. Запись доступна только роли «архитектор» —
наблюдатель получит внятный отказ.

## Типовые сценарии

**Построить схему по коду.** `archmap_import_prompt` → агент читает исходники и
строит YAML по полученным правилам → `archmap_import_preview` (разбор, слияние
нескольких репозиториев, предупреждения) → `archmap_import_apply`.

**Поддерживать схему актуальной.** Тот же промпт по свежему коду →
`archmap_sync_preview` (что создастся, что обновится, что пропало из кода) →
`archmap_sync_apply`. Синк не удаляет объекты и не трогает раскладку.

**Дописать документацию.** `archmap_docs_prompt` → агент готовит `.mmd` и
спеки → `archmap_docs_preview` → `archmap_docs_apply`.

**Ответить на вопрос по архитектуре.** `archmap_schema` для общей картины,
`archmap_node` по конкретному объекту, `archmap_processes` для сценариев.

**Найти незавершённость.** `archmap_alerts` — те же шесть классов замечаний,
что видит человек в интерфейсе.

## Разработка

```bash
./venv/bin/ruff check .
./venv/bin/mypy
./venv/bin/python -m pytest -q
```

Тесты идут поверх подменённого транспорта httpx — живой ArchMap им не нужен:
они про клиент (логин, скоуп, перевод отказов) и про то, во что инструменты
сворачивают ответ. Контракты самих эндпоинтов держит pytest бэкенда.
