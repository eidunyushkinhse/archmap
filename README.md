# ArchMap

Веб-сервис для описания архитектуры программных систем. Схемы в духе C4, но без ограничения в четыре уровня. Бизнес-процессы собираются из тех же связей, что и архитектура. Beta-фича: документацию собирает ИИ-агент по исходному коду.

> **Статус:** в активной разработке, MVP ещё не выпущен. Интерфейс и API могут меняться.

## Зачем

Модель C4 описывает систему четырьмя уровнями: контекст, контейнеры, компоненты, код. В реальных системах вложенность бывает глубже, а инструменты вроде Structurizr её не выражают.

Вторая проблема — расхождение. Диаграммы процессов рисуют отдельно от архитектуры, документацию пишут отдельно от кода, и со временем они перестают совпадать.

ArchMap решает обе:

- **Произвольная глубина.** Любой объект может содержать дочерние. Где остановиться, решает архитектор.
- **Одна правда.** Шаг бизнес-процесса нельзя нарисовать произвольно: его выбирают из уже описанных связей схемы.
- **Документация из кода.** ИИ-агент изучает репозиторий и собирает схему и описания, а сервис проверяет результат на полноту.

## Возможности

**Схема архитектуры**

- Объекты четырёх форм — сервис, база данных, брокер сообщений, пользователь — с вложенностью любой глубины и навигацией по уровням.
- Связи между объектами разных уровней. Геометрия стрелок строится автоматически.
- Изолированные проекты и две роли: архитектор правит схему, наблюдатель читает.

**Бизнес-процессы**

- Диаграммы последовательности поверх схемы: участники — объекты схемы, сообщения — задокументированные связи между ними.
- Фрагменты alt, opt, loop и par, в том числе вложенные, и ветви «иначе».

**Документация объектов**

- Схемы логики в Mermaid и OpenAPI-спецификации.
- Структура БД, каналы брокера, параметры конфигурации.
- Проверки полноты: 15 классов предупреждений — объекты без связей, связи в контейнер, незадокументированные сообщения процессов и другие.

**Импорт и экспорт**

- Схема в YAML: экспорт, импорт с предпросмотром, догрузка и синхронизация с репозиторием.
- Полный архив знаний проекта в zip.

## Документирование из кода: BYOA и MCP (beta)

ArchMap не встраивает собственную ИИ-модель. Подход называется **BYOA — bring your own agent**: сервис выдаёт промпты с правилами формата, а пользователь запускает их в своём агенте (Claude Code, Claude Desktop или любом MCP-клиенте) прямо в репозитории системы.

По коду агент может:

- собрать архитектуру в YAML;
- составить перечень точек входа, описать логику каждой в Mermaid, а API — в OpenAPI;
- собрать факты: структуру БД, каналы брокера, параметры конфигурации;
- привязать шаги бизнес-процессов к схемам логики.

У промптов три варианта: `builder` строит, `skeptic` проверяет готовый результат, `orchestrated` объединяет оба в цикл «построил → аудит скептика → починил».

**MCP-сервер** (`mcp/`) убирает ручной перенос результатов. 29 инструментов дают агенту прямой доступ к проекту: чтение схемы, импорт с предпросмотром, запись документации и те же проверки полноты, что видит человек в интерфейсе. Подробности — в [mcp/README.md](mcp/README.md).

## Стек

- **Фронтенд:** React 19, TypeScript, Vite, React Flow, ELK для раскладки схем
- **Бэкенд:** Python, FastAPI, SQLAlchemy 2.0, Alembic, PostgreSQL
- **MCP-сервер:** Python
- **Качество:** 2800+ тестов на vitest и pytest, eslint, ruff, mypy. Один и тот же гейт работает в pre-commit-хуке и в CI на GitHub Actions

## Быстрый старт

Нужны Python 3.11+, Node.js 22 и запущенный PostgreSQL.

```bash
# бэкенд
cd backend
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

# фронтенд
cd ../frontend
npm install

# запуск из корня проекта
cd ..
./dev.sh
```

Скрипт `dev.sh` создаст `backend/.env` со случайным `SECRET_KEY`, создаст базу данных, применит миграции и поднимет бэкенд и фронтенд. Интерфейс откроется на http://localhost:5173, Swagger — на http://localhost:8000/docs.

Экрана регистрации пока нет. Первого пользователя создайте в Swagger запросом `POST /api/v1/auth/register` с ролью `architect`.

Ручной запуск и частые проблемы описаны в [DEV.md](DEV.md).

## Как ведётся разработка

ArchMap разрабатывается одним человеком вместе с ИИ-агентами. Каждая доработка начинается с плана в `docs/`, проходит гейт тестов и принимается вживую. Инструкции для агентов лежат в [CLAUDE.md](CLAUDE.md).
